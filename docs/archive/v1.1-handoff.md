### A.2 Hard rules

1. **No git writes.** Never `git add`, `git rm`, `git mv`, `git reset`,
   `git checkout -- <file>`, `git stash`, `git commit`, `git push`, `git tag`.
   Read-only git (`status`, `diff`, `show`, `log`) is fine.
2. **No servers.** No SSH, SOCKS proxy, `curl` to a panel host, or anything that
   touches uk-node, alpine-node, us2-node or the panel host. Items that need
   them are written up as **"awaiting Owner approval"** (see A.5).
3. **No edits** to existing files in `migrations/` (0001–0113), `go.mod`,
   `go.sum`. New migrations are new files. No new Go module dependency.
4. **No third-party binaries in the product.** Xray: official. sing-box: official,
   or our reproducible build of unmodified upstream (Phase 8). No gost, brook,
   nftables forwarding, tc.
5. **No downloaded binary is run on this workstation**, with one exception: the
   protobuf toolchain (A.4). Real-core tests are written so that they skip when
   their binary environment variable is unset, and are wired into the CI
   `cores` job in `.github/workflows/check.yml` with digest-verified downloads
   (see how mihomo, Xray and sing-box are fetched there).
6. **Stop conditions.** If an upstream capability the plan assumes does not
   exist, do not patch a core and do not build a substitute. Stop that item,
   record it in `docs/v1.1-plan.md` §12.3 as a limitation and in the progress log,
   and continue with the next item.
7. **R9 — keep the Owner's UI.** Do not change page structure, navigation or
   visual design. Change only what fills an existing slot; add inputs inside
   existing forms/panels. No fabricated values: unknown → "—" or "未知".
8. **Encoding.** Edit files with the editor tools only. Never use PowerShell
   `Set-Content`, `Out-File`, `>`/`>>` redirection or `sed -i` over Vue/TS/Go/MD
   files with non-ASCII text. Every file: UTF-8 **without BOM**, **LF** endings.
   Migrations are checksummed: LF, no trailing whitespace changes after pinning.
9. **Memory.** Go always with `-p 1`. Never two `go test` runs at the same time.
10. **Searches.** Never search recursively from the repository root (node_modules,
    .tools are huge). Scope to `internal/ cmd/ pkg/ proto/ web/src docs/
    migrations/ deploy/ scripts/ .github/`.
11. **Style.** Match the surrounding code: Go comments in English, full
    sentences explaining *why*; Chinese for user-facing UI text and
    user-facing error messages where the module already does so.
12. **Honesty.** Never claim a test passed that was not run. Paste real output.

### A.3 Workflow inside a phase

For every numbered task:

1. Read the files the task names before editing them.
2. Make the change.
3. Build the touched packages: `go build -p 1 ./internal/...` and
   `go vet -p 1 ./<package>`; for web changes `cd web && npx vue-tsc --noEmit`.
4. Run the touched packages' tests: `go test -p 1 -count=1 ./<package>`.
5. Fix before moving on.

At the end of every phase:

1. Full gate (A.6).
2. Encoding check (A.7).
3. Progress entry in `docs/v1.1-progress.md` (A.8) and a short block in
   `docs/v1.1-plan.md` §12.5.
