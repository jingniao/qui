| 消息 | 新字段及编号 |
|---|---|
| Capabilities | `HostInfo host = 19`；`bool tuning_supported = 20` |
| HostInfo（新） | `cpu_model=1` string；`cpu_cores=2` int32，逻辑核心；`architecture=3` string，GOARCH；`kernel_version=4` string；`memory_total_bytes=5`、`swap_total_bytes=6`、`disk_total_bytes=7` uint64；`os_pretty_name=8` string |
| Heartbeat | optional double `load1=23`、`load5=24`、`load15=25`；optional uint64 `process_count=26`、`tcp_connections=27`、`udp_sockets=28`、`memory_used_bytes=29`、`swap_used_bytes=30`、`disk_used_bytes=31`；`map<string,string> tuning_current=32` |
| ServerMessage.payload | `TuningCommand tuning_command = 20` |
| AgentMessage.payload | `TuningResult tuning_result = 27` |
| TuningCommand（新） | `string request_id=1`；`map<string,string> settings=2`；`bool clear=3` |
| TuningResult（新） | `string request_id=1`；`string status=2`；`repeated TuningKeyResult keys=3` |
| TuningKeyResult（新） | `string key=1`；`string value=2`；`bool applied=3`；`string error=4` |

HostInfo 随每次 Capabilities 发送刷新，包括重连和核心更新后能力重报。Linux 从 procfs、os-release 与 statfs 读取；内核 release 来自 /proc/sys/kernel/osrelease。磁盘是 Sampler 状态目录所在文件系统，与 disk_percent 相同，used 均按 Blocks−Bavail。TCP 包含 tcp/tcp6 所有状态，UDP 为 udp/udp6 套接字；任一家族不可读不报不完整总数。进程数统计 /proc 数字进程目录，不把累计 forks 或线程数当进程数。新增心跳指标读失败保持 optional 未设置；非 Linux 不虚报。HostInfo 按要求使用普通标量，零值本身无法区分缺测与真实零，K2b 展示须考虑这一限制。

## 调优文件协议、事务与权限

Agent 只写 `/var/lib/proxy-agent/tuning/desired.json`（原子替换、0600），等待同 request_id 的 status.json，最长 30 秒；发送结果走现有 Connect/Ack 流，不另建数据库、任务或重传日志。每节点同时只应下发一个请求。每个新操作使用唯一 request_id；结果未确认时不能宣称没有应用，也不要自动生成新 ID 重试变更。断线可能丢失流内结果，实际值由后续心跳重新观测，K2b 须保留未确认状态。

`status` 为 `applied`、`cleared`、`failed`；keys 包含逐键读回值、applied 与 error。失败事务的键 applied 均为 false，value 是恢复后读回值；全局错误使用空 key。应用、读回或配置持久化失败时恢复本次尝试前的值；恢复失败也明确记错。status 写入/流投递失败属于结果未确认，须核对实际状态。

settings 是完整 profile；新 profile 省略此前受管的键时恢复其初始值。tcp_rmem/tcp_wmem 输入仅为第三个整数（最大值），应用时保留当前前两个整数，心跳和结果返回完整三个值。clear=true 必须无 settings；空 settings 同样表示清除。

| 白名单键 | 输入范围 |
|---|---|
| net.ipv4.tcp_congestion_control | bbr、cubic、reno、htcp、hybla、bbr2、bbr3，且必须已经在 tcp_available_congestion_control 中 |
| net.core.default_qdisc | fq、fq_codel、cake、pfifo_fast |
| net.ipv4.tcp_ecn、net.ipv4.tcp_tw_reuse、net.ipv4.tcp_mtu_probing | 0–2 |
| fs.file-max | 65536–16777216 |
| net.ipv4.tcp_rmem、net.ipv4.tcp_wmem | 最大值 4194304–268435456 |
| net.core.somaxconn | 128–65535 |
| net.ipv4.tcp_max_syn_backlog | 128–262144 |
| net.core.rmem_max、net.core.wmem_max | 212992–268435456 |
| net.ipv4.tcp_fastopen | 0–3 |

helper 再次独立校验，只直接写对应 procfs 文件，不调用 shell、sysctl 或模块加载程序。先在 root 控制的 `/etc/sysctl.d/.proxy-tuning-snapshot.json`（0600）持久保存首次应用前所有可读白名单值，成功 profile 原子保存到 `99-proxy-tuning.conf`；后续 profile 保留原始快照。清除恢复快照并移除配置和快照，不重写已经相同的只读键。root 的 `.proxy-tuning.lock` 用 flock 串行化进程。请求目录用 os.Root 固定，拒绝符号链接、目录替换逃逸、FIFO 与超过 16 KiB 的输入。status.json 无秘密，0644 供 Agent 读取，父目录仍为 Agent 所有的 0700。

- systemd：proxy-agent-tuning.service（root oneshot）与 .path；开机排在 systemd-sysctl 和 update-recovery 后重放。ProtectSystem=strict、ProtectHome、PrivateTmp、NoNewPrivileges 等硬化；/proc/sys 默认只读，只允许 13 个具体 sysctl 路径，以及 /etc/sysctl.d、tuning 目录写入。
- 能力为 **CAP_NET_ADMIN + CAP_DAC_OVERRIDE**。后者是读取 Agent 的 0600 请求并写入其 0700 目录所必需；仅 root UID 加 CAP_NET_ADMIN 不能越过这些 DAC 权限。fs.file-max 依赖 root 对 procfs 的文件权限，未授予 CAP_SYS_ADMIN、CAP_SYS_RESOURCE 或模块加载能力。只读 procfs/受限宿主拒绝时失败，不扩权。
- OpenRC：proxy-agent-tuning 监管 tuning-watch（busybox inotifyd），启动重放、desired.json 写入/rename 触发。root 的 ambient IAB 不足以约束 exec 后的权限，因此显式从 bounding set 排除其余 0–40 capability；cap_last_cap>40 时拒绝启动，避免未来能力静默扩权。OpenRC 无 systemd 文件系统命名空间隔离。该服务的实际 libcap/OpenRC 行为仍待 Linux/root 验收。
- 安装记录第 11/12 行为新增服务与 path/watcher 的摘要，第 10 行仍为 init system。卸载校验摘要、停触发器、以 root 临时目录中的 clear 请求恢复快照，成功后才删除单元；恢复失败保留程序并中止。qui-update 快照包含新增单元/watcher，回滚前停止 tuning，回到无该功能的版本时禁用并移除相应定义；已有定义恢复后重新布防。开机更新恢复顺序也覆盖 tuning。

## 续证策略与 K2b 必改项

`RenewalDue(at)` 为 `at >= NotBefore + 30d OR NotAfter <= at + 14d`。仅现有已连接 session 循环调用；重连完成后检查，不为离线节点启动独立定时器。CSR 复用原 key，SaveRenewal 仅替换证书；失败保留身份并退避 1 小时，成功后重连。90 天证书签发期未改。

**阻塞实际 30 天续证的服务端条件**：`internal/panel/node/certificate_renewal.go` 目前仍以 `!request.Immediate && time.Until(leaf.NotAfter) > 30*24*time.Hour` 拒绝自动续证。K2b 必须改成与 Agent 相同的“年龄不足 30 天且余期大于 14 天才拒绝”，并保留已有认证、同钥、幂等回执和确认流程；不通过 Immediate 绕过正常自动续证策略。先发布 K2b 面板，再发布 Agent。

K2b 还需：

1. 消费并保存 Capabilities.host/tuning_supported；消费 Heartbeat 的 optional 指标和 tuning_current。区分缺测与真实 0，保留原 tcp_congestion_control/default_qdisc。按计划实现每分钟一条、保留 7 天、排除备份的 node_metric_samples 与 GET /nodes/{id}/metrics?hours=，本次无迁移。
2. 提供 Owner+CSRF+审计的下发/清除入口，拒绝不支持/离线 Agent，服务端同样校验白名单与边界，持久保存请求 ID、期望 profile 和结果/未确认状态；每节点一个进行中操作，收到 TuningResult 后按 node_id 与 request_id 匹配，正常 Ack。不能阻塞其他 Agent 消息的 Ack 等待 helper 结束。
3. 发送 ServerMessage.TuningCommand，接收 AgentMessage.TuningResult；展示逐键读回/失败及实际 tuning_current，未确认时依据新心跳核对，不能仅凭按钮点击或本地 profile 宣称成功。无能力旧 Agent 显示不支持。
