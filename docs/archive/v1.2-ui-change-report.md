## 1. Conflicts with the previous version

These are places where the new UI changes earlier behaviour or decisions. Existing installations will notice them.

| # | Area | Before | Now | Effect on existing data/users |
|---|---|---|---|---|
| C1 | Node groups (节点分组) | A group held **servers**; a user got every subscription-visible inbound on them. The v1.2 plan had renamed groups to 线路组 ("groups servers, grants users"). | A group holds **individual inbounds and imported proxies**. Granting users happens on the group page. Explicit server members remain only for policy scope (relay/egress groups). | Migration 0122 expands each server member into its eligible inbounds and keeps every original server for policy scope, so access is unchanged at upgrade. **New inbounds are no longer automatically in any group**; add them via the editor's 所属分组 field or the group page. |
| C2 | Imported (airport/manual) subscriptions | Granted per user on each source. | Distributed only through node groups (a whole source or individual proxies by `name|protocol`). | 0122 converts each existing per-user source grant into a generated group "导入 · <source>" with the same users. The source API still accepts `userIds` but ignores it. |
| C3 | User pages | Node-group grants were set on the user list/detail. | No grant controls on user pages; 可用节点 shows real access derived from groups. | New users have no access until they're added on a group page. |
| C4 | Per-scheme access (planned S1) | Planned v1.2 phase. | Dropped; node-level groups cover it (a group can contain just a scheme's entry inbound). | No data impact; S1 was never built. |
| C5 | Server tuning | Read-only (AGENTS L2: no privileged tuning operation). | 调优 tab applies a whitelisted sysctl profile through a root helper (CAP_NET_ADMIN + CAP_DAC_OVERRIDE), persisting `/etc/sysctl.d/99-proxy-tuning.conf`. | **Security boundary change.** Needs the new Agent and the helper units, installed by install.sh/qui-update. Linux/root acceptance is pending. |
| C6 | Cores per server | Exactly one core per node (AGENTS §35). | Several cores per node: add, remove and upgrade per core; inbounds choose a core. | Migration 0125 adds per-component update tasks. Old Agents stay single-core. Removing a core is refused while any inbound uses it, and the last core can never be removed. |
| C7 | Certificate renewal | Agent renewed when ≤14 days remained. The panel accepted auto-renewal only with ≤30 days left. | Renewal every 30 days with the same key, only while connected (or ≤14 days left). The panel accepts the same rule. The certificate panel is hidden (Owner decision). | Roll out the panel before the Agent, otherwise the panel refuses early renewals. The expired-certificate recovery UI is no longer available. |
| C8 | Relay tunnels | Each scheme owned its connections; generated objects matched by scheme-name prefix. | Tunnels are shared objects referenced by schemes; ownership is recorded explicitly. | 0124 creates one tunnel per existing connection. Only certain matches of published objects are adopted. Objects of renamed or deleted schemes appear under **待认领的历史对象** and must be claimed (or left alone) before a conflicting publish. |
| C9 | Port rule | U4/U5 allowed a TCP and a UDP inbound to share a port number. | One enabled listener per numeric port per server, whatever the transport. | This corrects an earlier mistake: the Agent always rejected such pairs at apply time. Existing data with such pairs fails on save/publish with a clear message. |
| C10 | Port range | None. | Per-server range (服务器设置) used for random ports in the node editor and for canvas relay listeners. | The earlier browser-only/remark-suffix storage was migrated into real columns (0122). |
| C11 | Monitoring | In-session data plus a real latency chart; diagnostics on the same tab. | Stored history (1H–7D, minute samples kept 7 days, excluded from backups) for CPU, memory, disk, network, connections, processes, load. Diagnostics cards removed (see §2). | Needs the new Agent for processes/load/TCP/UDP/totals; old Agents show "—". |
| C12 | Shell and navigation | Top header bar with account menu; 用户管理 had 用户/管理员 children. | No top bar; logout and 修改密码 in the sidebar user center; 用户管理 is one item listing admins and end users together. | `/users/admins` and `/system/admins` redirect to `/users`. |
| C13 | Version and update pages | Agent/core task lists and release registration on 版本与更新. | Task history, signed-release registration, recovery and attempts on 系统管理 › 任务记录. 版本与更新 does single/batch upgrades and core management. | `/system/agents`, `/system/cores`, `/system/updates` redirect to 任务记录. |
| C14 | Server list | Card view paginated; 显示已删除 toggle; per-card 升级/调优/详情 buttons. | All servers on one page; clicking a card opens details; no deleted toggle. | Deleted servers are reached through the status filter option 已删除 (or the URL `/nodes?deleted=1`); the separate toggle is gone. |
