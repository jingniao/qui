# 同时在线设备上限

用户编辑表单的“同时在线设备上限”取值为 0–100，0 表示不限。
设备按用户在入口节点上活跃的来源地址估算：IPv4 使用完整地址，IPv6
按 /64 合并，跨节点去重。中转凭据和 WireGuard 不参与统计或限制。

同一个 NAT / CGNAT 后面的多台设备算一台；双栈、切换 Wi-Fi/移动网络，
或不同节点使用不同地址族，可能让一台设备暂时算多台。地址在最后一次
观测后的 60 秒内算活跃；随后保留已允许的名额 120 秒，再提升最早出现
的活跃受限地址。先到先得；Owner 可提高上限或重置准入顺序。

新地址超限后，通常要等约一个上报周期加投递时间（约 5–20 秒）才受限。
Xray 拒绝匹配用户与来源的新连接，既有连接继续使用；sing-box 每 2 秒
通过 Clash API 关闭匹配的活连接，因此是事后执行。Xray SOCKS5 UDP 没有
用户身份，不受此限制。其他 UDP 协议的实测结果仍待 CI/Owner 验收；官方
Xray 没有 Hysteria2/TUIC 入站，这两种协议只适用于 sing-box。

gate 是有 3 分钟有效期的内存命令，不创建配置版本。面板失联后自动过期
放行；能力不足、旧 Agent、API 字段缺失或观测失败时也放行。管理页面与
门户显示“部分执行”及对应节点，未知数量显示“未知”。WireGuard 仍只能
一次在一台设备上使用。

来源地址只在内存观测和控制通道内处理。面板不保存、不审计、不记录来源
地址，也不将它们放入备份。Owner 和门户均只显示 IPv4 /24 或 IPv6 /48。
统计中的 IPv6 /64 合并与显示时的 /48 掩码是两个不同的步骤。

Xray 仅通过安装的官方核心的 `api adrules` 与 `api lsrules` 管理临时规则。
失败后立即恢复已渲染的无 gate 路由并核对标签；验证失败则由 supervisor
从当前成功修订重启。RoutingService 只在已有回环 API 上启用：该 API 没有
认证，节点本地进程属于信任边界，不能把它暴露到主机外。
