## v1.7.0：页面加载隔离与读取诊断

- 轻量 DTO 保留能力及核心门禁；展示读取走独立只读池，多步一致读取用同一短事务；认证、额度、凭据生成与发布写决策不迁到展示池。数据库恢复、准备取消和启动早退必须关闭/重开并释放读池。
- 诊断 `QUI_READ_TIMING` 默认关闭，无效值启动报错；仅记录请求序号、路由模板、状态与阶段耗时，不记录 SQL/参数、Token、配置或密钥。`db_acquire` 包含打开连接与排队；`sql` 计数包含 Query/Next/Scan/Close，不等于语句数；缺阶段表示未覆盖或未执行，不按零处理。现行用法见[运维手册](operations.md)。

## v1.7.0：受管 Agent 终端升级

- 终端入口由唯一监督进程在自身事件循环处理固定 `status`/`check`/`install`/`reserve` 请求，沿用原生命周期锁、认证任务日志与安装恢复，不启动第二套监督者。
- 候选先做签名/平台/摘要校验；本地候选重启恢复不得改为联网下载；`local-` 前缀不能被网页请求借用；预检至停服用保留连接持锁并暂停轮询，EOF 或停服释放。
- 两阶段分别提交：引导已提交后，实际 Agent 安装失败须非零退出并分别报告两阶段版本，不声称整套回滚；“已是最新”须同时核对两个版本。完整网页入口统一方案见[升级统一](#2026-11-20-agent-terminal-web-update)。

## v1.7.0：流量历史整理与新回执安全淘汰（0154）

- **核心明细按小时合并**：原始 `core_traffic_samples` 保留最近 7×24 小时，仅对 `observed_at < floorUTC(now-7days, 1hour)` 的完整旧小时按每批最多 500 条原子汇总入 `core_traffic_hourly(node_id, core, bucket)` 并删除原始行；不删累计游标、不改 epoch。迟到补传始终先写原始表，再由下一轮任务合并，查询按「核心原始 + 小时汇总 + 符合回退条件的账户样本」各加一次；边界切入已压缩小时无法精确回答时固定返回 `traffic_history_resolution`，禁止按比例分摊或静默扩范围；已发布 `retained_account_samples` scope 值不变。
- **新编号队列与双向检查点**：Hello/Welcome 协商能力位后启用独立交付元数据 `(queue_id, delivery_seq)`；`queue_id`、序号分配、未确认集合与确认进度纳入认证本地状态（bound spool ABI 7 / 认证头 v2）。面板按 `(node_id, queue_id)` 保留各代队列且每节点仅一条活动队列，维护 `R <= A <= C`（连续完成 `C`、节点确认删除 `A`、已淘汰 `R`）；隔离批次留缺口会阻断检查点跨越但不阻断后续入库。显式身份恢复核销与换证同事务封存旧代，普通握手拒绝换队列。
- **回执淘汰五项前提与 24h 冻结**：仅当（1）双方协商新协议且身份/编号完整、（2）统计/记账/完成标记持久完成、（3）位于双方确认连续前缀且无 pending/恢复引用、（4）进入双方确认前缀满 24 小时、（5）更早回执全部满足条件时，才在同一事务分批删除并推进 `R`。同一时刻仅冻结一个等待满 24 小时的候选边界，新确认不延后已有候选计时。无编号旧回执第一版明确保留，不自动删除或推断完成。
- **重放拒绝与存储 floor 保护**：`seq <= R` 批次在统计/记账前拒绝并返回 `traffic_delivery_retired`，Agent 保留原数据并报告本地状态冲突，收到该错误不得删队列。按旧 `batch_id` 查已淘汰回执时明示未保留，不建永久 ID→序号映射。监督进程须先确认基线、当前及上一签名回滚镜像均支持新格式且无未完成升级任务，再持久提升 storage floor；worker 仅在 floor 提升后迁移，防止升级中断回滚后旧镜像读不了队列。
- **恢复一致性**：在线或保有冻结库的恢复将流量原始表、小时汇总、游标、回执、队列状态与 pending 作为一组采用当前冻结库事实；先认证冻结证据并复制迁移私有副本再附加，冲突暴露为恢复失败，不自动执行 `VACUUM`。

## v1.7.2：提前准备展示数据（0155）

- SSE 可能丢最后事件，须配 30 秒轻量校准；心跳提交只排按节点合并的展示刷新，不等读池、不阻塞 ACK。清单/元数据均成功才消费失效标记，清单另有 5 分钟核对；前端按服务代次＋统计版本拒绝迟到旧结果，配置变更立即停用旧配置结果。展示快照与用户额度账本完全分离，禁止用于扣额。

## v1.7.3：剩余加载、同机覆盖重装、CPU 与日志

- 普通心跳只合并指标；能力/分组/草稿/发布/证书变化及重连才使配置展示失效；能力读取改用窄读取避免反复算调优建议导致高 CPU。
- 同机覆盖重装先准备校验、停旧服务、以旧身份向本次指定端点补传最终持久数据，面板完整确认后才持锁删固定 Agent 数据；失败保留数据与进度，不清面板历史/账本/授权。新机接替不能替另一台机器补传或删数据；核销后旧证书作废且旧连接退出不能把新连接标离线。OpenRC 覆盖要求宿主已有 `strace` 与进程观察权限，停服前拒绝缺失，不自动装工具。
- Agent 运行日志预算为当前＋9 个归档、各 10 MiB、总 100 MiB（不含流量队列、程序核心或 v1.7.5 独立升级日志），轮转失败必须可见。

## v1.7.5：完整网页/终端 Agent 升级统一（0157）

- 独立 root 更新服务固定运行已安装 `/usr/local/bin/qui-update --component agent --version X.Y.Z --yes`：只接收固定 schema 的探测或在线升级请求（任务/尝试 ID、节点身份、期望修订、正式版本），不接受 URL/脚本/命令/环境变量/文件路径，命令参数逐项传递、禁止 `eval`。
- 外层任务独立保存在 0157 表中，不进旧 `agentjobs` 队列避免与终端更新器自锁；旧已发布任务/回执继续按原合同读取恢复，新任务不降级回旧目录。
- 失败阶段固定分 10 类：请求检查、下载、校验、预检、引导安装、引导健康检查、实际 Agent 安装、实际健康检查、恢复、结果保存。Agent 本机投递错误独立保存为 `dispatchError`，不锁死后续真实 root 结果。
- 两阶段恢复先将原 local RequestID、候选摘要与完整签名清单 fsync 至 root 事件；原 cause 在回滚前、outcome 在收尾前加密保存在 `local-candidates`，不改 jobs/spool ABI；重启由监督进程只读核对原任务与安装请求，材料不足保持 `unconfirmed` 且不重复安装，缺 CLI 退出收据保持中断失败与空退出码。
- 完整输出保存在独立 root 任务目录并分块补传、面板持久化后 ACK（同键异内容拒绝，未 ACK 不删），**不纳入 100 MiB 普通 Agent 日志轮转**，未获后续清理授权前保留，仅 Owner 可看。

## v1.7.5：成功线路维护/离线过滤（0158）

- 0158 为面板派生发布证明，不扩展 Agent desiredstate/proto。单次只读事务固定服务端时刻、规则与状态：维护立即排除、确认离线用共用时限、等待恢复保留；过滤只影响下次订阅输出，不改凭据、运行配置或触发自动发布。
- 依赖按稳定端点 Ref 与成功规则路径/修订摘要与成功快照同事务提交；各节点当前成功加密修订递归证明完整线路，不用草稿或整个批次集合代替。默认出口组全部已发布受管候选及 `BackupKind` 递归备用均计入依赖，任一维护/确认离线排除整条入口；客户端链缺任一跳整条排除、不截短。

## 沿用的架构约束与防踩坑备忘

从早期版本沉淀、当前代码仍须遵守的隐蔽约束（切勿误作冗余代码删改）：

1. **订阅中立模型叶子依赖**：`internal/panel/subscription/proxy` 必须保持叶子包，`system` 和 `net/http` 不得进入其依赖图。
2. **`canvas_schemes` 旧数组兼容**：读取须继续容忍 v1.7.5 及更早数据里的 `null`/缺失 JSON 数组，新写入输出严格 `[]`，空字符串仍是未发布哨兵。
3. **客户端策略已接受边界**：配置保存与并发删除规则集存在跨模块竞态；每份 profile 单独 GET（上限 50）；无合格预览用户时不校验格式；渲染逐个查询规则集启用态。
4. **导入刷新撞名（16i）**：内容导入节点改名后，若 URL 来源刷新引入同名同协议端点，Registry 保留先收集者并警告丢弃后者（自建来源优先注册），目前未做自动消歧。
5. **Telegram 响应 64 KiB + 1 字节校验**（`notification/sender.go`）：多读 1 字节并判超长不是多余防御——前 64 KiB 恰好是合法 JSON 加空格、后面是脏数据时，直接截断会误解析成功。
6. **旧 Bash 数据库比对的 SIGPIPE 处理**：旧快照中的 `cat | cmp -s` 遇首字节不同即退出，库大于管道缓冲时 `cat` 会被 SIGPIPE（退出码 141）终止；不能把内容不同误判为读取失败。v1.10.4 起数据库比对下沉到 `internal/platform/hostupdatedb`，旧快照仍交给自己的 updater 恢复。
7. **规则集 `.prev` 恢复失败仍须重启旧核心**：旧配置引用的规则集按 URL 哈希命名仍存在，`.prev` 改名失败时记错但仍用旧配置重启（多核心逆序撤回），最后 `errors.Join` 合并错误，防止核心停服。
8. **目录句柄与硬链接检查**：面板数据目录归无特权账号所有，root helper 与 `update.sh` 必须固定目录句柄防符号链接替换；安装记录沿用 `0:600:1` 硬链接数校验。
9. **实机排障固化参数（v1.2 RC）**：设备观测使用 20 秒保留窗口 + 500ms 采样避免 15 秒心跳间漏掉短连接；Alpine/OpenRC 脚本读取 `/proc/sys/kernel/cap_last_cap` 必须用 `cat` 而非 BusyBox `ash` 的 `read`（逐字节读触发内核 `proc_dointvec` 异常）；同节点同协议多入站订阅名追加 `· <port>` 消歧；安装脚本不得在登记前预建 `/var/lib/proxy-agent/tuning`；核心健康检查连续 3 次 `ErrListenerUnavailable` 才重启，防止 conntrack 表满时级联重启。
