# v1.1.0 发布说明（DRAFT，尚未发布）

草稿日期：2026-10-28。本文件用于审核，不是发布公告。v1.1 与 v1.2 合并为 v1.2.0 发布（2026-10-30 决定），本草稿的版本号与文件名待随 v1.2.0 发布说明改写。2026-10-31 release/v1.2.0 的 CI（含原生核心 cores 作业与 `-race`）已通过，见验收矩阵 §10.4；RC1、RC2 与正式发布均 **awaiting Owner approval**；具体证据与阻塞见 [进度记录](v1.1-progress.md) Phase 11 和 [验收矩阵](v1-acceptance.md) 的 v1.1 部分。

## 主要变化

- 模块化订阅格式与来源；新增 mihomo、legacy Clash、全局客户端规则模板及 Token 授权的 classical provider。
- 用户独立门户账号、会话隔离、状态/用量/节点/订阅查询与修改密码；Owner 可只读预览。
- 每用户一条共享订阅与隐藏接入身份；新 Token 的加密副本允许本人和 Owner 再次查看。
- qui sing-box 从未修改的上游源码可复现构建，增加上游 `with_v2ray_api` 标签；有能力节点的每用户流量纳入共享额度。
- 跨入口源地址估计的并发设备限制，运行时门控与部分执行提示；不使用客户端专有设备标识。
- 加密外部订阅源、按用户授权、缓存导入及 mihomo 客户端链；服务器元数据与提醒、真实可选指标、固定 TCP 探测、原生端口转发与按用户流量重置周期。
- 沿用 Owner 的界面布局，移除伪造数据、隐式 Token 重置和浏览器凭据缓存。

- qui-update 支持 RC 版本 `X.Y.Z-rc.N`、semver 优先级与 `--component panel|agent`。组合主机可先更新面板再更新 Agent；旧更新器的首次升级须从已审核并校验的归档运行新版 update.sh，见[部署 §5.0](deployment.md)。L4 本地完成，Linux/root 与主机验收仍待执行，RC1/RC2 未运行。

## 不兼容变化与升级前检查

1. **设备管理 API 已移除。** 旧设备路由及带 `deviceId` 的订阅 Token 请求返回 410 `devices_removed`；旧 `maxDevices`、`maxConnections` API 字段退役，使用 `deviceLimit`（0–100，0 不限，升级默认 0）。设备策略作用域与页面设备字段移除。
2. **0113 会合并每用户的额外设备。** 保留主接入身份；其他设备凭据被撤销，其链接失效（403），主身份链接继续使用。历史设备 ID、流量与墓碑仍保留。迁移会处理旧设备作用域策略，无法保留引用的策略禁用并备注。先审查受影响用户并准备升级前备份；备份 B3 实跑仍待 Owner。
3. **sing-box 流量开始计入用户额度。** 仅有 `singbox_user_stats` 能力的节点适用；用户可能因此更早超额并由自动版本移除凭据。官方无标签构建仍维持节点总量、每用户未知。升级前告知用户并核对额度。
4. **UA 识别机制与格式选择顺序改变。** 显式 `?format=` 优先，再尝试已验证 UA，最后系统默认；开关默认开启，未知格式返回 400。但可信 UA 表当前为空（Phase 0 A.7 待核实），不能宣称自动识别已可用。现提供复制/二维码，一键导入 scheme 未核实不启用。旧 URI/Base64/sing-box 输出保持 fixture 字节兼容，sing-box 仍是片段。
5. **旧 Token 无法再次查看。** 升级前 Token 没有加密副本，仍可使用但需主动重置才能重新查看；重置撤销旧链接。凭据重置是另一个操作，等待节点自动版本应用才切断旧代理设置。
6. **每用户上下行限速移除（D-e/L1）。** 0118 清除旧闭合备注元数据前缀中的 up/down；不声称官方核心能提供该限制。

## 升级顺序与回退

先完成验收和 Owner 批准，再备份数据库及身份材料，**先升级面板，再逐台升级 Agent**。1.1 面板可继续接受 1.0.9 Agent 的发布、回滚与 Xray 流量；旧 Agent 的新增统计/门控能力不可用且明确提示部分执行。再按能力选择 qui sing-box；换核心前清理目标核心不兼容入站并发布确认。sing-box 默认 `--core-source qui`，取同 qui 发布的静态归档与 SHA256SUMS；`--core-source official` 保留官方 glibc/musl 路径。Xray 始终官方。

`qui-update` 的自动回滚与升级前数据库是回退路径。1.0.x 不能打开新迁移数据库，跨迁移降级需指定相应升级前数据库，见 [部署与升级](deployment.md) §5.1。L4 已按 Owner 批准方案本地扩展 updater：支持 RC 与组件选择；首次使用须运行审核归档内的新版更新器。主机验收与 RC 清单执行仍需 Owner 批准。

设备限制统计地址而非物理设备：NAT 少算、双栈/切网多算，IPv6 按 /64 合并，60 秒活跃＋120 秒释放；Xray 既有连接不断，sing-box 响应式关闭约 2 秒，检测有报告延迟，断联 3 分钟租约过期放行。WireGuard 一次一端且不计数；Xray SOCKS5 UDP 无用户归属不能门控。Owner 和用户都只看 /24、/48 掩码，完整源地址不入库/日志/备份。

**Xray 下行计数在连接关闭时入账。** Linux 上官方 Xray 对明文 TCP 使用 splice 零拷贝转发，用户的下载字节在 splice 结束（通常是连接关闭）后才计入该用户的计数器；上传字节照常实时计入。长时间保持的明文 TCP 连接（例如大文件下载、长连接）在关闭前不会让用户的下行用量增长，额度判定与超额切断因此会推迟到连接结束后的下一个上报周期，超额窗口比第 9.1 节的正常路径更长。这是上游行为（CI 原生核心测试在 SOCKS5 入站直连出站上确认），面板和 Agent 无法提前读到这部分字节。按上游实现，走 splice 的是两端都能取得原始 TCP 连接的路径（如 SOCKS5/HTTP/端口转发入站经 Direct 出站，以及识别出内层 TLS 后的 VLESS XTLS Vision）。sing-box 是否有同类延迟未单独验证。
