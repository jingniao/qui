# v1.2.0 发布说明（DRAFT，尚未发布）

草稿日期：2026-10-31。本文件用于审核，不是发布公告。v1.1 与 v1.2 的工作合并为 v1.2.0 一次发布（2026-10-30 决定，不单独发布 v1.1.0）；GOST 推迟，按方案授权（S1）取消。release/v1.2.0 的 CI（原生核心 cores 作业与 `-race`）已通过，见[验收矩阵](v1-acceptance.md) §10.4；RC1、实机验收与正式发布均 **awaiting Owner approval**，步骤见 [实机测试计划](v1.2-host-test-plan.md)。

**平台：** 本版本只验收 linux/amd64。发布仍附带 arm64 归档，但未在任何 arm64 主机或模拟器上验证（Owner 2026-10-31：暂不考虑 arm64）。

## 主要变化

用户与订阅（原 v1.1）：

- 模块化订阅格式与来源；新增 mihomo、legacy Clash、全局客户端规则模板及 Token 授权的 classical provider。
- 用户独立门户账号、会话隔离、状态/用量/节点/订阅查询与修改密码；Owner 可只读预览。
- 每用户一条共享订阅与隐藏接入身份；新 Token 的加密副本允许本人和 Owner 再次查看。
- qui sing-box 从未修改的上游源码可复现构建，增加上游 `with_v2ray_api` 标签；有能力节点的每用户流量纳入共享额度。
- 跨入口源地址估计的并发设备限制，运行时门控与部分执行提示；不使用客户端专有设备标识。
- 加密外部订阅源与缓存导入、mihomo 客户端链；服务器元数据与续费提醒、固定 TCP 探测与延迟曲线、原生端口转发、按用户流量重置周期。

服务器与节点（原 v1.2）：

- **多核心节点：** 一个节点可同时运行 Xray 与 sing-box，按核心添加、升级、移除，入站选择所属核心；端口在全部核心与端口转发之间按数字唯一。旧 Agent 仍按单核心工作。
- **共享中转隧道：** 中转方案引用独立的隧道对象，对象归属显式记录；多个方案可共用一条隧道。
- **节点分组按入站授权：** 分组直接包含具体入站与导入代理，在分组页授权用户；显式服务器成员只用于节点策略范围。
- **主机信息与监控：** CPU/内存/交换/磁盘/网络/连接/进程/负载的分钟历史（保留 7 天，不进备份），1H–7D 视图。
- **服务器调优：** 白名单 sysctl 配置由 root helper 应用、读回核对、可清除恢复（变更 L2）。
- **证书续期：** 连接期间每 30 天用原密钥续期（或剩余不超过 14 天时）。
- **界面：** 沿用 Owner 的布局，移除顶栏、伪造数据、隐式 Token 重置与浏览器凭据缓存；版本与更新、任务记录、节点分组、中转画布重新整理。
- **安装与更新：** `install.sh`/`node-install.sh` 可重复 `--core`；安装记录 v2；`qui-update` 支持 `X.Y.Z-rc.N`、semver 优先级与 `--component panel|agent`，所有核心一起快照与回滚。

## 不兼容变化与升级前检查

1. **设备管理 API 已移除。** 旧设备路由及带 `deviceId` 的订阅 Token 请求返回 410 `devices_removed`；`maxDevices`、`maxConnections` 退役，使用 `deviceLimit`（0–100，0 不限，升级默认 0）。策略的设备作用域与页面设备字段移除。
2. **0113 合并每用户的额外设备。** 保留主接入身份；其他设备凭据被撤销、链接失效（403），主身份链接继续可用。历史设备 ID、流量与墓碑保留。无法保留引用的设备作用域策略被禁用并备注。升级前审查受影响用户并备份。
3. **sing-box 流量开始计入用户额度。** 仅有 `singbox_user_stats` 能力的节点；用户可能更早超额并被自动版本移除凭据。官方无标签构建仍只有节点总量。
4. **格式选择顺序。** 显式 `?format=` 优先，其次已验证 UA，最后系统默认；未知格式返回 400。可信 UA 表当前为空，不能宣称自动识别可用。旧 URI/Base64/sing-box 输出保持字节兼容。
5. **旧 Token 无法再次查看。** 升级前的 Token 没有加密副本，仍可使用，重置后才能再次查看；重置撤销旧链接。
6. **每用户上下行限速移除（D-e/L1）。** 0118 清除旧备注中的 up/down 元数据。
7. **新入站不再自动进入节点分组。** 0122 把每个服务器成员展开为其可用入站并保留原服务器作为策略范围，升级时访问不变；之后新建的入站要在编辑器的“所属分组”或分组页加入。导入订阅改由分组分发，0122 为每个旧的按用户来源授权生成“导入 · <来源>”分组；来源 API 的 `userIds` 被忽略。用户页面不再有授权控件。
8. **端口规则收紧。** 每台服务器每个数字端口只能有一个已启用监听，不区分 TCP/UDP（Agent 一直如此拒绝）；已有这种成对配置在保存/发布时报错。
9. **中转对象归属。** 0124 为每条旧连接建立独立隧道，只认领已发布、名称精确且无歧义的旧对象；其余出现在“待认领的历史对象”，冲突发布前需显式认领。
10. **服务器调优是新的特权边界。** 需要新 Agent 与 helper 单元（`proxy-agent-tuning.*`，CAP_NET_ADMIN + CAP_DAC_OVERRIDE），修改会影响整台主机上的所有服务。
11. **先升级面板，再升级 Agent。** 新 Agent 每 30 天续证，旧面板会拒绝提前续证。
12. **Agent 升级是单向的。** 成功升级后安装记录改为 v2，新更新器拒绝降级到 1.0.9 安装器；只有失败的升级会自动恢复 1.0.9。
13. **界面入口变化。** 证书面板、手动 TCP 探测与高级诊断不再显示（接口保留）；`/users/admins`、`/system/admins` 跳转到 `/users`，`/system/agents`、`/system/cores`、`/system/updates` 跳转到任务记录；已删除服务器经状态筛选“已删除”查看。

## 升级顺序与回退

1. 备份面板数据库与各节点的身份目录，审查 0113 的影响。
2. **先升级面板**：`qui-update --component panel --version 1.2.0`。1.2 面板继续接受 1.0.9 Agent 的发布、回滚与 Xray 流量；旧 Agent 的新能力显示为不可用或部分执行。
3. **再逐台升级 Agent**：`qui-update --component agent --version 1.2.0`。每次升级会重启该节点的代理核心，节点上的既有连接短暂中断。
4. 旧更新器首次升级须从已校验的归档运行新版 `deploy/linux/update.sh`，见[部署与升级](deployment.md) §5.0。

回退：面板降级只能带升级前数据库 `qui-update --component panel --version 1.0.9 --database <pre-update-1.0.9-*.db>`，升级后写入的数据会丢失（[部署与升级](deployment.md) §5.1）。Agent 成功升级后不能回到 1.0.9（见上文第 12 条）。

| arm64 | 归档随发布构建，未验证 |

设备限制统计地址而非物理设备：NAT 少算、双栈/切网多算，IPv6 按 /64 合并，60 秒活跃＋120 秒释放；Xray 既有连接不断，sing-box 约每 2 秒关闭匹配连接，检测有报告延迟，断联 3 分钟租约过期放行。WireGuard 一次一端且不计数；Xray SOCKS5 UDP 无用户归属不能门控。Owner 与用户只看 /24、/48 掩码，完整源地址不入库、不写日志、不进备份。

**Xray 下行计数在连接关闭时入账。** Linux 上官方 Xray 对可 splice 的 TCP 路径零拷贝转发，用户的下载字节在 splice 结束（通常是连接关闭）后才计入该用户；上传照常实时计入。长时间保持的连接在关闭前不会让下行用量增长，额度判定与超额切断因此推迟到连接结束后的下一个上报周期。这是上游行为（CI 原生核心测试在 SOCKS5 入站直连出站上确认）。按上游实现，走 splice 的是两端都能取得原始 TCP 连接的路径（如 SOCKS5/HTTP/端口转发入站经 Direct 出站，以及识别出内层 TLS 后的 VLESS XTLS Vision）。sing-box 是否有同类延迟未单独验证。

面板主机 -race、备份 B3、浏览器走查、RC1/RC2、实机验收和正式发布均不得以本地或 CI 结果替代；逐项证据见验收矩阵。v1.2.0 尚未发布。
