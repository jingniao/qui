# v1.3.0 发布说明

发布日期：2026-11-03（tag `v1.3.0` 指向 `f849f01`，与 rc.6 同一 commit；GitHub 正式发布，非预发布）。预发布版 rc.1–rc.6 与最终版在三台主机（us2-node、uk-node、alpine-node）验收，结果见[验收矩阵](v1-acceptance.md) §12。计划与设计见 [v1.3 计划](v1.3-plan.md)、[T1/P2 设计](v1.3-design-t1-p2.md)、[GOST 设计](v1.3-design-gost.md) 与 [G0 实测](v1.3-g0-gost-findings.md)。

**平台：** 只验收 linux/amd64。GOST 只支持 linux/amd64（同一个静态二进制用于 Debian 与 Alpine）。

## 主要变化

- **整机月流量（T1）：** 每台服务器按所选单张网卡统计整机用量（默认默认路由网卡），可选计量方式（入站 + 出站、仅出站、两者取较大值）、可选额度（进度条，只用于展示）与独立的流量重置日（1–31，短月份取最后一天，面板时区）。服务器卡片的“本月”一栏改为整机流量，节点详情同时显示整机流量与代理流量。首次采样只建立基线；LXC 只能看到容器自己的网卡；跨主机重启且 Agent 离线期间的流量无法补计。迁移 0126。
- **Xray 端口转发计入节点总量（P2，修复 v1.2 的 F11）：** Xray 节点总量 = 账户计数 + 端口转发入站的原生计数，不进入用户额度。
- **GOST 3.3.2 作为第三种核心（G1）：** 只承载端口转发，从不服务用户（无订阅、额度、设备限制或域名记录）。安装 `--core gost` 或在面板“添加核心”，只接受官方 v3.3.2 amd64 归档与固定摘要。迁移 0127。
- **GOST 转发（G2）：** 多个目标的轮询或主备（主备切换会让一次请求失败）、端口范围（每个端口一个服务，最多 256 个）、按端口的上下行限速与 TCP 连接上限。
- **GOST 加密中继（G3）：** 中转画布里的端口转发可以选 GOST：入口服务器的转发经出口服务器的 GOST 中继（TLS + 客户端证书）到达目标。每条隧道一套由面板签发的证书（10 年，CA 私钥签发后即丢弃），“更换证书”后下一次发布先出口后入口，期间短暂中断。迁移 0128。

## 其他修复

- sing-box 健康检查失败时写明哪个 TCP/UDP 监听不可用。
- 用户列表与详情把超额用户显示为红色“额度已用尽”；门户徽标读取接口实际返回的原因。
- Xray 与 sing-box 适配器共用同一份核心进程标记代码（去掉两份相同副本）。
- 加固三个偶发失败的真实核心测试（SOCKS5→Shadowsocks 中转、mihomo 路由、UDP 互通）。

## 升级注意

- 面板先升级，再升级 Agent；迁移 0126–0128 自动执行，升级前 `qui-update` 会备份数据库。
- 发布配置仍会重启节点上的**全部**核心：修改 GOST 转发会短暂中断同节点 Xray/sing-box 的连接，反之亦然。
- **GOST 不能作为节点的主核心**：`cores` 第一项必须是 Xray 或 sing-box（`--core gost` 单独使用或排在前面会被安装脚本拒绝），也不能移除最后一个 Xray/sing-box。
- **GOST 转发只能直连目标**：它不参与出站资源、分流策略与出口组，唯一要求是该节点有启用中的 `direct` 默认出站；需要经出口服务器时用 GOST 加密中继（G3）。
- 安装 GOST 后若要把 Agent 降级到 1.3 以前，先移除 GOST 核心。
- 整机流量从升级后的第一次采样开始累计，之前的用量不补算。

## 验证

- 门禁：`f849f01` 在本地 Linux 测试机上通过 `scripts/check.sh`（1823 秒）与真实核套件（Xray 26.3.27、sing-box 1.14.3、mihomo、GOST 3.3.2，合计 3090 秒）；GitHub 手动作业 41556983475 的 `check` 与 `cores` 通过，发布作业 41566922164 只构建发布。
- 代码审查：Codex 11 轮，最后一轮无发现；修复约 22 项，每项都有回归测试。主要是：v1.2.0 备份被恢复校验拒绝、整机流量跨日分摊在夏令时跳过午夜时死循环、回滚时 GOST TLS 材料被覆盖、GOST 不能作为主核心、已有中继时的发布顺序、多核心设备门控、GOST 转发的 direct 默认出站要求、依赖当天时间的测试。
- 只在实机上发现、已在 rc.2–rc.6 修复：面板拒绝 GOST 能力条目导致控制流反复重连（rc.2）；空闲 GOST 的统计源状态被拒与 `core_lifecycle_unconfirmed`（rc.3）；中继快照只按主核心判断入站（rc.4）；链与订阅校验只认主核心（rc.4、rc.5）；us2→uk 隧道与既有中继被误判为依赖环（rc.6）。
- 实机验收摘要：三台主机用 `qui-update` 逐版升级（面板先、Agent 后），迁移 0126–0128 执行、`quick_check` 正常、0 个回滚目录；T1 与 `/proc/net/dev` 同 5 分钟对比误差在 0.39% 内；P2 在 uk 上传输 2 × 10,000,000 B 后节点总量 +20,000,522 B、用户额度不变；GOST 3.3.2 在三个节点安装（契约 3），`fifo` 池故障切换、端口范围与节点计数符合预期；us2→uk 加密中继 3/3 × 1 MB HTTP 200，无证书客户端被拒（TLS alert 116）、异构 CA 被拒（48），中继字节不计入节点总量，轮换凭据后再次 3/3 通过，既有中继与链路不受影响，移除 GOST 后主机回到原状。逐项见[验收矩阵](v1-acceptance.md) §12。

## 已知限制

- 只验收 linux/amd64，arm64 归档未验证；GOST 只支持 linux/amd64。
- uk-node 的 conntrack 表偏小（`nf_conntrack_max` 7680，内核频繁报 table full），Xray 监听健康探测会超时并重启核心（RC-D 期间 5 分钟内 10 次）。这是 v1.2.0 起就有的主机设置问题，本版本未改。
- 移除 GOST 不清理节点上的 `runtime/gost` 文件。
- 两台服务器之间的任何隧道改动也会重发布经其中继的第三台（例如 us2 与 uk 之间的改动会重发布 alpine），期间该主机的 Xray 短暂重启。
- 重命名隧道生成的入站会让它脱离画布，直到改回原名。
- LXC 的整机流量只能统计容器自己的网卡。
- 本次实机未验证：经过 GOST 中继的 UDP（主机上只测了 TCP/HTTP）、GOST 限速与连接上限的主机观测、整机流量的时区分桶变更、备份恢复演练。
- conntrack 主机设置、移除核心后的 `runtime/<组件>/` 清理、跨服务器重发布与画布入站改名四项已在 v1.3.1 处理，见[发布说明 1.3.1](release-notes-1.3.1.md)；本文件的原始结论保留不改。
