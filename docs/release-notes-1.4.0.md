**范围与状态（2026-11-05 America/Los_Angeles）：** [协议支持补齐计划](subscription-import-compatibility-plan.en.md#148-implementation-status-2026-11-05)的全部工作并入 v1.4.0。S1–S4、M1–M4 已在本地整合，迁移头 0133；Linux 实核和精简开发验证通过，本地来源诊断、协议编辑器及五格式预览走查完成；完整 race 按用户要求省略，不声称最终完整门禁通过。Owner 授权后，面板及三台 Agent 已部署未公开发布的离线 `1.4.0-rc.1`（`f11fe4e`），生产 A1 部分完成；真实客户端流量与三节点路径仍待验收，见[主机记录](v1.4-a1-host-report.md)与[验证记录](v1.4-protocol-verification.md)。

## 主要变化

- **节点创建与编辑：** 六步向导改为单页分区表单，常用配置集中填写，协议参数按核心能力联动，高级设置和变更预览折叠，底部直接保存草稿或保存并发布。保持现有配置字段和发布语义。
- **页面加载：** 服务器列表先显示基础信息，再补充元数据与流量；中转画布的方案与资源并行读取，节点列表的导入/分组/方案及中转明细不再串行等待。全量节点请求每页读取 100 条，普通分页保持 20 条。已做构建及定向延迟验证，尚未部署到 `f11fe4e` 生产离线 RC，也未完成截图环境的加载耗时复测。
- **门控与刷新风暴修复：** 生产浏览器诊断确认相同门控下发会触发 Agent 连续上报，版本页随 SSE 重复读取导致约 15 秒排队。修复后相同门控每分钟续期、变化立即下发；版本页合并读取期间的重复状态刷新。定向测试通过，修复后主机复测待执行，见[诊断记录](page-loading-verification.md)。
- **订阅来源刷新误报（已实施，Linux 门禁通过）：** 拉取或解析失败时，面板已记录失败并停用该来源缓存节点，但刷新接口仍返回成功，页面提示“刷新完成”。修复后返回 `import_refresh_failed` 错误，页面显示失败并重新加载来源列表（计划 §14.5）；提交 `650b349` 的门禁为 `check` 1980s、`cores` 572s、`GATE 650b349 PASS total=2552s`（END 2026-11-05T09:30:12Z），真实失败来源的浏览器走查仍待 A1。
- **订阅导入诊断（S1，已实现并整合；原门禁仅因 0133 缺校验和固定失败，Linux 实核及精简开发验证通过，正式验收待执行）：**
  - 抓取失败按 DNS、非公网地址、重定向、TLS、连接、超时、HTTP 状态与内容大小分类，只回显固定代码与说明，不含链接、Location、响应体或凭据；HTTP 状态写入结果并由同一固定文案渲染，403 显示为实际状态而不是“HTTP 0”。
  - 刷新返回结构化结果（`ok`/`partial`/`failed` 与导入、跳过、重复、缓存、可用于订阅计数），部分成功按业务结果显示警告，失败保留缓存但排除订阅并显示业务结果而非错误文本。
  - 粘贴导入走同一分析管线：保存接口返回来源 ID 与结果，无条目可导入为 422、输入无效为 400、写入失败为 500，页面保留草稿并可直接查看逐条原因。被拒绝的粘贴明确说明“未保存任何来源/未保存任何更改”，并给出原有缓存与可用数量，不声称已抓取或已排除。
  - 结果校验只接受面板可达状态：成功结果的尝试时间与成功时间一致、`ok` 不带跳过、`partial` 必有跳过、落库结果只可能是面板真正写入的代码且缓存计数已知；诊断字段白名单与解析器实际发出的字段同源。来源自身密封数据损坏按本地存储失败（500、状态不变）处理，不伪装成抓取失败。
  - 写入失败一律报告“未能保存、来源状态保持不变”，并给出回滚后仍保留的成功时间与缓存/可用数量，不会把本次分析结果说成已写入。
  - 逐条原因最多 50 条、结果最多 32 KiB，页面用对话框展示；手工刷新、定时刷新与粘贴导入共用同一路径。
  - 同一来源内 `name|protocol` 重复时保留文档顺序第一条，其余以 `duplicate_endpoint_key` 拒绝并附保留条目；完全相同的条目单列为内容重复。
  - 迁移 0133 保存最近结果与最近成功时间，旧来源与旧归档显示“未记录原因”，迁移不抓取订阅。
- **外部订阅导入补齐（S2–S4，已实现并整合，最终验收待执行）：**
  - 导入 Shadowsocks 2022、VLESS Reality（TCP/gRPC）与 VLESS xhttp，完整保留参数并加密缓存。
  - 各订阅格式只输出能表达的端点，其余逐条省略并给出原因，不再整份失败。
  - URI/Base64 保留公开参数；mihomo 只输出已测 Reality TCP Vision、Reality xhttp-auto 且 ALPN 恰为 `[h2]` 的组合；sing-box 只输出已测 Reality TCP Vision，不输出 xhttp；其余组合逐条省略。xhttp 四种模式为 auto/packet-up/stream-up/stream-one，ALPN 只允许空列表或 h2/http/1.1，拒绝 H3 与未知值。证书指纹与客户端 TLS 指纹分开保存。
- **自建节点 Reality / xhttp（M1–M4，已实现并整合，最终验收待执行）：**
  - Xray VLESS 用户入站支持 Reality TCP（无 flow/Vision）、Reality gRPC（无 flow）、Reality/TLS xhttp（四种模式）；sing-box 仅 Reality TCP（无 flow/Vision），须单个具体 DNS SNI，不提供 xhttp。
  - 按已安装核心原生探测和 Agent 精确组合上报放行，旧/未知契约不能授权；内部代理中转仍用 TCP/TLS。X25519 私钥加密保存并在普通查询、预览和差异中隐藏；普通保存不轮换，明确轮换先保存草稿，成功发布后客户端须更新订阅。
  - 关联该入站的成功发布中转端点携带相同公开参数与原 SNI。CDN 前置会合并或分散源地址设备估计；本轮 Windows 原生/认证证据不替代 Linux、浏览器或主机验收。

- **客户端策略配置库：** 0132 新增服务端配置库与独立编辑/活动版本，启用后由客户端更新订阅生效；支持授权端点成员、关键词包含/排除、emptyPolicy 与只读草稿/已保存配置预览。共享规则集可查询全部客户端配置/规则及节点策略引用，有引用时禁止删除；禁用允许并提示下载 404、客户端可能继续使用缓存或报错。

- **隧道管理：** 新增“隧道 / 规则”。隧道为 entry → [mid] → exit，最多三台不同服务器，GOST relay over TLS＋mTLS；各接收跳只有一个共享监听，多个规则复用。两节点各跳要求契约 ≥3，三节点 ≥4；Agent 当前上报 4，按能力校验，不按 GOST 二进制版本猜测。
- **独立转发规则：** 规则配置入口监听、TCP/UDP、可选隧道与最终目标。无隧道时直接转发，有 GOST 优先，否则主 Xray/sing-box；linked 目标跟随用户入站，出口即目标时用 loopback，manual 保持手填且不进订阅。保存只写草稿，目标公网地址/入站端口变化使已发布规则 needs_publish。
- **节点添加中转与订阅：** 目标节点可选择已有隧道创建 linked 规则，或新建以当前节点为入口的代理中转方案。成功发布且启用/可见的规则追加 `<目标节点> · <协议> · 经 <入口节点>` 端点，保留原端口消歧、凭据、传输和 TLS，仅换入口地址/规则端口，并显式保留原 TLS server name。订阅使用成功发布快照，草稿不会提前改地址；Owner shareLink 可预览合格用户真实凭据，Viewer 恒 null。
- **中转方案收敛：** 画布只新增代理中转（proxy_chain/tunnel，tls/wireguard）。出口可选 qui 入站（生成独立内部监听/凭据）或外部 SOCKS5/HTTP/Shadowsocks/Trojan/VLESS 出站，外部出站属于前一跳并决定最终出口，按 TCP/UDP 能力校验。relayPort 优先旧 tunnelPort。
- **端口与归属：** tunnel_objects 按 ID 管理生成入站，普通编辑/删除返回 409 managed_by_tunnel；被 linked 规则引用的目标删除返回 inbound_has_relays。port_claims 始终预留端口；自动分配跳过所有入站（含禁用/范围），ports/check 也报告禁用入站。手动保存仅检查启用入站间冲突及持久声明。新隧道/规则必须手填或配置端口范围；仅画布无范围时保留 8443/51820。
- **计划与发布：** 先展示服务器、监听、路由、变更与冲突，再按 exit → mid → entry 发布，失败反向回滚。选隧道纳入规则，选规则纳入隧道和必要拨号依赖；未变返回 unchanged，不生成修订/批次。已发布对象删除进入 pending_delete，成功发布移除前保留声明、引用及订阅快照。

## 升级注意

- 面板先升级，再逐台升级 Agent；升级前备份数据库、身份目录及必要配置密钥。发布/升级 Agent 会短暂重启受影响节点核心，须安排窗口。本轮已按此顺序完成离线 RC 部署并保留恢复点，尚未正式发布。
- 新迁移 **0129–0132**：0129 新增 tunnels、tunnel_hops、tunnel_rules、port_claims、tunnel_objects；0130 增加规则 published_snapshot；0131 增加 canvas_forward_reconcile 与 tunnel_migration_report。0132 增加 client_policy_profiles，活动指针为 system_settings.client_policy_active，备份恢复核对活动模板快照；正式版迁移头仍为 0128；跨迁移降级须恢复匹配的升级前数据库，不能让旧程序打开新库。
- 启动/恢复在旧 0124 归属核对后，**自动单次**转换合格已发布画布转发：普通转发变直接规则，GOST 转发变两节点隧道＋规则。保留 ID、端口、原运行入站/修订与密封材料，不重签、不下发；规则默认订阅隐藏。目标公网地址与成功运行版本中的用户入站端口唯一匹配才 linked，否则 manual。迁移连接从画布布局移除；首次无修改发布复用旧物化输入。
- Owner 必须查看 `GET /api/v1/tunnels/migration-report` 的 `{items:[{tunnelId,name,reason}]}`：核对未发布连接、缺失/重复归属、共享路径不一致、缺失服务器、目标池/范围、端口冲突、材料或运行设置不一致。无法确定的连接留在画布只读，可删除，不可新增/改动。报告记录单次尝试，处理后不自动消项/重试；事务失败可重试。按原路径与所有权明确重建及发布，不猜测接管。
- GOST 隧道每跳必须已安装并上报启用 GOST、所需契约且无组件操作占用；接收跳须公网地址或 connectHost。按规则 network 放通入口监听，按每段放通 TCP 中继端口。新隧道/规则无默认端口回退。
- 凭据轮换走 `/api/v1/tunnels/{id}/rotate-credentials`，带 updatedAt，仅生成 modified 草稿，必须再计划/发布；三节点材料按段独立。不要对已迁移对象使用旧 canvas-tunnels 轮换路径。
- 旧归档先迁移再执行同一单次转换；新归档保留端口声明、归属、材料、发布快照、完成标记与报告。恢复不重签、不自动发布，已发布对象标 modified，由 Owner 核对后显式发布。0130 前无历史快照的规则须再次成功发布才进入订阅。
- 同一来源内名称与协议相同的导入条目：只保留文档中的第一条，其余以 `duplicate_endpoint_key` 拒绝并在刷新结果中说明（S1 起生效）。旧版本会全部导入，升级后这类条目会减少；须由来源方或 Owner 改名后才会再出现。节点组与客户端策略中的 `name|protocol` 引用始终只对应一个端点。
- 自建 Reality / xhttp 设置只下发给上报相应精确能力的 v1.4.0 Agent；仍按先面板、后 Agent 升级，v1.3.1 Agent 不能保存或接收这些设置。

具体操作见[运维 §21](operations.md#21-隧道管理与中转方案v14-草稿未发布)，转换边界与恢复验证见 [M1 报告](v1.4-m1-report.md)。

## 已知限制

- 目标看到中继源地址，同一中继后的客户端在设备限制中合为一个来源；尚无 PROXY protocol 透传。账户额度在目标用户入站计量；规则入口字节只进节点总量，中间/出口 relay 排除，避免重复。
- UDP 经 TLS/TCP 中继后由出口发出，可能受丢包与队头阻塞影响；重启会丢失既有 TCP 会话与 UDP 关联，客户端需重建。不承诺未实测的空闲寿命、长流恢复或性能。
- 核心健康只说明进程/监听，不能证明 mTLS、目标连通或完整路径可用。轮换先切监听再切拨号，期间可能中断；删除不能立即撤销离线节点仍生效的材料。
- Reality/xhttp 已实现并整合，实际选择受逐核心契约与每格式边界限制；Linux 实核及本地编辑器/预览已验证，生产配置发布与历史回滚已执行，生产实客户端认证和连接 Agent 的浏览器运行验收仍未完成。中转端点按规则 network 过滤，导出器继续保留固定证书、legacy Clash 等原有省略边界。
- xhttp 经 CDN 部署时，节点看到 CDN 地址，设备限制的源地址估计会合并或分散客户端。
- GOST 不支持 arm64；新三节点路径与正式浏览器走查结果须由 A1 补充，旧版验收不得替代。
