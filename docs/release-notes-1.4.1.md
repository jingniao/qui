# v1.4.1 发布说明

发布日期：2026-11-08（UTC）（tag `v1.4.1` → `0c1b061`，即 `release v1.4.1: one-click panel installer, new default ports, editor help`；经 GitHub 发布工作流的 tag 推送发布）。v1.4.1 是 v1.4.0 之上的补丁版本：**没有迁移**（迁移头仍为 **0134**）；内容为面板一键安装器与[项目安装与使用指南](install-guide.md)、默认端口改为 22550／18880、节点编辑器与用户列表的交互修正，以及一条拒绝节点证书的日志（`95796b1`）。门禁、GitHub `check` 与生产升级结果见“验证”、文末“发布记录”与“生产升级”。

**平台：** 与 v1.4.0 相同，构建 linux/amd64 与 linux/arm64；GOST 仍只支持 linux/amd64。本版未新增 arm64 实机验收。

## 新增与改进

- **一键面板安装器 `deploy/linux/panel-install.sh`：** Debian/Ubuntu 面板主机上一条命令完成下载、按 `SHA256SUMS` 校验归档、安装程序与服务账号、写端口与证书路径、用 `--check-config` 校验、开机自启、稳定性确认与防火墙放行（ufw/firewalld 已启用时才询问）；已安装主机上同一脚本变成更新／状态／重启／卸载菜单，更新交给 `qui-update`，不覆盖已有配置、证书与数据库。用法见[项目安装与使用指南](install-guide.md)；手工安装与目录权限见[部署与升级](deployment.md)第 3 节。
- **默认端口改为面板 22550（Web/API/SSE/订阅）与 Agent 18880（gRPC）：** 安装器提问默认值与 `--help`、示例配置 `deploy/examples/panel.yaml`／`agent.yaml`、节点一键安装脚本（信任锚 URL 在端口不是 443 时带端口）及面板生成的节点安装命令（总是显式传 `--http-port` 与 `--grpc-port`）同步。安装器从不改写已存在的 `/etc/proxy-panel/config.yaml`；本地开发配置仍是 8080／9443。
- **节点编辑器补充自动填充与就地说明：** 切到 Reality 时自动生成一个 Short ID、由握手目标一键回填 server names、追加 Short ID、生成 xhttp 路径；选 xhttp 而当前安全方式在该核心上不成立时自动切到核心上报的安全并提示；Reality／xhttp 字段增加填写说明。
- **隐藏不可用选项：** 入站协议与传输／安全按所属核心上报的能力过滤（编辑时保留原值），节点组“添加代理节点”不再列出无法授权的节点。
- **用户管理列表每行增加“详情”入口：** 编辑用户时用户名改为只读，避免提交被后端忽略的改名。
- **拒绝的节点证书写入日志（`95796b1`）：** `Control.Connect` 在 `ValidateIdentity` 拒绝证书时写一条 WARN `node certificate refused`（节点、指纹、对端与错误），例如原位身份恢复后仍出示已作废证书的旧 Agent。拒绝行为本身不变；Agent 的 30 秒退避上限使过期 Agent 每分钟约两行日志。见[运维手册](operations.md)第 5.1 节。
- **文档：** `docs/handoff.md` 归档到 `docs/archive/`（`bb18301`）；新增[项目安装与使用指南](install-guide.md)。

## 修复

两项都是本轮安装器开发中的缺陷，**没有进入任何已发布版本**：

- **新装忽略指定端口：** 首次实机安装测试发现新装时提问得到的端口被忽略、没有写进配置；已修复并复验（自定义 23456／23457 与默认 22550／18880 都能写入并监听）。
- **卸载后重装被拒：** 同轮测试发现卸载留下 `panel.removed` 后重跑安装被拒绝，无法按提示重装；已修复，现在自动识别该记录并按重新安装处理，保留配置、证书与数据库，复验通过。

## 已知限制

- **已有生产面板保持原端口 443／9443：** 安装器从不改写已存在的 `/etc/proxy-panel/config.yaml`，端口与证书路径只在首次安装时写入。要换端口用面板主机的 `qui` 菜单第 2 项（改 `http_address` 端口并先做配置校验）或手工编辑配置后重启，见[安装指南](install-guide.md)。
- **私有 CA 证书导致客户端拉不动订阅：** 生产面板使用私有 CA 签发的证书，Clash Verge、v2rayN 等严格校验 TLS 的客户端经 HTTPS 拉取订阅会失败，报 `self-signed certificate in certificate chain`。临时办法是在浏览器打开 clash／base64 链接后导入文件或粘贴内容，这样**没有自动更新**；公网证书计划在后续版本提供。
- **Trojan 端点的自签证书在订阅中没有信任材料：** 自 v1.0 验收起即为已知限制，客户端需自行关闭校验或改用其他接入协议。
- **非交互 shell 下的菜单“更新”默认取 GitHub 最新正式发布：** 没有降级保护（待实现）；`qui-update` 自身的确认提示默认 No，误触不会直接执行。

## 升级

- **先面板，后 Agent：** 面板主机执行 `qui-update --component panel --version 1.4.1`，确认面板就绪（`systemctl is-active proxy-panel`、版本页显示 1.4.1）后，再在每台节点主机执行 `qui-update --component agent --version 1.4.1`；组合主机同样先 panel 后 agent。
- **没有迁移：** 迁移头仍为 0134，升级不做数据库变更；`qui-update` 仍在替换前备份面板数据库（`pre-update-<旧版本>-<时间>.db`），健康检查失败或中断时自动回滚。
- **已有安装保持原端口与证书：** 配置不会被改写；新装用 `panel-install.sh`（默认 22550／18880，自签名或自有证书），步骤见[安装指南](install-guide.md)。
- **升级 Agent 会短暂重启该节点的代理核心**（核心是 Agent 的子进程），既有连接瞬断；修订不变、没有回滚。发布配置仍会重启该节点全部核心（v1.4.0 起的行为没有改变）。
- 离线升级、降级与旧更新器的首次升级见[部署与升级](deployment.md)第 5 节与 5.1。
