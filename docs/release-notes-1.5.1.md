# v1.5.1 发布说明

v1.5.1 是 v1.5.0 的补丁版，**没有迁移**，修复 1.5.0 的两个严重问题，并带来若干改进。逐项设计与证据见 [v1.5.1 规划](v1.5.1-plan.md)。

**1.5.0 的两个已知问题在本版修复，建议直接升到 1.5.1：**

- 已启用网页升级（受管模式）的 1.5.0 Agent，无法发布指定核心（如 sing-box 的 Hysteria2）的入站，发布报 `apply_failed`；草稿里有这样的入站时，该节点的所有手动发布都会失败。
- 在「分流控制 → 规则集」页面编辑并保存规则集，会清空它的关键字条目。

## 修复

**受管 Agent 发布指定核心的入站失败（第 2 项）。** 受管模式下，上层监督进程长期持有发布历史锁，实际执行配置的 worker 在发布前做存储格式检查时撞锁失败。现在由监督进程在启动 worker 之前，用它已打开的发布历史证明并升级存储格式；worker 不再自己加锁，格式已升级时直接跳过检查。应用前的早期失败改为固定错误码 `storage_preflight_failed`／`revision_store_failed`，并在 Agent 日志写一条 WARN，不再只有一个 `apply_failed`。

**1.5.0 新装节点没有真正启用网页升级（第 4 项）。** `node-install.sh` 在 Agent 写出存储基线之前就去初始化受管模式，在小机器上会失败，安装仍显示成功。现在启用前最多等待 60 秒存储基线，超时不改动任何东西并提示。已装好的 1.5.0 节点在本机运行一次 `qui-update --component agent` 即可启用。

**规则集页面保存清空关键字（第 1 项）。** 两个页面改为共用同一个规则集编辑组件，保存总是携带关键字与外部来源；规则集列表显示外部来源数量、最近抓取状态与关键字数量。

**监控 CPU 与网速大多为空（第 7 项）。** Agent 两次心跳间隔不足 1 秒时不再清空 CPU 与网卡速率，也不重置计算基准；面板在同一分钟内不再用后到的空值覆盖已有的速率。只升级面板也能让现有 1.5.0 Agent 的曲线连续。页面去掉了误导的「需要新版 Agent 上报」。

**节点列表把从未生效的入站显示为「已生效」（第 9 项）。** 原来按整台服务器最近一条修订贴标签。新增只读接口 `GET /api/v1/nodes/{id}/inbound-states`，按入站与服务器当前运行的修订比较，显示已生效／有未发布修改／发布中／未生效（附最近一次失败原因）；入站未生效时「真实状态」显示「未生效」；Hysteria2／TUIC 的传输显示 `udp + quic`。

**Windows 上国旗只显示国家代码（第 5 项）。** 自托管 Twemoji 国旗字体（约 78 KB，`unicode-range` 仅限国旗码位，页面出现国旗时才加载）。

## 新增与改进

**安装命令可选启用网页升级（第 4 项）。** 三个安装命令弹窗增加「启用网页升级」勾选框（默认不勾选），勾选后命令带 `--web-upgrade`，装完即可在面板网页上升级 Agent。`node-install.sh` 不带该参数时不再自动启用网页升级（与 1.5.0 不同），需要时在节点本机运行一次 `qui-update --component agent`。

**安装命令弹窗不再编辑面板地址与端口（第 3 项）。** 统一使用「系统设置 → 节点安装连接地址」或浏览器地址，弹窗只读显示本次命令使用的地址。

**用户详情「可用节点」（第 6 项）。** 改为列出该用户订阅里实际可用的节点（名称、协议、地址:端口，中转／导入有标签），不再显示服务器信息；订阅预览接口的条目增加 `name` 与 `kind`。

**监控图表改用 Chart.js（第 8 项）。** 参考 CF-Server-Monitor：坐标轴、网格、面积填充、图例与悬停读数；CPU 与负载（双轴）、内存与交换、下载与上传、TCP 与 UDP 合并展示，共 7 张卡片。Chart.js 只在监控页按需加载。

## 迁移与升级注意

- 无迁移，面板可在 1.5.0 与 1.5.1 之间直接升级。
- 已启用网页升级的 1.5.0 节点可直接在面板「版本与更新 → Agent」点「升级」。升级只替换实际运行的 Agent；`/usr/local/bin/proxy-agent` 监督进程仍是 1.5.0，下次运行 `qui-update --component agent` 时更新。worker 1.5.1 已足以修复「发布指定核心入站失败」（存储格式已升级的节点直接跳过检查）。
- 未启用网页升级的节点：运行 `qui-update --component agent` 升级（从 ≤1.4.7 升级仍需运行两次）。
- `node-install.sh` 默认不再启用网页升级，需要时在安装弹窗勾选「启用网页升级」。

## 已知限制

- 第 2 项实测覆盖测试机 systemd＋sing-box SOCKS5，以及 5.45.96.43 网页升级后的 Hysteria2＋ACME（该机监督进程仍为 1.5.0，只有 worker 是 1.5.1）；Alpine/OpenRC、TUIC、GOST，以及「存储格式尚未升级」的初始状态只有单元测试。
- `ApplyResult` 协议没有原因字段，早期失败的原因文字只写进 Agent 日志，面板只显示错误码。
- 核心启动失败时保留 stderr 末尾的诊断延后。
- 后端订阅预览测试只覆盖自建入站的 `kind`，中转与导入两类没有用例。
- 延迟图未改为 Chart.js 风格。
- 「版本与更新」页的国旗方块使用等宽字体，等宽字体栈没有加国旗字体，Windows 上该页仍显示「DE」「HK」；其他页面（节点列表等）已显示国旗。留待下一版。
