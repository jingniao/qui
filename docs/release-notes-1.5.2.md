# v1.5.2 发布说明

v1.5.2 是 v1.5.1 的补丁版，带一个**只写数据**的迁移 0142（迁移头 0142）。按 Owner 要求版本号仍为 1.5.2。逐项设计、根因与验收见 [v1.5.2 规划](v1.5.2-plan.md) 第 1–8 项。

> **已知问题（已由 [v1.5.3](release-notes-1.5.3.md) 修复，请直接升级到 1.5.3）：** 启用「屏蔽回国」这类展开后很大的策略并发布时，sing-box 加载规则约需 30 秒；期间 Agent 先上报了新修订的流量，面板拒收并断开控制连接，应用结果随之丢失，节点一直停在「发布中」、反复离线重连（数据面已在运行新修订）。见下文「实机验证」。

## 新增与改进

**内置三个「屏蔽回国」客户端策略预设（第 7 项）。** 新建客户端策略配置时可以从内置模板开始，新增「精简／标准／完整分流 · 屏蔽回国」三档，按 MetaCubeX meta-rules-dat 的 mrs 规则集组织（5／14／58 个规则集）。国内域名（`geolocation-cn`、geosite `cn`）与国内 IP（`cn`）直接 REJECT，不经过客户端能切回直连的组，国内域名规则排在所有服务规则之前。参考配置里不存在的三个规则集已换成仓库里实际存在的：`applemusic` → `apple-music`，`proxy` → `gfw`，`proxymedia` → `category-media`。套用预设时一并接管规则集与 DNS（之前只复制组与规则，规则集会丢）。

**规则集上限 32 → 256。** 一个客户端策略模板最多 256 个规则集；请求体仍为 1 MiB，超过时提示「请求内容超过 1 MiB 上限」，不再是笼统的「invalid JSON request」。保存失败时，规则集与策略组字段错误显示中文名称。

**补齐内置规则集（第 8 项，迁移 0142）。** 在原有 7 个内置规则集之外，按「完整分流」的服务分组新增 18 个：广告拦截、AI 服务、微软服务、苹果服务、社交媒体、流媒体、游戏平台、教育资源、金融服务、云服务、Spotify、Pixiv、Abema、E-Hentai、代理服务、代理媒体、国内、私有网络。25 个内置集合都挂上 meta-rules-dat 的 yaml 来源，节点策略与客户端共用。

- **只抓取被引用的集合**：面板只定时刷新被至少一条已启用节点策略引用的集合；策略保存后立即抓取尚未成功的来源。未被引用的集合在「规则集」页面显示「未被策略引用，不自动刷新」，手动刷新不受限制。客户端规则引用不触发面板抓取，因为订阅直接输出来源地址。
- **内置「屏蔽回国」节点策略**：默认禁用，作用于全部节点，匹配「国内」集合（约 5400 个域名＋9600 个 IP 段），动作 Block，优先级 1。启用并发布后生效；可以编辑或删除，删除后升级不会再写回。节点侧「国内」集合不含 geosite `cn` 的全部 11 万条域名（如 `www.qq.com` 只在后者里），这类域名靠客户端「屏蔽回国」预设拦截。

**节点策略展开后的上限 2000 → 50000（第 8 项前置修复）。** v1.5.0 起，节点策略引用的规则集（含外部来源缓存）展开后超过 2000 条就会让该节点整次发布失败，提示英文 `policy matcher limit exceeded`。现在 Owner 手写的条目仍限 2000 条，展开后单条策略最多 50000 条。超过 2000 条只发布到上报新能力位 `expanded_policy_supported`（`Capabilities` 字段 29、`CoreCapability` 字段 14）的 1.5.2 Agent；旧 Agent 在快照与发布前得到带策略名与条数的中文提示，明确指定节点或节点组的策略在保存时就列出这些服务器。节点配置超过 2 MiB 的提示也改为中文。

**延迟图与机器监控统一（第 3 项）。** 「网络质量与延迟」改用与机器监控相同的 Chart.js 图表：12px 坐标轴、顶部圆点图例、悬停读数；横轴刻度自动生成（12H 不再只有一个刻度）；丢包改为右侧第二纵轴的虚线；只保留机器监控右上角一套时间范围控件。

**Reality 握手目标说明。** 补充「部分站点只适用于 sing-box，Xray 连接会失败；不确定时从常用目标中选择」；常用目标去掉 `www.microsoft.com:443`（官方 Xray 26.3.27 用它握手失败）。

## 修复

**监控页面反复显示「正在读取历史指标…」并清空图表（第 1 项）。** 监控卡片不再因每条心跳重新读取历史指标，只靠 60 秒定时刷新，后台刷新保留旧图，失败也不清空；节点 ID 与时间范围不变时不再清空。节点状态事件带上节点 ID，节点详情只响应本节点，其余列表页面 5 秒内最多重读一次。

**「版本与更新」页国旗仍显示字母（第 2 项）。** 等宽字体栈首位加入国旗字体。

**sing-box TCP 入站让 Agent 每 30 秒记一条 WARN（第 4 项）。** Agent 自己对 sing-box TCP 入站的健康检查连接（来自回环地址、没有目标）不再计为未归属观测；非回环、没有目标的连接仍照常计数。

**HTTP／SOCKS5／Shadowsocks 入站可以选 WebSocket、gRPC（第 6 项）。** 这些协议只允许 TCP：编辑器只列 TCP，面板保存、生成快照与发布前三处一致拒绝并给中文提示。规则不进入期望状态解码，历史修订、回滚与备份仍能读取旧组合。

## 迁移与升级注意

- **迁移 0142 只写数据**：新增内置规则集、来源与禁用的「屏蔽回国」策略，不改表结构。ID 或名称已存在的内置集合跳过（例如已有名为「国内」的自定义集合时，不建内置「国内」集合，也不建「屏蔽回国」策略）；已有外部来源的内置集合不追加来源；0009 内置集合的描述仍为原文时才更新。跳过的项不另行提示。
- **已保存的不合法传输组合**：若某节点上有 HTTP、SOCKS5 或 Shadowsocks 入站带 WebSocket／gRPC／xhttp（包括已禁用的入站），升级后该节点的发布（含自动额度版本）会被拒绝，提示「… 入站只支持 TCP 传输 …」。处理：在入站编辑器里把传输改为 TCP（或删除该入站）后重新发布。2026-11-12 只读检查生产：9 个入站中 HTTP、SOCKS5、Shadowsocks 都是 TCP，没有不合法组合；生产现有 7 个内置规则集均无来源、没有与 0142 同名的自定义集合，升级时 18 个新集合、63 个来源与「屏蔽回国」策略会全部写入。
- **「屏蔽回国」与大规则集需要 1.5.2 Agent**：展开后超过 2000 条的策略只能发布到 1.5.2 Agent；先升级 Agent 再启用。
- **客户端屏蔽回国依赖节点可用**：mihomo 下载规则集同样走规则，用户的节点全部不可用时规则集为空，屏蔽不生效。
- 面板与 Agent 的升级方式与 1.5.1 相同；已启用网页升级的节点可在「版本与更新 → Agent」直接升级。
