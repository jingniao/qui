# v1.5.3 发布说明

v1.5.3 是 v1.5.2 的补丁版，**没有迁移**（迁移头仍 0142）。只修一个在 v1.5.2 实机验证中发现的问题；v1.5.2 的全部内容见其[发布说明](release-notes-1.5.2.md)。**已升级到 1.5.2 的面板请直接升到 1.5.3。**

## 修复

**发布大策略后节点停在「发布中」、反复离线重连。** 在 Owner 自己的面板 qui.lluu.de 上，把内置「屏蔽回国」策略（展开后约 15000 条）发布到「德国 netcup」（Agent 1.5.2）时：

1. sing-box 加载这些规则约需 30 秒才开始监听；Agent 在这段时间里已经切换核心，采集器开始按新修订 28 上报流量。
2. 面板只接受「部署成功」修订的流量与访问记录，修订 28 还在等待结果，于是拒收（`traffic batch rejected`，之后 `access batch rejected`），控制连接随之断开。
3. 这次应用完成时会话已断开，应用结果随会话一起丢失；此后每次重连都先发送被拒的批次，面板重发的应用命令总是来不及完成，节点一直停在「发布中」，约每 30 秒断开一次，页面时常显示离线。数据面不受影响：两个核心都在运行修订 28，原有入站照常工作。

这个竞态在应用耗时较短时也存在，只是窗口很小；1.5.2 允许大策略后变得容易触发。修复：

- **面板**：已下发给该节点、仍在等待结果的修订，它的流量与访问记录照常归属（`deployment.Repository.AppliedState` 接受 `pending`）；失败或回滚的修订仍拒绝，从未下发的修订也拒绝。已经卡住的节点在面板升级后即可恢复：重发的应用命令能执行完，结果被接受。只升级面板就能解决，旧 Agent 同样适用。
- **Agent**：同一轮里先发送已产生的应用结果，再发送流量与访问记录批次，避免结果排在新修订的数据后面。

## 迁移与升级注意

- 无迁移，面板可在 1.5.2 与 1.5.3 之间直接升级。先升级面板即可解决上述问题；Agent 升级到 1.5.3 是额外保险。
- 其余升级注意（迁移 0142、HTTP／SOCKS5／Shadowsocks 只允许 TCP、展开后超过 2000 条的策略需要 1.5.2 及以上 Agent）同 1.5.2。

## 已知限制

- 节点侧「国内」集合只含 `geolocation-cn`（约 5400 个域名）与国内 IP 段，geosite `cn` 里的大量域名（如 `www.qq.com`）在节点侧按域名匹配不到；客户端「屏蔽回国」预设引用了完整的 geosite `cn`，两者配合使用。节点按 IP 段匹配只对客户端直接用 IP 连接的请求生效。
- Agent 侧的发送顺序调整没有单独的时序测试。
- 被隔离的流量批次在冷却（1 小时或 Agent 重启）后重试：本次两批在 03:22Z Agent 升级重启后重试并被接受，Agent 本地队列已清空（流量 0、访问记录 0）。
