# v1.5.7 发布说明

**已于 2026-11-15 发布，tag `v1.5.7` → `bd4fe2f`。** 无迁移，迁移头仍为 0149。来源为 v1.5.6 生产删除测试中发现的问题（E1–E4、E7–E9，见[删除测试记录](v1.5.5-production-relay-cleanup-test.md)第 6 节）与 Owner 的节点列表调整。

## 修复内容

- **E1** 隧道发布遇到中转依赖错误返回 409 `dependency_not_ready`，写明出站、目标节点与原因码（v1.5.6 为 500）。
- **E2** 撤除阶段被 Agent 拒绝或回滚返回 409 `remove_apply_failed`，文案为节点名与固定结果码（v1.5.6 为 400 并显示节点 ID）。
- **E3** 遗留资源「只处理一部分」勾选区改为普通分组，第一行不再被挤成右侧窄列。
- **E4** 隧道页与「使用已有隧道」的失败提示不再出现「。。」。
- **E7（Agent）** 开启访问记录时，VLESS／Trojan／Shadowsocks 不再按「入站×凭据」复制节点策略规则：这些协议的 Xray 访问行自带 email，账户由访问日志归属。WireGuard（逐对端计数依赖克隆出站）与 HTTP／SOCKS5（用户名账户）保持原样。此前「屏蔽回国」等引用原生规则集的策略会按凭据重复加载 geosite／geoip，在美国 shlii.io（256 MB 容器）上使 `xray run -test` 被内存上限杀掉，表现为每次发布 `validation_failed`。须升级 Agent 才生效。
- **E8** 「停用并移除」不再绑定 HTTP 请求：撤除在面板后台运行，请求最多等待 5 秒，未完成返回 202 `{schemeId,status:"removing"}`；同一方案的重复请求复用进行中的撤除、不再新建修订；新增 `GET /api/v1/canvas-schemes/{id}/remove-status`（`idle`／`removing`／`succeeded`／`failed`）。客户端断开不再取消或回滚已在节点成功的阶段，只有面板关闭会中止并持久化恢复命令；审计在后台完成时写入。撤除结果保存在内存，面板重启后丢失（方案已不存在即视为成功）。页面每 2 秒查询状态，关闭弹窗后完成仍会刷新列表。
- **E9** 面板不再因已取消修订的数据断开 Agent 控制连接：已终结目标的应用结果确认后忽略并记一条 WARN；本节点已下发、因撤除取消（`canvas_remove_canceled`）的修订的流量、访问记录与设备观测照常归属；调度清理后才到达的 TCP 探测结果校验格式后确认并丢弃。未知或不属于本节点的修订仍拒绝。

## 节点列表调整（Owner 2026-11-15）

- 卡片标题行只保留国旗、名称与协议；原「直连／中转」与「来源 · 传输 · 延迟」两行合为一行，状态合并为一个标识放在该行右端。合并规则：状态未知 ＞ 离线 ＞ 未生效 ＞ 发布中 ＞ 在线·有修改 ＞ 在线（导入节点为在线／未检测／离线），悬停同时显示服务器状态与发布状态。列表视图的状态列使用同一标识，名称旁不再单独显示发布状态。
- 中转、隧道卡片的方案名改为路径的悬停提示，点击路径仍跳转到方案。
- 「中转线路」在每张卡片上默认收起，标题保留数量。
- 隧道的出口／中间监听不再单独显示，只在隧道管理里出现；关联到节点的隧道规则与中转方案一起显示在出口节点的「中转线路」中，合计数量，并使用与方案相同的小卡片（路径、隧道转发与发布状态、入口地址与复制、Owner 可编辑）。
- 出口为服务器的中转方案挂在该服务器在列表中的第一张自建节点卡片下，新建入口随之收起；该服务器在列表中没有卡片时入口仍单独显示。
