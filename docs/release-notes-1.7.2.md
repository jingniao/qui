# v1.7.2 发布说明

状态：2026-11-19 正式发布，tag → `aacf4db`，未部署生产。Owner 指定使用 v1.7.2，包含四批展示读取优化与总览固定高度卡片；新增迁移 0155。

## 变化

- 服务器运行状态用白名单快照和 SSE 更新，前台恢复时保留完整卡片；轻量校准修正漏掉的事件，真实离线仍正常显示。展示刷新由后台队列处理，不阻塞 Agent 心跳确认。
- 新增可重建的代理流量小时索引：完整小时读取汇总，时间边界读取原始样本，保留来源切换、去重、补传、溢出错误与压缩历史的精度限制。原始流量账本和用户额度计算不变。
- 后台统一准备日／月／趋势／整机统计，总览、服务器列表与详情复用同一版本。配置改变使旧结果失效；失败明确报告原因，适用时保留上次完整结果及其截止时间。
- 总览基础内容与流量统计分开读取，保留待处理问题、节点流量、用户用量与到期、近期阻断。四张内容卡片固定为 480px，长列表内部滚动，标题保持可见。
- 服务器详情按节点读取统计；修复清单刷新失败后不重试、调优建议过期、跨页旧账期缓存和夏令时跳过午夜的日期边界问题。

## 验证

本地相关 Go 回归、前端自测、类型检查、构建和 Chrome 冒烟已通过。固定的 120,960 条样本查询约从 150.74ms 降至 2.71ms，先验证两种查询结果相同后计时；这是本机组件测量，不能当作生产网页耗时。

发布提交 `aacf4dba3f0a20bbfff69bdc2a0794648145d3a8` 的完整 Linux 门禁通过：`GATE aacf4db PASS total=876s`，其中真实核心测试 306 秒，含 `go test -race ./...`、前端检查及部署脚本测试。同 SHA 的 [GitHub check 44525017037](https://github.com/jingniao/qui/actions/runs/44525017037) 通过，包含真实核心测试与发布包试构建。Windows 的 race 曾因 ThreadSanitizer 影子内存分配失败而无法运行，最终并发检查以这次 Linux 通过结果为准。

首轮发布检查保留失败事实：快速检查发现服务器排序自测未提供新加载流程的校准依赖，补齐夹具并保留原排序断言后通过。首个发布提交 `95ef33e` 的完整检查发现四个新接口未登记到管理员／门户权限覆盖清单，以及迁移 0155 未登记不可变校验和；本地门禁 `FAIL total=833s`，GitHub check 44523044587 的 server/rest 分片也失败。补齐登记后，三个针对性用例通过，原有权限拒绝断言和旧迁移校验值未改动。这些是本批改动的验证遗漏，不按偶发失败处理；修正后的 `aacf4db` 已重新通过上述两条完整门禁。

实现、迁移成本测量、回归范围与覆盖限制见[四批实施记录](superpowers/plans/2026-11-19-prepared-display-data.md)。生产首屏 P95、真实节点长时间后台恢复、持续写入时的迁移等待及 WAL 峰值尚未验收。
