# v1.7.5 发布说明

状态：已正式发布 v1.7.5（发布当时未部署生产；后续生产观察见[项目说明书](project-spec.md#当前状态)）。

## 内容

- 管理后台与订阅统一使用通知规则「节点离线」的持续时间。短暂断线显示「连接中断，等待恢复」，达到设定时间后才判定离线；取消通知勾选只关闭通知。
- 网页 Agent 升级由服务器本机运行 `qui-update --component agent --version X.Y.Z --yes`，复用终端的官方来源、校验、完整安装、健康检查和失败恢复流程。
- 任务记录区分完整升级与历史工作进程升级，保留每次尝试、失败阶段、原始错误、退出码、基础组件与实际 Agent 版本、服务与恢复结果，并提供任务输出读取和下载。
- 订阅按成功发布的完整路径判断可用性。入口、中间、出口或后续固定链任一受管服务器维护或确认离线，相关整条线路退出订阅；等待恢复期间保留，恢复可用后重新包含。
- 路径过滤适用于统一订阅候选及客户端链，URI、Base64、Clash 与 sing-box 使用同一结果。纯导入节点没有受管机器身份时，不按地址猜测离线。

## 迁移与升级

新增 **0157**（完整 Agent 升级能力、任务、尝试与日志）和 **0158**（成功发布线路依赖索引），迁移头 **0158**。版本按 Owner 指定采用 v1.7.5。

已有 Agent 需要先在终端完成本机安装组件升级，安装新的独立 root 更新桥接服务。旧更新器可能需要再次运行同一版本的 `qui-update --component agent`；网页依据实际桥接探测结果提供入口，不仅依据版本号。历史工作进程任务继续保留原有查询和恢复流程。

新网页任务不使用面板托管的 Agent 文件。服务器无法访问终端使用的 GitHub 来源时，直接记录下载错误。两阶段升级可能留下新基础组件和旧 Agent，任务分别记录观测结果，不把它显示为整套升级成功。

离线或维护过滤只改变订阅输出，不撤销凭据、不自动发布、不停止服务器上的现有配置。客户端需重新拉取订阅才能得到变化；已有连接沿用节点运行行为。

已发布的动态出口组按全部可能经过的受管候选计算依赖；任一候选维护或确认离线，会排除这个订阅入口。服务器上的组选路规则保持原样，不自动生成「仅保留健康成员」的新配置。
