# v1.9.0 发布说明

## 功能与修复

- 节点可以只安装 Agent，或只安装 GOST。安装命令支持 `--no-core`，网页安装选项允许不选内核；后续可在「内核管理」添加 Xray／sing-box。
- 纯 GOST 节点可做端口转发和隧道任意跳。没有用户内核时，界面显示「未安装内核」或「仅 GOST（纯转发）」，入站、出站、策略与订阅按实际能力限制。
- 已有节点可以移除最后一个用户内核，再按需添加。有依赖对象时返回 `user_core_in_use`；旧回退镜像不支持新存储格式时返回 `fallback_incompatible`，保留原运行状态。
- 无用户内核节点继续登记、心跳、采集整机指标和执行 Agent 网页系统升级；拒绝含用户入站的配置并保留上一份成功配置。
- 服务器续费信息新增自动续费：按面板时区在到期日过后按原周期顺延日期，保留续费提醒并记录审计。支持月、季、半年、年、两年和三年周期，月末夹紧到短月末日。
- 修复 OpenRC 零内核首装缺少更新监听器目录、登记目录白名单不接受安装器创建的 `system-update` 目录的问题。前端自测沿用真实的用户内核过滤逻辑。

## 兼容与迁移

迁移头为 **0160**，新增 `node_meta.auto_renew`，默认关闭。最低兼容版本仍为 **v1.7.5**，保留有效数据与在途任务。

Agent 支持配置存储格式 6。零内核／纯 GOST 首装以及移除最后一个用户内核会启用格式 6；保留用户内核的旧节点不会因此自动抬升。启用后，即使加回 Xray／sing-box，也不能降回不支持格式 6 的旧 Agent。

## Linux 实机验收

在隔离的 Alpine/OpenRC 节点与真实非开发面板上，使用官方 Xray 26.3.27、GOST 3.3.2 验收；进程、文件系统与身份独立，宿主网络共享，监听端口各不相同。

- 零内核首装、登记、网页添加 Xray、发布用户 SOCKS 入站、授权节点组、导出 Clash 订阅及带用户凭据的真实 HTTP 请求通过。
- 纯 GOST 入口跳和中间跳组成三跳 TLS 隧道，真实 HTTP 请求通过。
- 有入站时移除被拒；清空后移除 Xray、纯 GOST 转发、重新添加 Xray 后的用户订阅请求及原 GOST 转发通过。
- 普通 Xray 节点的认证配置格式从 4 抬升到 6 后移除成功；纯 GOST 转发及重新添加 Xray 的真实请求通过，加回后格式仍为 6。
- 真实 v1.7.5 工作进程升级为 v1.9.0 后，原转发响应和修订文件摘要保持一致；保留旧回退镜像的节点移除用户内核被 `fallback_incompatible` 拒绝。
- 在格式 6 数据上启动实际 v1.7.5 Agent，以旧版可解析的配置排除 YAML 校验干扰后，启动被存储认证兼容门禁拒绝。
- 零内核节点通过网页触发完整 `qui-update` 系统更新，下载、摘要核验、安装与服务健康检查成功，实际程序摘要、引导／安装／运行版本及 `cores: []` 已核对。发布前使用仅测试环境信任的 HTTPS 候选仓库与本地测试签名；起始程序是实机验收提交 `9931e3d` 构建、标记为 `1.8.999` 的验收夹具，不代表正式 v1.8 系列支持零内核。未提前发布正式版。
- 向隔离测试面板注入含用户入站的修订，实际 Agent 返回 `no_user_core`，原成功修订和文件保持不变。

原始证据保存在 Linux 测试机 `/root/qui-v190-accept/evidence/`；测试私钥、令牌、身份与配置未进入仓库。

## 生产与边界

本轮未连接或升级生产。arm64 未运行原生实机验收。v1.7.6 按 Owner 要求删除的历史测试未恢复；其他既有未验证边界见[实施决定](../implementation-decisions.md)。

已复现的上游边界：Xray 26.3.27 的 splice 路径中，只关闭客户端而源站继续等待 EOF 时，半关闭超时可能被覆盖为 24 小时，在线来源随尚未结束的会话继续保留。本轮未修改上游核心；连接观察验收明确关闭两端后再检查来源消失与观察窗口保留。
