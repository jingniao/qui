# v1.5.0 执行计划总索引

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按 [v1.5.0 规划](../../v1.5.0-plan.md) 的 11 项需求，分 P1–P7 七个阶段实现、审查并发布 v1.5.0。

**Architecture:** 每个阶段一份独立计划，各自可测试、可审查；阶段之间只通过本文登记的 proto 字段号、迁移号和公开接口衔接。全部阶段完成后在同一快照上跑一次完整门禁再发布。

**Tech Stack:** Go 1.26（面板与 Agent）、SQLite（modernc）、protobuf/gRPC、Vue 3 + TypeScript + Vite、Node 自检脚本（`web/scripts/*-selftest.mjs`）、bash 部署脚本。

**Spec:** `docs/v1.5.0-plan.md`（需求与验收）；`AGENTS.md`（产品规则与安全边界）；`docs/release-runbook.md`（发布流程）。

## Global Constraints

- 改动只能通过既有模块接口扩展；跨模块调用用 Go 接口或回调，由 `internal/platform/server/server.go` 装配（说明书 §24）。
- 新迁移只能新增文件，编号按下表；每个新迁移同时：在 `migrations/checksums_test.go` 登记校验和；在 `internal/panel/system/backup/` 与 `internal/platform/recovery/` 各加一个 `rewind<Name>` 夹具，并让上一个最新的 rewind 函数先调用它（参照 `rewindCertificates`、`rewindNodeConnectAddress`）。
- proto 只做加法，字段号按下表；改完运行 `bash scripts/generate-proto.sh`（本机已有 `.tools/protoc` 与插件），提交生成的 `pkg/contracts/agentpb/agent.pb.go`。
- Agent 解码期望状态拒绝未知字段：任何新的 `desiredstate` 字段都必须有能力位门禁，面板在保存、快照（`SnapshotIntent`）与发布前（`deployment.validateStateCoresTx`）三处一致拒绝旧 Agent。
- 前端：不可用的选项直接隐藏不置灰（例外：请求进行中的按钮、编辑中的当前值、只读展示）；不替换 Owner 已有页面布局；字号规则见 `docs/design-system.md` §3（正文 14px、辅助 ≥12px）。
- 新增 `web/scripts/*-selftest.mjs` 必须在 `scripts/check.sh` 的自检列表里登记（参照第 87–91 行）。
- 新增 HTTP 路由必须写进 `internal/platform/server/testdata/portal_route_coverage.txt`；Owner 写接口要求 CSRF 并调用 `system.Repository.Record(ctx, operator, action, target, result, ip)` 记操作日志。
- 密钥类数据（Bot Token、Webhook 地址）用 `vault.Vault.Seal/Open` 加密存 `system_settings`，接口只回「已设置」与末 4 位；随加密备份往返。
- 外发 HTTP 必须有超时与大小上限，失败只记固定错误码，不回显上游正文或带密钥的 URL。
- 文本文件 LF、无 BOM；新建 `.sh` 用 `git update-index --chmod=+x` 设为 100755。
- **提交与推送**：每次提交、推送、打 tag、升级生产都要 Owner 明确同意（`docs/release-runbook.md` §0）。计划里的「提交」步骤只在 Owner 授权「执行期间可在本地逐任务提交」后执行；推送另行同意。

## 开工前决定（Owner）

1. **P2 安全边界**：官方构建内置 Ed25519 公钥；Agent 在未配置 `updates` 时，只接受「主机名等于自己的控制连接主机、端口来自 Welcome、证书由面板 CA 签发」的面板目录。这放宽了「控制消息不得引入 URL」的现有规则（只放开端口，不放开主机与信任根）。**Owner 已于 2026-11-09 同意。**
2. **P2 签名密钥**：执行者生成密钥对，Owner 在 GitHub 仓库 Settings → Secrets 新建 `AGENT_SIGNING_KEY`（私钥 base64）。私钥不进仓库、文档与日志。
3. **执行期间是否允许本地逐任务提交**（推送仍逐次同意）。
4. **生产是否先升级到 v1.4.7**，以及 Alpine 主机 SSH（113.29.231.218:10141）需先恢复。
