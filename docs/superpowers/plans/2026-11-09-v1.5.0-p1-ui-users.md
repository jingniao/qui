# v1.5.0 P1：界面修复、发布状态与用户协议 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复提示被弹窗遮住、用途组不能加全部节点、调优预设清空草稿；发布后实时显示结果；去掉用户的协议控制。

**Architecture:** 以前端改动为主。发布状态复用现有 SSE `deployment_status` 与 `GET /api/v1/revisions?nodeId=`，不新增后端状态；用户协议改为后端统一视为全部协议，启动时补齐并由已有的 `EnsureAllAccessIdentities` 与自动额度对账下发凭据。无迁移、无 proto 改动。

**Tech Stack:** Vue 3 + TypeScript、Node 自检脚本、Go（`internal/panel/user`、`internal/platform/server`）。

**Spec:** `docs/v1.5.0-plan.md` §0、§4、§5、§8、§10「补充判断」最后两条；总索引 `2026-11-09-v1.5.0-index.md` 的 Global Constraints 适用于本计划。

## Global Constraints

- 见总索引。另：用户 API 仍接受并返回 `allowedProtocols` 字段（兼容），但不再作为限制。

## Review Focus

- 旧客户端（或旧页面缓存）提交 `allowedProtocols: ['socks5']` 时，保存后仍得到全部 8 个协议——Task 6 的 `TestInputValidateGrantsAllProtocols` 覆盖。
- 发布后 Agent 一直不应答（离线）：进度停在「待服务器确认」并在 120 秒后提示可去配置版本查看，不能无限转圈——Task 3 的 `publishWatchTimeout` 断言覆盖。
- 同一编辑器连续发布两次：第二次的进度不能被第一次的事件覆盖——Task 3 的 `revision` 匹配断言覆盖。
- 用途组已经含 `@all` 时再选一次不重复添加——由现有 `addGroupMemberDirect` 去重保证，Task 2 自检断言选项值为 `@all`。
- 调优预设合并时，用户已填但预设未涉及的参数保持不变——Task 7 的 `applyPreset` 断言覆盖。

- Produces（Task 4、5 复用）：

```ts
export type PublishTone = 'info' | 'success' | 'danger' | 'warning';
export interface PublishPhase { label: string; tone: PublishTone; final: boolean }
export function publishPhase(status: string): PublishPhase;
export const publishWatchTimeout = 120_000;
export interface PublishWatch { stop(): void }
export function watchPublish(nodeId: string, revision: number, onUpdate: (phase: PublishPhase, timedOut: boolean) => void,
  deps?: { list?: typeof deploymentAPI.nodeRevisions; now?: () => number; setTimer?: typeof setTimeout; clearTimer?: typeof clearTimeout; target?: EventTarget }): PublishWatch;
```

`publishPhase` 映射（固定文案）：`draft`→`草稿未发布`/warning/final；`pending`→`待服务器确认`/info/非 final；`success`→`已生效`/success/final；`failed`→`失败，已保留原配置`/danger/final；`rolled_back`→`已回滚`/danger/final；其他→原值/warning/final。`watchPublish` 在收到 `proxy-deployment-status` 事件或每 3 秒轮询时调用 `list(nodeId, 1, 20)`，只认 `id === revision` 的条目；final 时停止；超过 `publishWatchTimeout` 回调 `timedOut=true` 并停止。
