# v1.5.0 P2：Agent 网页一键升级 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 正式版发布时自动生成 Agent 签名清单；面板从 GitHub 导入并托管签名目录；Agent 默认信任官方公钥并从自己的面板下载，Owner 在「Agent 管理」一键升级。

**Architecture:** CI 用 `cmd/release sign` 给每个架构的 `proxy-agent` 签名并上传 `.manifest.json` 与 `.bin`。面板新接口按版本导入：经 GitHub（允许跳转到 GitHub 下载主机）下载、用内置公钥与清单摘要校验、写入面板目录 `/var/lib/proxy-panel/releases/agent-catalogue/`，再用既有 `SaveRelease` 登记，由 Web 监听上的只读路由 `/agent-catalogue/` 提供。Agent 的下载器拒绝任何跳转，所以不能直接用 GitHub；未配置 `updates` 的 Agent 用「控制主机＋Welcome 给的端口＋面板 CA＋内置公钥」组成默认目录。排队与执行沿用既有 `POST /api/v1/agent-updates` 与 Agent 更新流程。

**Tech Stack:** Go（`cmd/release`、`pkg/contracts/release`、`internal/agent/agenthost`、`internal/agent/control`、`internal/panel/deployment`、`internal/panel/system`）、protobuf、GitHub Actions、Vue。

**Spec:** `docs/v1.5.0-plan.md` §1；总索引的 Global Constraints、proto 登记（Capabilities 26、Welcome 22）与「开工前决定」第 1、2 条。

## Global Constraints

- 「开工前决定」第 1 条（安全边界）Owner 已于 2026-11-09 同意；`AGENT_SIGNING_KEY` Secret 必须在 Task 2 之前建好，否则停在 Task 1 之后。
- 签名清单序号 `sequence = major*1_000_000 + minor*1_000 + patch`（1.5.0 → 1005000）；只给正式版 `X.Y.Z` 签名，RC 不签。有效期 `--valid-for 8760h`（清单规则上限 366 天）。
- 默认目录只接受：主机名 == Agent 配置的 `control_address` 主机；端口来自本次连接的 `Welcome.agent_catalogue_port`（1–65535）；TLS 根 = Agent 配置的 `tls.client_ca`（面板 CA）。配置里显式写了 `updates` 时完全按配置，不用默认值。
- 面板导入只接受官方仓库 `github.com/jingniao/qui` 的正式版；下载允许的跳转主机与核心更新一致：`github.com`、`objects.githubusercontent.com`、`release-assets.githubusercontent.com`；单个文件上限沿用 `release.MaxArtifactBytes`、清单上限 `release.MaxManifestBytes`；整个导入 120 秒超时；失败统一 502 `agent_release_import_failed`，不回显上游。
- `/agent-catalogue/` 不需要登录（内容是公开且已签名的），只读、禁止目录列表、只服务上述两类路径，`Cache-Control: no-store`。

## Review Focus

- 面板目录里清单存在但 `.bin` 被删或损坏：Agent 下载按摘要拒绝，任务以 `download_failed` 结束，旧 Agent 继续运行——Task 6 的 `TestCatalogueServesOnlyKnownPaths` 加一条缺文件 404，Agent 侧由既有下载测试覆盖。
- 同一版本重复导入：幂等，不重复登记、不改已有文件——Task 4 的 `TestImportAgentReleaseIsIdempotent`。
- Agent 配置里显式写了 `updates`（自建签名的用户）：完全不受默认值影响——Task 3 的 `TestEffectiveUpdatesKeepsExplicitConfig`。
- Welcome 的端口为 0（旧面板）：Agent 不生成默认目录；Agent 未上报 `panel_catalogue_supported`（旧 Agent）时网页升级按钮按「不可用即隐藏」不出现——Task 3、Task 7。
- 有人伪造一个签名不对或用别的密钥签的清单放进 GitHub Release：导入拒绝——Task 4 的 `TestImportRejectsForeignSignature`。
