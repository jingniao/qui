# v1.5.0 P3：多公网地址与通知系统 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Agent 上报全部公网地址、Owner 点选中转地址、新建服务器可填连接地址；新增通知模块（通知中心、Telegram、Webhook），覆盖离线、资源占用、公网 IP 变化、整机流量与既有后台告警。

**Architecture:** 地址：Heartbeat 新字段 → 面板保存候选列表 JSON 与「选定地址」，`public_ip` 由选定地址或自动规则导出，其余消费方（中转、隧道、画布）不改。通知：新模块 `internal/panel/notification`，一个每分钟运行的评估器读取节点、资源采样、整机流量与地址候选，按规则与冷却生成通知，写库、推 SSE、发送到渠道；`system.alert` 通过事件总线订阅接入。迁移 0138、0139。

**Tech Stack:** Go、SQLite、protobuf、`internal/platform/vault`、`internal/platform/events`、Vue。

**Spec:** `docs/v1.5.0-plan.md` §2、§3；总索引的 Global Constraints、proto（Heartbeat 36）与迁移（0138、0139）登记。

## Global Constraints

- 地址判定只用 `pkg/contracts/netaddr.Public`；每次最多上报 16 个地址；候选里的对端地址来源记为 `peer`，网卡地址记为 `interface:<名称>`。
- 通知默认规则（迁移写入，可改）：

| kind | 默认开关 | threshold | duration_minutes |
| --- | --- | --- | --- |
| `node_offline` | 开 | — | 3 |
| `cpu` | 开 | 90 | 5 |
| `memory` | 开 | 90 | 5 |
| `disk` | 开 | 90 | 0 |
| `public_ip` | 开 | — | 0 |
| `machine_traffic` | 开 | 100（额度百分比） | 0 |
| `system_alert` | 开 | — | 0 |

  每条规则 `cooldown_minutes` 默认 30。阈值范围：百分比 1–100，持续 0–1440 分钟，冷却 0–1440 分钟。
- 渠道外发：10 秒超时、响应体最多读 64 KiB；错误码固定为 `channel_timeout`、`channel_network`、`channel_http`、`channel_rejected`；Telegram 请求 `POST https://api.telegram.org/bot<token>/sendMessage`，体 `{"chat_id":…,"text":…}`；Webhook `POST <url>`，体 `{"kind","severity","title","body","nodeId","at"}`，只允许 `https://`。
- 通知记录保留 90 天；评估器每 60 秒一次，同一节点同一规则在冷却期内不重复，恢复时发 `resolved` 一次并清除状态。
- Viewer 只能看到 `node_offline`、`cpu`、`memory`、`disk` 四类通知，不能看渠道与规则。

## Review Focus

- 面板重启后：已处于告警的节点不应立即再发一次（状态表持久化）——Task 6 的 `TestEvaluatorKeepsStateAcrossRestart`。
- 节点刚登记、从未上报心跳（`pending`）：不能算离线告警——Task 6 的 `TestPendingNodeIsNotOffline`。
- 资源采样缺测（NULL）：不触发也不算恢复——Task 6 的 `TestMissingSamplesNeitherFireNorResolve`。
- 渠道全部失败：通知仍写入通知中心，业务不受影响，渠道显示最后错误码——Task 7 的 `TestDeliveryFailureKeepsNotification`。
- 原手动 IP 不在新候选里：保留原值并标记提示，中转地址不变——Task 2 的 `TestMigratedManualAddressIsKept`。

type NodeSnapshot struct { ID, Name, Status string; LastHeartbeat time.Time; Addresses []string }
type MetricWindow struct { NodeID string; CPU, Memory, Disk []*float64 } // 最近 N 分钟，按时间升序，缺测为 nil
type TrafficSnapshot struct { NodeID string; UsedBytes, AllowanceBytes *uint64 }

type Event struct { Kind, Severity, NodeID, Title, Body, DedupeKey, Value string; Resolved bool }

规则：
- `node_offline`：`Status` 为 `offline` 且 `Now-LastHeartbeat ≥ duration` 触发；`pending`、`disabled` 不评估；再次 online 发 resolved。
- `cpu`／`memory`／`disk`：最近 `max(duration,1)` 个采样全部非 nil 且 ≥ threshold 触发；最近一个非 nil 采样 < threshold 发 resolved；全部缺测不变。
- `public_ip`：`Addresses` 排序后与状态里的 `Value` 不同即发一条 info（首次见到只记录不发）。
- `machine_traffic`：有额度且 `used/allowance*100 ≥ threshold` 触发，跌回去发 resolved（新周期）。
- 冷却：同 `DedupeKey`（`<kind>:<nodeId>`）在 `cooldown` 内不重复触发；resolved 不受冷却限制。
- 标题与正文为固定中文模板，例：`节点「us2」离线`／`已 3 分钟没有心跳`；`节点「uk」CPU 持续 5 分钟超过 90%`；`节点「alpine」公网 IP 变化`／`203.0.113.5 → 203.0.113.9`。
