# v1.5.0 P5：按域名查找证书 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 入站编辑器先填域名，再依次查找节点证书目录与面板证书库里覆盖该域名的证书；都没有时提供「申请证书」。

**Architecture:** Agent 在能力上报的 `HostInfo` 里附带 `/etc/proxy-agent/certs/` 的证书摘要（不含私钥内容），每 5 分钟重扫，变化时重新上报能力；面板已把能力整体存进 `nodes.capabilities_json`，无需迁移与新命令。面板新增只读匹配接口，同时查节点文件与证书库；前端据此给出选项，申请走既有 `POST /api/v1/certificates`。

**Tech Stack:** Go（`internal/agent/capability`、`internal/agent/control`、`internal/panel/node`、`internal/panel/certificate`）、protobuf、Vue。

**Spec:** `docs/v1.5.0-plan.md` §6；总索引的 Global Constraints 与 proto 登记（HostInfo 9、10，`CertificateFileSummary`）。

## Global Constraints

- 只扫描 `desiredstate.CertificateDirectory`（`/etc/proxy-agent/certs`）一层，不递归；每个文件先 `filepath.EvalSymlinks`，解析后必须仍在该目录内（复用 `internal/agent/core/certfiles.go` 的 `resolveCertificateFile`）；最多 64 个证书摘要；单文件最多读 1 MiB。
- 证书文件后缀 `.crt`、`.cer`、`.pem`；私钥候选后缀 `.key`、`.pem`。配对用 `tls.X509KeyPair` 在进程内检查，**私钥内容与路径以外的任何私钥信息都不上报**。
- 域名匹配规则与 `crypto/x509` 的 `VerifyHostname` 一致（通配符只覆盖一级）；已过期证书显示但标记「已过期」，不作为默认选项。
- 未配置 Cloudflare Token 时隐藏「申请证书」按钮，只显示去「系统设置 → 证书与 DNS」配置的说明（不可用即隐藏）。

## Review Focus

- 目录里有指向目录外的符号链接（例如 `/etc/ssl/private/x.key`）：不上报——Task 1 的 `TestInventoryIgnoresLinksOutside`。
- 证书与私钥不配对、私钥是 PKCS#8／EC：配对失败的证书仍上报但 `key_path` 为空，EC/PKCS#8 正常配对——Task 1 的 `TestInventoryPairsECAndPKCS8`。
- 目录不存在或 Agent 无权读：上报空列表且 `certificate_inventory_supported=true`，页面显示「节点证书目录为空」而不是报错——Task 1 的 `TestInventoryMissingDirectory`。
- 旧 Agent（不报 10 号字段）：页面不显示节点文件这一层，只查证书库——Task 3 的 `TestMatchesWithoutInventory`。
- 申请证书后签发失败：编辑器显示证书库的固定错误说明并保留表单——Task 4 的自检断言 `lastErrorText` 显示路径。

```go
type CertificateLibrary interface {
	// Covering returns issued (valid) library certificates whose names cover domain.
	Covering(ctx context.Context, domain string) ([]LibraryMatch, error)
	CloudflareConfigured(ctx context.Context) (bool, error)
}
type LibraryMatch struct { ID string `json:"id"`; Domains []string `json:"domains"`; NotAfter string `json:"notAfter"` }
type NodeFileMatch struct { CertificatePath string `json:"certificatePath"`; KeyPath string `json:"keyPath"`; DNSNames []string `json:"dnsNames"`; NotAfter string `json:"notAfter"`; Expired bool `json:"expired"` }
type CertificateMatches struct {
	Domain string `json:"domain"`; InventorySupported bool `json:"inventorySupported"`
	NodeFiles []NodeFileMatch `json:"nodeFiles"`; Library []LibraryMatch `json:"library"`; CloudflareConfigured bool `json:"cloudflareConfigured"`
}
// coversDomain matches like x509.Certificate.VerifyHostname (one-label wildcard, case-insensitive).
func coversDomain(names []string, domain string) bool
```

**Interfaces:**

```ts
export type CertificateChoice =
  | { kind: 'file'; certificatePath: string; keyPath: string; label: string; expired: boolean }
  | { kind: 'acme'; certificateId: string; label: string }
  | { kind: 'request'; label: string };
/** Ordered choices: unexpired node files, library certificates, expired node files, then request (when Cloudflare is configured and nothing usable exists). */
export function certificateChoices(matches: CertificateMatches, filesSupported: boolean): CertificateChoice[];
/** Apply a choice to the form: file → tlsSource 'file' + paths; acme → tlsSource 'acme' + certificateId. */
export function applyCertificateChoice(form: EditorForm, choice: CertificateChoice): void;
```

`filesSupported` 用现有 `certificateFilesSupported(server, core)`；为假时不产生 `file` 选项。界面：TLS 区块第一项是「域名」（即 `server_name`），右侧「查找证书」按钮（输入框失焦也触发，带 400ms 防抖）；结果以单选列表显示 `label`（例：`节点文件 fullchain.pem · 到期 2027-02-01`、`证书库 example.com · 到期 2027-01-15`、`已过期：old.pem`）；`request` 选项点击后调用 `certificatesAPI.create([domain], false, '')`，每 5 秒用 `certificatesAPI.list()` 查该证书状态，`valid` 后自动选中，`failed` 时显示其 `lastErrorText`；自签与粘贴仍在「其他来源」下拉里。
