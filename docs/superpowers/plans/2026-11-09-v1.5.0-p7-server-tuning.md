# v1.5.0 P7：服务器调优完善 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 调优页面显示真实状态（来源、可用性、初始值、漂移、重启后覆盖）；补齐有用参数；可加载的拥塞控制与排队算法可选；面板为每台服务器自动计算推荐；增加 TCP 重传率曲线。

**Architecture:** 白名单抽到共享包 `pkg/contracts/tuning`，面板、Agent、helper、备份校验共用。Agent 在 `HostInfo` 里加报虚拟化类型、每键存在／可写、已可用与可加载算法、sysctl 配置来源、进程文件句柄上限；心跳加 TCP 段计数。推荐是面板侧纯函数（`internal/panel/node/tuningadvice`），规则带版本号；「不采纳」与线路带宽由迁移 0141 存储。应用仍走现有调优请求（整份替换语义不变，前端负责合并）。

**Tech Stack:** Go（`pkg/contracts/tuning`、`internal/agent/{tuning,capability,control}`、`internal/panel/node`、`internal/panel/system/backup`）、protobuf、SQLite、Vue。

**Spec:** `docs/v1.5.0-plan.md` §10；总索引的 Global Constraints、proto（HostInfo 11–18、Heartbeat 37–38、TuningResult 4）与迁移（0141）登记。

## Global Constraints

- 白名单（键 → 边界）在原 13 个之外新增：`net.ipv4.tcp_slow_start_after_idle` 0–1、`net.ipv4.tcp_notsent_lowat` 16384–16777216、`net.core.rmem_default`／`net.core.wmem_default` 212992–268435456、`net.ipv4.udp_rmem_min`／`net.ipv4.udp_wmem_min` 4096–1048576。拥塞控制候选 `bbr cubic reno htcp hybla bbr2 bbr3`，排队算法 `fq fq_codel cake pfifo_fast`；页面只显示本机「已可用」或「可加载」的。
- 「可加载」= `/lib/modules/$(uname -r)/kernel/net/ipv4/tcp_<名>.ko*` 或 `…/kernel/net/sched/sch_<名>.ko*` 存在且未加载；`modules.builtin` 中的算法算「已可用」。helper 写入「可加载」的算法时由内核自动加载模块（2026-11-09 测试机实测），不调用 `modprobe`。
- 「可写」只是估计：键存在且 `/proc/sys` 不是只读挂载；最终以 helper 逐键回执为准。不存在的键（LXC 里的 `net.core.*`）草稿、预设、推荐都不包含。
- 推荐规则版本 `RulesVersion = "2026.11-1"`；推荐只填草稿，Owner 确认后才应用；可选设置「新服务器上线后自动应用推荐」默认关闭，存 `system_settings` 键 `tuning_auto_apply`（`{"enabled":false}`），只对该设置开启之后首次上报能力、且从未有过调优请求的服务器生效。
- 不做：批量应用、漂移通知、任意 sysctl、显式 `modprobe`、安装或更换系统内核、`ethtool`。

## Review Focus

- LXC（Alpine）上推荐与预设不出现 `net.core.*`，提交前过滤掉不存在的键，避免 helper 因一个键整体回滚——Task 5 的 `TestAdviceSkipsAbsentKeys`、Task 7 的提交过滤断言（`tuningRequest` 丢弃 `unavailable` 键）、Task 3 的 `TestApplyRollsBackWholeRequestOnAbsentKey`。
- 主机上 `99-bbr-qdisc.conf` 已设 bbr：显示「系统已是该值（外部配置）」，不作为推荐——Task 5 的 `TestAdviceSkipsSatisfiedKeys`、Task 7 自检。
- 内存 330 MB 的机器：缓冲推荐不超过 8 MiB；有 Hysteria2 入站时也至少 7.5 MiB——Task 5 的 `TestBufferTiers`、`TestQUICFloor`。
- 计数器回绕或重启（段计数变小）：该分钟重传率为 null，不出现负数——Task 4 的 `TestRetransRateResetIsNull`。
- 「不采纳」后规则推荐值变化（例如新增 Hysteria2 入站）：重新提醒——Task 6 的 `TestDismissalReappearsWhenValueChanges`。

type KeyState struct{ Present, Writable bool }

规则（值与理由固定）：

| Rule | 条件 | 键 → 值 | 级别 | 理由 |
| --- | --- | --- | --- | --- |
| `cc-bbr` | bbr 已可用或可加载，当前不是 bbr | `net.ipv4.tcp_congestion_control` → `bbr` | suggested | `BBR 在长距离和有丢包的线路上吞吐更稳定` |

| `idle-restart` | 当前不是 0 | `net.ipv4.tcp_slow_start_after_idle` → `0` | suggested | `代理长连接空闲后不再重新慢启动` |
| `notsent-lowat` | 当前 > 131072 | `net.ipv4.tcp_notsent_lowat` → `131072` | suggested | `减少发送端排队，降低交互延迟` |
| `buffer-cap` | 当前上限 < cap | `net.ipv4.tcp_rmem`、`net.ipv4.tcp_wmem`（只给最大值）、`net.core.rmem_max`、`net.core.wmem_max` → cap | suggested | `按内存 <档位> 与线路估算的缓冲上限` |
| `quic-buffer` | 有 QUIC 入站且 `rmem_max` < 7864320 | `net.core.rmem_max`、`net.core.wmem_max` → max(cap, 8388608) | suggested | `QUIC（Hysteria2/TUIC）需要约 7 MB 以上的 UDP 缓冲` |
| `mtu-probing` | 中转或出口角色，当前为 0 | `net.ipv4.tcp_mtu_probing` → `1` | optional | `中转线路上避开路径 MTU 黑洞` |
