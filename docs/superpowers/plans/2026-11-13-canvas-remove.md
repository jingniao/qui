# 切片 8 后端撤除实施计划

依据：[第 15 项设计](../../v1.5.5-item15-design.md)第 6、12、13 节与 Owner 决定 3/4/6。

目标：Owner 可只读预览撤除影响，显式确认恢复目标和人工改动后，先停止或恢复入口，再清理通道，成功确认后删除方案。

约束：保持现有工作区与 DELETE 语义；不改前端、canvas_import_refs.go，不暂存、提交、推送；不新增持久操作表；使用 Go 1.26、-p=1 与指定离线缓存。

1. `canvas_remove_plan.go` 与测试：从绑定、当前/历史通道归属规划入口、引用保护、恢复目标与入口优先的节点顺序。无历史完整配置或分组快照时明确要求确认，避免猜测历史。
2. `canvas_remove.go`、部署窄接口与测试：入口和通道分阶段发布并等待终态，复用 undo 和部署回滚；最后事务删除资源、绑定和方案。失败保留方案。
3. `canvas_handler.go`、HTTP 测试及路由清单：Owner+CSRF、严格 JSON、409 details；旧 DELETE 保持 detached 行为。
4. 审查共享资源依赖闭包、恢复目标成环、单节点/批次失败、取消及回滚失败；执行指定 gofmt、vet、proxy/deployment 与 Portal 测试，保留原始输出。

实施边界：现有批次没有数据库对象补偿的持久操作材料。本切片同步等待阶段终态，进程内失败用 undo 恢复；进程崩溃恢复不扩展为新执行器，仍为切片 4 边界。
