# 16c implementation plan

**Goal:** Convert stored content identities and references once, atomically.
**Spec:** `docs/v1.5.5-item16-design.md`, section 4 and Owner decisions 2–4; the task overrides recovery scope.
**Architecture:** importer owns the transaction, strict source inspection, identity map and report. Server injects node, rules and canvas transaction adapters using resolver callbacks. The report uses `system_settings.import_identity_report`; no schema migration is needed.
**Constraints:** Keep existing uncommitted work; no staging, commits, branch changes or recovery edits. Proxy receives only `canvas_import_refs.go`; its tests live in subscription. Preserve URL rows and references exactly. No network.

- [x] Core: test rollback/retry, strict decryption and metadata validation, once-only marker; implement `Store.ReconcileImportedIdentities` with injected callbacks.
- [x] Node/canvas: test source/key expansion, duplicates, empty and dangling references, failed caches, both canvas snapshots; implement transaction adapters.
- [x] Rules: test all profiles and active snapshot, exclusions, source freezing, empty groups and revisions; reuse typed read/write validation.
- [x] Integration: compare actual subscriptions and group labels for multiple users, before/after identity mapping; wire startup before refresh and HTTP serving.
- [x] Review and run the requested gofmt, vet, package tests and Portal checks; retain raw command output.

Review focus: legacy names beginning `id:`; one key with multiple rows; empty sources; more than 200 members without truncation; dangling refs retained with an object-specific report. Existing stable refs created by 16a/16b before the marker is set must follow their rows too.

## Execution decisions and verification

- Sort fresh IDs before assigning them in old-ID order within each content source. This preserves subscription name-deduplication order without consulting the migration map at runtime.
- Increase client-policy member/exclusion capacity from 256 to 1000 so frozen sources remain editable through the existing validator. Node group capacity was already 1000. Exceeding capacity fails the transaction; nothing is truncated.
- The task explicitly permits retaining the original `@source:` when an empty-source conversion leaves no group member. Such cases are reported as unable to freeze. Review raised its dynamic semantics; the task's explicit exception governs and the comment now states that limitation accurately.
- Initial cross-package compilation was temporarily blocked by another session's incomplete canvas removal methods. These files were not edited here; the final checks below passed after that session supplied the methods.
- Final `gofmt -l` for all 13 Go files: no output, exit 0.
- Final `go vet ./internal/panel/... ./internal/platform/server/ ./migrations/`: no output, exit 0.
