## 目标与约束

- 代理节点页、用户列表与详情、新建节点弹窗减少等待；保持卡片结构和流量账本、额度、时间边界的准确语义。
- 已登记服务器也可生成安装命令；复用原位身份恢复，新登记成功后旧证书失效，保留面板记录和业务配置。
- Owner 已指定：旧 Agent 最后上传，面板确认成功后删除旧 Agent 本机数据，再安装；面板数据全部保留。最后上传失败必须保留数据并拒绝清理。
- Owner 追加日志容量限制：只限制 Agent 日志，建议默认总计 100 MiB；队列、程序和核心不计入日志上限。2 GiB 总磁盘预算讨论已撤回，不实施。
- Owner 追加并批准面板 CPU 修复及相关回归：控制连接读取能力时不计算调优建议。
- 失败必须可见，不能用空结果、吞异常或假成功隐藏慢请求。
- 不新增基础设施，不做无关重构；只运行直接相关测试。

## 设计与已知依据

1. 代理节点：生产 `/nodes/inbound-states` 最慢 8.282 秒；前端心跳每 5 秒触发全量服务器选择及入站发布状态读取。`readInboundStates` 构建完整 `SnapshotIntent`，即使比较明确排除用户凭据仍加载完整访问材料。优先消除不必要快照内容和心跳重读，保留真实配置与发布变化触发。单纯拉长轮询周期无法减少首次读取成本；通用 TTL 缓存增加失效复杂性，暂不采用。
2. 用户：列表 `observeMany` 读取设备与连接观察；详情先等用户、全部分组、全字段服务器、全部入站才启动订阅和活动读取。按实际展示依赖使用轻量选择接口、并行独立读取，重复读取合并；额度直接采用现有准确账本，不缓存写入决策。
3. 新建节点：检查编辑器初始化依赖，弹窗立即显示，选项按实际需要加载并复用当前页数据；保存前仍校验真实能力和完整选择，不以默认空选项假成功。
4. 重装：已有 `IssueRecovery` / `consumeRecoveryTx` / `Control.Enroll` 支持核销时吊销旧身份、断开旧连接及流量队列交接。UI 安装入口复用恢复接口，不放宽普通注册码。安装脚本增加显式覆盖参数，只替换 Agent；准备和校验先于停服务，终止采集并补传最终持久数据、收到面板确认后才可删除旧本机数据。

## 审查重点

- 旧连接退出不得把新连接标记离线；旧证书不得重连抢占。
- 重装不得清空面板已计费流量或悄悄丢弃本机尚未上报数据。
- 配置编辑、发布成功/失败、配额变化后状态不能因请求合并而永远停留在旧值。
- 慢请求、失败与路由切换后迟到响应不能覆盖新页面或掩盖错误。
- 安装脚本备份/移动路径必须明确，不触碰其他组件或未经核实的自定义数据路径。
