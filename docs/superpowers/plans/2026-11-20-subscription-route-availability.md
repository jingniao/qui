# 订阅线路维护与离线过滤实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 任一真实经过的受管机器维护或确认离线时，从订阅排除整条线路；恢复后重新包含。

**Architecture:** 成功发布时记录端点实际路径的机器依赖，订阅生成时批量读取当前状态并统一过滤。后端离线语义与已确认的展示持续时间一致，所有格式复用同一端点结果，不修改节点运行配置或凭据渲染。

**Tech Stack:** 现有 Go/SQLite、发布事务、订阅 source/格式无关端点模型；无新增服务或依赖。

**Spec:** [线路可用性设计](../specs/2026-11-20-subscription-route-availability-design.md)

状态：v1.7.5 已实施，发布门禁与正式发布由发布批次统一记录；未部署生产。与 [Agent 网页/终端升级统一计划](2026-11-20-agent-terminal-web-update.md) 独立实现。

## Global Constraints

- 任一入口、中间、出口受管机器维护或确认离线即移除相关整条线路；无关线路继续保留。
- 离线使用 `node_offline.duration_minutes`；通知 enabled 只控制通知；等待恢复期间保留订阅。
- 成功发布路径为准，实时状态为准；不从草稿推断当前线路。
- 不将状态过滤用于凭据渲染、自动发布或实际连接操作。
- 已发布旧记录需要可核对的依赖重建；材料不全显式报错，不默认可用、不返回假成功空订阅。
- Owner 后续授权实施、现有测试和发布门禁，以及完成规划后发布 v1.7.5；不新增测试方法、实体或 mock，不部署生产，保留工作区既有改动。

## Review Focus

1. 旧快照缺少中间节点，不能用当前草稿或整个发布批次的节点集合替代每条实际路径。
2. 固定服务器画布入口、隧道出口到自建目标、目标之后的固定链和导入出口必须完整覆盖。
3. 控制断开时底层 status 立即 offline，订阅仍须等待已配置持续时间；0 分钟、无心跳、心跳恢复要正确。
4. 过滤不得改变凭据下发或因维护/离线自动发布新配置。
5. 成功过滤与数据读取/依赖重建失败必须区分，避免误返回空订阅或放行未知路径。

## 实施记录

- 0158 保存稳定端点 Ref、来源摘要、成功发布标识及当前规则自身路径。节点成功回执只保存该节点和成功修订摘要，完整线路原材料保留于该加密修订；订阅读取时按各节点当前已确认配置递归证明完整依赖，防止目标单独成功发布后继续使用旧依赖。
- 状态固定一次服务端时刻，在同一只读事务读取全部状态与 `node_offline` 持续时间；统一 `node.ConfirmedOffline` 判定。通知 enabled 不参与过滤。
- 新规则的逐线路受管跳在发布准备时捕获，成功收尾才写快照和索引；普通节点、服务器画布、成功回滚与其 runtime 修订在同一事务写索引。失败发布保留原成功证明。
- 旧中转用匹配的成功加密日志及其中真实 listener 的 TLS 身份重建，不读取当前 `tunnel_hops` 或画布草稿。重建只读历史、不改运行配置；无法证明的线路明确报告缺失材料。启动提交可证明的索引并记录所有错误，管理界面继续可用；相关订阅读取缺失索引会失败。
- 规则可以先于目标入站发布，此时还没有可输出的目标订阅端点。索引保留目标入站引用；生成订阅时仍必须取得其成功配置，绝不把未发布目标当作可用。
- 生产订阅将可选的外部缓存与必须成功的导入出口中转拆成两个来源；客户端链在统一过滤之后组合，缺跳整体排除。原 `Store.Proxies` 接口保留其实际完整收集语义。
- 备份校验核对成功配置、规则快照及索引来源；旧归档须有可重建材料。恢复在现有成功修订/发布日志合并后重建索引。
- 预览共用同一收集路径，正常排除显示线路、具体服务器及原因；错误保留原始原因。未改 desiredstate/proto，也不向旧 Agent 发送新字段。
- 现有测试适配将 `node_relays_test.go` 三处结构体 `!=` 比较改成等价的 `reflect.DeepEqual`（Relay 新增切片字段后不可直接比较）。客户端链的既有 `Chains` 方法改为返回 error，相应现有测试调用点和 `candidateClones.Chains` 夹具签名同步接收该 error 并要求为 nil；没有新增测试方法、实体或 mock，没有降低原断言，也没有保留为旧测试吞错的接口旁路。
- 本轮验证仅运行现有相关 Go 包。首轮发现维护候选装配、合法 loopback 目标及测试结构体比较问题并修正；最后结果在交付消息与发布记录中同步。不新增独立验收场景，设计表中的全部组合尚无逐项新增实测证据，不能记作逐项通过。

Ruling：索引只属于面板发布证明，不扩展 Agent 配置合同；避免旧 Agent 严格 JSON 解码拒绝新字段。Ruling：无路径材料只阻断相应订阅，不使整个面板无法启动；管理员仍可处理具体失败。Ruling：loopback 目标可以是正常本机服务，仅在成功配置存在匹配 forward 时追踪该转发；不将普通 loopback 当作缺失转发错误。

Ruling（主代理确认）：默认出口组的全部已发布候选都属于该订阅入口的相关线路，按所有受管候选依赖过滤；不重写只含健康成员的运行组、不自动发布。该边界会在任一候选维护/确认离线时排除整个订阅入口。

Ruling：真实成功回执和成功回滚不执行跨节点线路证明。发布或反向回滚中，各机器可能暂时持有不同修订；派生订阅索引不得因此撤销真实成功、阻断下一台回滚。完整跨节点监听/凭据证明在订阅读取时执行，材料不匹配明确失败。

审查首轮发现成功回执内跨节点证明会阻断反向回滚，以及默认出口遗漏备用路径；本轮已分别移除节点/规则成功收尾中的跨节点派生证明，并补齐 typed backup 递归。相关现有检查通过只证明其已有覆盖范围，不替代上述新组合场景的专门验收。

Ruling：默认出口的出站、出口组和固定链按 `BackupKind` 递归计入已发布备用目标，Direct/Block 不增加受管依赖，保留环路检查；不扩展到域名策略。现有批次回滚、嵌套备用和备用链检查通过；未新增跨修订回滚或维护备用成员的独立场景。
