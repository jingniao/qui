# v1.10.1 Storage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Follow checked task requirements; implementation and release are already authorized.

**Goal:** Ship v1.10.1 with once-only discard/rebuild of legacy Agent state and tiered panel storage.

**Architecture:** Extend existing root installer and authenticated node lifecycle with a durable reset transaction. Keep telemetry compaction, accounting, receipt retirement and identity barriers separate, using existing SQLite jobs and lifecycle locks.

**Tech Stack:** Go, SQLite, gRPC/protobuf, Bash, Vue 3.

**Spec:** `docs/superpowers/specs/2026-11-23-v1.10.1-storage-design.md`

## Global Constraints

- Version v1.10.1; compatibility floor v1.7.5; production untouched.
- User authorized focused regression tests and all release gates, commit/push/release.
- Legacy Agent data is deliberately discarded without telemetry upload or old-state archive.
- Preserve panel accounting, existing published configuration and node IDs.
- Append migrations after 0160; tasks own 0161 reset, 0162 telemetry, 0163 traffic, respectively.
- Work in the current clean feature branch; no destructive Git operation or unrelated edits.

## Review Focus

- Reset must survive interruption after revocation/deletion without reusing retired identity or deleting new state.
- An old live stream cannot cross the identity barrier; accepted pending remains processable internally.
- A skipped release must still reset once, while fresh/new-generation nodes never reset repeatedly.
- Coarse histories preserve totals/attribution and reject unsupported boundaries; late samples count once.
- NULL metrics, counter reset/gap, and latency sampling weights remain distinguishable from zero.
