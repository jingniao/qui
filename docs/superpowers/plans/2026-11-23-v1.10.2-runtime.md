# v1.10.2 心跳与 Agent 升级修复计划

> **For agentic workers:** Use superpowers:executing-plans; tasks use checkbox syntax.

**Goal:** 修复整合任务阻塞心跳及 Agent 升级与旧状态重置的循环等待，测试通过后推送并发布 v1.10.2。生产不操作。

**Architecture:** 保留单写连接与既有离线时限；监控整合使用可提交的小事务、索引选桶与独立时间预算。重置任务保留升级锁隔离，但不作为运行中 Agent/helper 的启动前置条件；独立持有两把升级锁，停止旧 Agent 后再封存身份，已重建时仅恢复新服务并确认。

**Tech Stack:** Go、SQLite、Bash、systemd、OpenRC。

**Spec:** 用户本轮授权及只读排查证据；沿用 docs/project-spec.md 中的分层精度和一次性重置约定。

## Global Constraints

- 最低兼容 v1.7.5；不修改已发布迁移，迁移头仍为 0163。
- 不放宽心跳、身份或停核安全判断，不伪造成功，不补传旧 Agent 待上报数据。
- 不连接、修改或升级生产；测试仅使用临时数据库、隔离服务和 Linux 测试机。
- Owner 已授权相关回归测试、必要门禁、提交推送及 v1.10.2 发布。

## Review Focus

- 后续桶失败时此前桶已提交，重试不重复聚合且不丢失加权值及计数器前驱。
- 整合排队及执行均受独立预算约束；每桶释放唯一写连接，候选选择不全表分组排序。
- 重置等升级锁时 helper 能服务升级；重置启动新 Agent 不等待自己。
- operation.lock、update.lock 同时持有；封存或停服失败时不删除，已 rebuilt 时不重复封存。
- v1.10.1 遗留 prepared/sealed/rebuilt 状态保持原 reset ID 与身份绑定，可重入。
