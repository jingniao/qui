# Btrfs 锁识别修复与单节点升级

> 后续状态：本修复已随 [v1.12.1](../../releases/release-notes-1.12.1.md) 正式发布。下文保留单节点恢复阶段的授权范围、临时构建和验证记录；正式版门禁另见发布说明。

**目标：** 修复核心交接对 Btrfs 生命周期锁的误判，将已授权节点从 1.10.4 升级到本地修复构建 1.12.1，保留配置、身份、修订及持久数据。该构建未创建公开 Release。

**依据：** 2026-11-24 实机记录显示，同一生命周期锁的 `stat.st_dev` 为 `00:1b`，`/proc/locks` 为 `00:1a`；inode 一致，Agent 的 fdinfo 确认持锁。旧代码直接比较设备号导致 owner absent。

**方案：** 继续从 `/proc/locks` 取得内核报告的候选 PID 和锁记录，使用 `/proc/<pid>/fdinfo` 核对完整锁记录，再以描述符对应文件的设备号和 inode 与目标锁比较。不能仅凭同 inode、进程名或 PID 文件认领；保留启动 token、配置路径、命令模式及交接授权校验。普通进程/描述符退出允许继续查找，其他读取错误完整返回。

**范围：** `internal/agent/handovercli/local_linux.go`、说明书相关章节、本计划；仅在用户明确允许后增加最窄回归测试。不提交、推送、打 tag 或创建公开发布，不覆盖既有文档整理改动。
