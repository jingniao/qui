# 重装后隔离旧更新任务实施计划

> **For agentic workers:** 使用 executing-plans 按任务执行；用户已授权直接修复、相关测试、提交和发布。

**Goal:** 更新任务不阻止安装；成功恢复登记后旧更新不再下发或占用新 Agent 的配置恢复。

**Architecture:** 新增迁移 0165，允许 Agent 系统更新、旧 worker 更新、核心更新使用 `superseded` 协调状态。节点核销恢复码时调用 deployment 的事务接口，仅将该节点未结束任务标为由重装接替，原请求、阶段、结果及日志原样保留。生成恢复码、补传、普通重连不改变任务。新身份不能重试或回传旧任务；备份校验、恢复和页面支持该状态。

**Tech Stack:** Go、SQLite、Vue 3。

**Spec:** 用户本轮要求与 docs/project-spec.md §11.3、任务记录、备份恢复。

## Global Constraints

- 兼容 v1.7.5 有效数据和在途任务，不改旧迁移。
- 不删除任务、伪造执行结果，不改变发布/核心移除拦截。
- 不改生产服务；本轮只发布，不部署生产。
- 不提交其他批次已有的两份运维文档差异。

## Review Focus

- 恢复码仅签发或核销失败：旧任务与身份原样保留。
- 系统 running/unconfirmed/恢复失败、worker recover/failed_closed、核心 queued/running：新身份不再收到旧命令，配置可恢复。
- 任务结果、尝试、日志在迁移/重装/备份后仍可读取。
- 旧证书和迟到消息无法重新激活已接替任务。
- 新任务的唯一索引可正常保留一个活跃任务。
