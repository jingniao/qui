# v1.7.3 后剩余性能优化设计

用户已确认按三项调研结论实施，并一起验证数据库连接复用；允许新增和运行相关回归测试。继续在当前目录修改，先不发布部署，不暂存、提交或推送。

## 目标与边界

减少 CPU、代理节点页及用户详情中的无关计算和串行等待，保留流量统计准确性、真实授权/发布状态和现在的卡片显示。基线为 `f161e8a`，证据见 `docs/v1.7.3-production-acceptance.md`。本次不访问或修改生产，不改数据库迁移、账本、额度判断、时间窗口或 UI 布局。

## 采用的方案

此前已比较过直接清除无用工作、跨请求缓存和增加并发。采用已获准的最小路径：先清除无关调优、复用已有窄读取、批量中转展示、合并在途状态查询及并行详情读取。暂不增加共享订阅/入站状态缓存，不在单核上堆更多计算任务。

1. CPU 与数据库：延迟/订阅节点展开不计算调优；建议详情只计算一次；无有效带宽时不查询 RTT。保留卡片建议数量。只读池保留少量空闲连接（实施选择 2，最大并发仍 4），每次读取结束关闭事务；验证只读保护、写连接隔离、提交可见性、取消及恢复/回滚重连。保留自动应用和写路径的最新数据判断。
2. 代理节点：新增只返回中转展示信息的批量读取，避免列表生成无用分享链接；已有单节点接口和创建返回分享链接语义不变。读取保持画布一致性及权限。前端状态请求按数据代次和节点集合合并；仅可见集合缩小允许利用仍有效的超集响应，真实草稿、修订、证书、发布事件必须使旧响应失效，不把错误当成功。
3. 用户详情：只需要路由用户 ID 的预览、订阅链接、流量和访问读取可与主资料并行；依赖用户名的操作记录仍等主资料。保留 generation 防串页及错误提示。由第 1 项去掉订阅预览的无关调优计算。不缓存最终授权、额度或在线判断。

## 调优发布与 BBR/fq（后续授权）

用户补充调优页发布无反应、缺少算法时希望安装使用 BBR/fq，并明确选择补齐面板功能、先不部署。纳入检测、支持的模块加载/启用和发布反馈；沿用现有 Agent 能力、任务结果及特权辅助程序。不自动升级内核、重启主机或未经判断安装系统包。内核缺失/容器无权限等失败必须明确返回原因，不能标为成功。具体改动按只读调研证据确定，相关回归授权沿用本轮。

用户随后单独授权 shlii.io 美国 1元节点进行 BBR/fq/调优实机测试。该例外只用于指定节点，仍不发布或升级面板/Agent、不触及其他节点。先只读检查，候选代码使用临时隔离目录及受控同值写入验证，保留原业务配置与回执；真实权限限制作为失败用例，不通过放宽宿主权限绕过。认证信息仅保留在仓库外加密凭据文件。

用户进一步明确要求缺少 BBR/fq 模块时自动安装，并选定范围：自动安装与当前运行内核匹配的模块；需要换内核时提示处理。不安装新内核、不自动重启、不修改生产。安装仅可由固定受限任务调用可信发行版包管理流程，不能接受网页提供任意命令、包名或下载地址；无法取得精确匹配模块、容器需要宿主支持时明确失败。安装完成必须重新检测，启用仍沿用原白名单、读回及失败回滚，安装受理不等于已启用。

## 验证与交付

用户随后补充：很多页面刷新时卡片内容/格式变化，数据先空再出现。纳入本轮：检查公共加载组件及各页面刷新，已有成功数据刷新时保留现有布局和内容，结果到达后更新；初次载入保留稳定占位，真实错误显式呈现。换用户/资源、权限失效或确实删除时不能为防闪烁展示不属于当前身份的数据。以审计确认的路径为范围，不重新设计卡片。

先写能重现无用调用/额外请求/连接丢弃的行为测试，再最小修改。用项目现有 Go/前端自测和类型检查验证；补充短的连接复用对比，结果只作为本地证据，不声称生产提升。每项审查，最后整体审查。产出本地未提交修改和验证记录，明确未验证项。

不纳入：用户维度流量聚合表/新索引、全局修订解码缓存、完整入站投影缓存、跨端自动部署；这些需要独立证据和更完整失效设计。用户详情只读流量接口继续使用原精确查询。
