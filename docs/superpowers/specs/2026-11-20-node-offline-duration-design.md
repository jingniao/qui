# 节点离线展示共用通知持续时间

用户已确认：节点离线展示使用通知规则 `node_offline.duration_minutes`；`enabled` 只决定是否发送通知。目标是避免短暂断线让节点卡片反复消失。

后续已纳入 v1.7.5：订阅复用同一离线口径；Owner 允许现有测试和发布门禁，不新增测试方法、实体或 mock，不部署生产。首次实施的检查记录见对应计划，统一发布证据见 [v1.7.5 发布说明](../../release-notes-1.7.5.md)。

## 方案

采用展示状态与控制可用性分开计算的方案。直接延长控制连接和心跳有效期会让发布、调优等操作误用已断开的 Agent，因此不采用；只延迟隐藏卡片会留下服务器与节点页面状态冲突，因此统一共享展示判定。

- 后端保持现有断线与 45 秒心跳有效性检查；节点读取和运行快照附带规则持续时间秒数，不暴露其他通知设置。
- 展示先检查禁用、维护、待登记等状态；控制断开或心跳过期后，距最后有效心跳未达到规则持续时间时显示“连接中断，等待恢复”，保留卡片；达到时间显示离线，沿用节点页隐藏规则。
- 持续时间为 0 时，在控制断开或心跳过期被确认后立即显示离线。没有有效历史心跳的节点不虚构等待期。新有效心跳恢复原在线或核心异常状态。
- 通知继续按最后心跳计时，关闭规则后离线、恢复通知均不发送；恢复时清除已记录的离线事件状态。
- 保存通知规则后刷新运行快照并通过现有状态事件通知页面；等待期不用于发布、调优、更新等操作的授权。
- 不新增数据库迁移、依赖或测试，不运行测试、不提交、不部署。

## 覆盖与限制

覆盖管理后台服务器、节点配置、详情和总览、版本状态的展示；保持核心健康、实时指标与操作准入的原有有效期。沿用浏览器状态时钟和实时快照，通知发送仍由既有后台周期执行。
