# 面板更新磁盘开销优化设计

## 目标与边界

减少网页面板更新中的重复数据库复制和停服期间的磁盘工作，保留最终一致备份、逐字节校验、完整性与迁移检查、启动健康检查及失败回滚。不连接、不修改生产；Owner 后续已授权完成后提交、推送，本轮不发布。

## 已确认的现状

- `update.sh` 在停服后复制主库与 WAL，`sync -f` 同步，再与源文件逐字节比较。
- `proxy-panel --check-database` 的 `db.Inspect` 再把备份完整复制到临时目录，才执行 `PRAGMA integrity_check` 与迁移校验。
- 程序回滚快照也在停服后准备；安装器发布每个文件都执行 `sync -f`。Linux 的该参数调用文件系统级同步，范围超过本次变更文件。
- 本轮此前只读诊断看到约 878 MiB 主库、严重磁盘等待。流程优化减少工作量，实际耗时仍取决于云盘。

## 方案比较与选择

采用局部优化：保持最终备份在停服后取得，取消检查时的第二份整库复制，提前准备程序回滚材料，并在可精确列举持久化对象的原子发布步骤使用文件/目录级同步。

在线备份加增量追赶可以进一步缩短停服时间，但需要新的一致性、切换和崩溃恢复协议。本轮不引入。单纯延长超时不减少工作量，本轮不采用。

## 执行顺序

1. 服务运行期间完成既有下载、归档校验和解压；准备旧程序、单元、脚本与 manifest 的回滚快照，完成必要持久化，不提前写入表示安装已开始的 journal。
2. 停服后获取最终主库与 WAL 备份，保留 `.partial`、独立文件、fsync、逐字节比较、原子重命名及目标目录同步。备份失败恢复原服务并明确报错。
3. 更新器在 root 登记目录的 `check.XXXXXXXX` 中建立最终备份主库与 WAL 的硬链接，再交给新程序只读检查；不复制主库、不回放 WAL 到备份、不在备份目录创建侧文件，保留完整 `integrity_check` 和全部迁移校验。已提交但尚在 WAL 中的数据必须纳入检查；无法安全检查的输入明确失败。`copy_database_atomic` 已保证登记目录与备份目录同文件系统，root 不在面板账号目录内创建或删除检查材料；准备或删除失败返回 4，恢复旧服务并拒绝更新。
4. 备份检查成功后写现有 prepared journal，再按现有协议安装、启动、检查 10 秒 PID 稳定性、提交或回滚。

## 代码约束

- `db.Inspect` 的调用合同仍是离线、不存在写入者的数据库。在源目录下建立 0700 私有目录，通过硬链接只读打开主库与 WAL，SQLite 临时索引只在私有目录创建，结束后清除；不复制数据库字节，不修改原 SHM。要求源父目录可写且支持硬链接，失败明确报错。拒绝符号链接、非普通文件及非空 rollback journal。
- 更新器停服后的备份检查使用 `preflight_backup`，源路径位于 root 登记目录的 `check.*` 内；手工 `--check-database` 仍要求被检查文件父目录可写且支持硬链接。停服前 `--database` 对暂存库的检查保持原入口。信号处理清除 `check.*`，下次更新清除被 `kill -9` 或断电打断的真实检查目录，跳过并报告非目录或符号链接。仅检查模式额外处理 SIGHUP，让 `Inspect` 取消并清理私有索引，服务模式信号行为不变。
- 实测当前驱动的 immutable 模式忽略 WAL，普通只读加 exclusive 锁也无法正确打开离线 WAL，因此采用上述私有索引方案。完整性与迁移回归要求读到 WAL 中已提交内容。
- 输入主库、WAL、SHM 的内容与侧文件集合不得被检查修改；保留现有兼容性退出码，不增加忽略损坏或校验失败的路径。
- 把原子复制/发布中明确的文件与目录从 `sync -f` 改为文件级 `sync -- <path>`；安装发布还逐级同步父目录直至根目录，覆盖初装新建目录的持久性。递归程序快照仍需完整持久化，保留其整体同步并移到停服前，不仅同步顶层目录。
- 提前快照与 journal 分离：快照准备失败不停止服务；备份/预检失败或信号中断不得安装程序；prepared journal 只在最终备份确定后写入。无 journal 的遗留目录按现有恢复协议处理。
- 面板停服失败时丢弃提前准备的快照；Agent 停服失败路径保留现状，其快照可能包含已授权的核心交接现场。
- 复用现有更新锁、安装锁、回滚结构和恢复入口；Agent 的升级行为和数据格式不变，无新迁移。
- 已运行的旧更新器仍按旧的停服/快照顺序执行；目标程序的数据库检查优化可用于这次更新，提前快照等脚本优化在新更新器安装后生效。

## 验证范围

需 Owner 明确允许后，新增并运行最窄回归：

- 数据库检查无需可写临时目录；无 WAL 与有未 checkpoint WAL 均能检查；主库/WAL/SHM 和目录集合不变；损坏、较新迁移和非法文件仍拒绝。
- 隔离更新脚本验证快照在停服前准备、备份在停服后取得、校验失败不安装、备份/fsync/启动失败仍回滚；信号和中断恢复保留既有保护。
- 同步行为验证关键文件与目录被持久化，不将 fsync 错误当成功；现有 Linux 更新回归保持通过。
- 仅使用临时数据库、隔离 init 替身及 Linux 测试机；不做生产性能基准。
