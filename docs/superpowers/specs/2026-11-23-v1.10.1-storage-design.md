# v1.10.1 数据整合与旧 Agent 重建

## 已批准范围

Owner 批准实施、必要回归测试、全部发布门禁、提交、推送和发布 v1.10.1；未批准升级生产。兼容 v1.7.5 起的有效面板数据。旧 Agent 本地历史例外：Owner 明确要求全部删除，不补传未上报内容、不归档旧状态。

## 方案选择

比较了保持原精度、分层整合、24 小时后直接小时化，选择分层整合。Agent 从无引用文件清理改为整代重建，直接删除旧身份、队列、配置修订、运行状态、镜像、任务与日志。

## 一次性 Agent 重建

- 存量旧安装首次升级到 v1.10.1 或之后版本时执行一次；完成后永不因重启或再次升级重复清空。新装直接建立新代。不能依赖文件 mtime 或发布日期。
- 先面板后 Agent。独立 root 更新器持久保存 resetID、原节点/指纹、新公钥、目标摘要和阶段；该记录及新材料在旧清理目录外。
- 校验新版程序、核心、连接信任与可重建配置/证书后，停止旧监督、worker、所有核心，确认退出。执行显式 discard 路径，不调用 DrainTelemetry。
- 面板持久作废旧指纹及全部旧队列/身份代次，旧任务未知结果不得伪造成功。新身份绑定原节点 ID；同一 resetID 和新公钥幂等取得同一结果，回复丢失/重启不得重新启用旧证书。
- 清空旧 /var/lib/proxy-agent 业务状态，替换旧配置与本地证书，新建支持编号队列的状态及 v1.10.1 回滚基线，下发原节点已发布配置。
- Agent 专属旧更新输出和快照可清，共用工具、其他组件、面板、SSH、系统账号不删。宿主调优/网络原值恢复材料须先用于撤销旧设置，不可直接遗失。无法重建的本地材料预检报错。
- 未上报用量记“已丢弃，数量未知”，不假记为零。面板累计用量、计费、额度、机器流量游标保留；新 core epoch 不能重复记旧累计值。
- 删除前失败保留现场；删除后只前滚新安装；重启按原 resetID 接续。一次代理中断为预期行为。

## 面板历史

| 数据 | 0–24h | 较早 |
|---|---|---|
| 用户流量 | 原始 | 分钟，期限沿配置，当前 2d；现有小时/日表口径保留 |
| 核心流量 | 原始 | 24h–7d 分钟，7d 后小时 |
| 主机监控、延迟 | 分钟 | 24h–7d 五分钟，7d 后删除 |

合并与删除同事务、仅完整桶、短批次。流量保留原归属维度和原始样本数，上下行分别求和，计费/游标不依赖展示数据。查询的原始/分钟/小时层互斥，不重复计算；边界切入已合并桶返回精度错误，禁止比例分摊。迟到数据仍按原入账合同处理并归并。派生小时索引、核心/账户 epoch 回退规则同步覆盖新层。

监控每字段保留 sum/count/min/max，NULL 不变零。延迟保留分钟 median 的 sum/count/min/max 与 sent/failed，不冒充全局 median。重传先按有效相邻分钟计数差求原分钟率，再保留 sum/count 与极值，默认维持原分钟率平均口径。查询采用固定 UTC 五分钟及整数倍，不拆桶重造任意步长；返回实际分辨率。

## 回执与恢复

活跃新队列沿用 R≤A≤C 和 24h 冻结。重建事务建立 pre-reset 分区与逐入库事务身份屏障，封存提交后旧连接也不可继续入账。旧代已完成回执可批量删除；访问与流量分别保护，不能共用 seq。

面板已持久接收 pending 继续保留并走受限内部续记账路径，校验原 digest/授权/游标，不能被新代网络准入或旧 seq=0 拒绝规则误挡；该路径不开放旧网络重传。未完成只阻挡其关联回执淘汰，不阻挡新代。

恢复旧备份保护当前冻结库累计、游标、身份作废、队列封存及重建记录，不复活旧身份或旧批次。无法证明代次的恢复明确失败。只增量回收既有 incremental 库空页，不自动 VACUUM。

## 验收与发布

验证一次性迁移/跨版本跳升/新装、旧进程屏障、全阶段断电与重试、回复丢失、不补传、计费不清零/重复、旧协议拒绝、pending 续记账、流量总和和精度边界、监控缺失/丢包/重传、恢复不复活与删除路径边界。发布提交通过 Linux 完整门禁、真实核心及同 SHA GitHub check 后再打 v1.10.1 tag；生产不动。
