## 2. Findings carried forward

From the code:
- **Device IDs are in the Agent contract.**
  - Credentials sent to Agents carry `DeviceID`.
  - Xray stats only count credentials that have one.
  - sing-box rendering rejects user credentials without one (`internal/agent/core/singbox/render.go:247`).
  - Tombstones, traffic tables, policy scopes and the collector all key on it.

  Removing it from the wire format would force a lockstep panel+Agent upgrade and touch about 40 Go files. **Solution:** one hidden access identity per user (section 4.1).
- **Subscriptions only contain credentials that are already live on the nodes** (`subscription/service.go:137`).
- **Every config rollout restarts the core**, which drops every user on that node.
- **Formats are hard-coded in one function.** `subscription/export.go` builds uri/base64/sing-box in one 306-line function, and the format list is repeated in `system/runtime_policy.go` and in the handler.
- **The `sing-box` format is a fragment** (outbounds and endpoints only). The official sing-box apps can't import it as a profile.
- **Your uncommitted UI has three problems:**
  - `ClashRulePanel.vue` keeps its template in `localStorage` and builds YAML by string concatenation;
  - `ClientAccessPage.vue` calls the admin APIs and is device-centric;
  - `viewMode.ts` lets Owner and Viewer accounts switch into a "portal" mode.
- **Admin access control.** `auth.Handler.Require(next, owner bool)` guards every admin route, and sessions reference `admins` only.
- **Core download allowlist.** `pkg/contracts/release/core_source.go` allows only official GitHub release URLs, and both the panel and the Agent validate it.
- **The Agent already reads `Tags:` from `sing-box version`.**
- **The Agent's sing-box log parser** already maps each connection ID to the authenticated user name (`internal/agent/collector/singbox.go`).
- **Xray `GetStatsOnlineIpList` exists** (v26.3.27). Xray's `RoutingService.AddRule` with `shouldAppend=false` replaces the whole rule set and balancers without a restart; with `true` it only appends after existing rules. The replacement is **not atomic**: it clears rules and balancers before validating the new ones, so a rejected payload leaves the router empty (Phase 0, A.4).
- **Per-user upload/download** already exists in `account_traffic_daily`/`hourly`.

From the flyx report (evaluated):
- **One subscription per user with a shared user quota:** adopted (R5, R6).
- **sing-box accounting via `auth_user` routing, `routing_mark` and nftables:** valid with official binaries, but needs per-user copies of every route target, mark propagation through relays and chains, new privileged node code, and counts different bytes than Xray. Not adopted (R3 chosen); recorded as the fallback.
- **Portal identity:** the report's finding is confirmed. It is fixed by real end-user sessions (R4); `viewMode` is removed.
- **No flyx code or templates are copied** (GPL-3.0).

## 4. Architecture

### 4.1 User-level access (R5, R6)

- **Hidden identity.** Each user has exactly one `devices` row created by `user.EnsureAccessIdentity`. Its ID flows to the Agents unchanged.
  - **What still works as before:** traffic accounting, tombstones, the quota deployer, automatic revisions, rollback reconciliation and the collector need no change.
  - **What changes:** the device API, UI, policy scope and simulator field are removed.
- **Credentials.** `EnsureAccessIdentity` keeps one active credential per allowed protocol. It runs on user create/update, at panel startup and after a restore. Each change queues the existing automatic revision.
  - Reset: `POST /users/{id}/credentials/reset` re-issues every credential. The old link and the old proxy settings stop working once the automatic revision has been applied on the nodes.
- **Subscription.** One active token per user (the existing `subscription_active_user` index). The token is stored as a hash plus a vault-encrypted copy.

### 4.2 Accounts and sessions (R4)

- **A third principal kind**, separate from admins. Proxy users log in with `users.username` and a password set by the Owner, and can change it.
  - Admin tables, `Require`, and the Owner/Viewer roles are untouched.
  - End-user sessions use their own table (`user_sessions`), cookie (`qui_portal_session`) and middleware. Each middleware rejects the other's session by construction, and a test iterates every registered route to prove it.
- **Login rules:**
  - Login is allowed when `login_enabled = 1`, even if the user is disabled, expired or over quota, so they can see why.
  - Subscription content follows the user's status, as it does today.
  - Rate limiting is shared through `login_attempts` (per IP). Password hashing is shared (`auth/password.go`), and so are the same-origin CSRF check and the session lifetime setting.
- **The portal never shows** access records (§3.6 minimal audit) or other users' data.

### 4.3 Subscription system (R1, R2)

```text
internal/panel/subscription/
├─ service.go        token → user → Viewer → sources → Profile → exporter
├─ handler_http.go   format resolution and headers; no per-format branches
├─ proxy/            format-neutral client proxy model
├─ source/           Source interface + registry; published/ (qui nodes)
├─ format/           Exporter + reserved Parser interfaces, registry, UA table
│  ├─ uri/  singbox/  clash/
└─ rules/            neutral rule template: model, validation, presets, store
```

- **`proxy.Proxy`:**
  - origin `{Source, Ref, Labels}`, name, server/port, protocol;
  - credential fields;
  - TLS (SNI, ALPN, pinned CA, fingerprint, insecure);
  - transport (ws/grpc/quic/h2);
  - QUIC tuning.

  New protocols, e.g. VMess or Reality for imported proxies, are new values plus optional typed option structs.
- **`Source`.** `Proxies(ctx, Viewer) ([]proxy.Proxy, []Warning, error)`.
  - Registered now: `published`, qui's nodes, tagged with `nodeGroup:<id>` labels.
  - A failing source contributes nothing plus a warning, never failing the whole subscription. Name collisions are resolved after the merge, with qui nodes first.
- **`Exporter`:**
  - `ID`, `Aliases`, `ContentType`, `UserAgents`, `UsesRules`, `Render(Profile) (Output{Body, Warnings}, error)`;
  - each exporter filters its own capabilities: an endpoint it can't express is left out with a warning;
  - warnings go to the admin preview only, never to `/sub`.
- **U5 imports:**
  - registered typed URI, Base64 URI and Clash YAML parsers;
  - optional `imported` source; its failures become Owner-preview warnings;
  - `@source:<id>` expands only proxies already filtered by the user's grants;
  - imported proxies carry `proxy.Origin.Source = "import:<id>"`.
- **Constraints for imports:**
  - imported proxies are client-side only (never sent to Agents, never in revisions or quotas);
  - fetched on a schedule, never during `/sub`;
  - https only, with size and time limits, no redirects to private addresses;
  - stored encrypted with the vault;
  - parsed as untrusted typed input;
  - granted per user;
  - its own migration and API at that time.
- **Format resolution** for `GET /sub/{token}`:
  1. `?format=` (ID or alias; unknown → 400);
  2. else the UA table, if auto-detect is on: specific legacy patterns first (`clashforwindows`, `clashx/` without `meta`) → `clash-legacy`; then generic Clash UAs (`clash`, `mihomo`, `clash-verge`, `flclash`, `clashmetaforandroid`, …) → `clash`; `sfa`/`sfi`/`sfm`/`sing-box` → `sing-box`; others per F0 findings;
  3. else the Owner default.
- **Formats in v1.1:**

| ID | Aliases | Rules | Notes |
| --- | --- | --- | --- |
| `clash` | `mihomo`, `clash-meta` | yes | all qui protocols (`type: ss` for Shadowsocks; `servername` for VLESS, `sni` for Trojan/HTTP/QUIC). Pinned-CA Hysteria2/TUIC endpoints use `fingerprint:` = SHA-256 of the CA certificate DER (mihomo matches any certificate in the chain; A.1) |
| `clash-legacy` | `clash-premium` | yes | proxies: ss, socks5, http, trojan only (no vless, hysteria2, tuic, wireguard); rules: no GEOSITE, RULE-SET or rule providers (A.2) |
| `uri`, `base64` | — | no | byte-identical to today |
| `sing-box` | — | no | fragment, byte-identical to today |

  Future formats, each a single exporter: `sing-box-profile`, Stash, Surge, Quantumult X, Loon.
- **Headers:**
  - `Content-Type` from the exporter;
  - `Content-Disposition: attachment; filename*=UTF-8''<platform name>`;
  - `subscription-userinfo: upload=<u>; download=<d>; total=<limit|0>; expire=<unix|0>`, where u + d = `used_traffic`, split in the ratio of the user's `account_traffic_daily` totals (both 0 when there's no data);
  - `profile-update-interval` (Owner setting, default 12 h);
  - existing `Cache-Control: no-store` and `Referrer-Policy: no-referrer`.

### 4.4 Global rule template (R1)

- Stored as one typed `system_settings` row (`client_rules`) with an optimistic revision, like `runtime_policy`. **No migration.** Included in backups.
- The model:

```text
client:    mixedPort, allowLan, mode(rule|global|direct), logLevel, ipv6
dns:       enable, enhancedMode(fake-ip|redir-host), nameservers[], fallback[]
groups[]:  name, type(select|url-test|fallback), members[], testUrl, intervalSeconds
           member = DIRECT | REJECT | <group> | @all | @nodeGroup:<id> | @source:<id> (granted imported proxies only)
providers[]: name, behavior(domain|ipcidr|classical), sources{clash, sing-box}: https URL, intervalSeconds
rules[]:   ordered, last = MATCH;
           DOMAIN | DOMAIN-SUFFIX | DOMAIN-KEYWORD | IP-CIDR | IP-CIDR6 | GEOIP | GEOSITE | RULE-SET | MATCH
           payload (validated per type), target, noResolve
```

- **Per-user expansion.** `@all` and `@nodeGroup:<id>` expand per user, so one global template gives each user groups that match their own node groups. An empty expansion falls back to `DIRECT` with a warning.
- **Validation:** unique names, targets exist, no cycles, a single final MATCH, syntax checks, https providers; at most 64 groups, 2,000 rules and 32 providers.
- **Presets.** The four presets from the draft panel become built-in Go data. Applying one copies it; it isn't live-linked.
- **Unsupported rules.** Each exporter maps rule types through its own capability table. An unsupported rule is dropped with a warning; its target is never rewritten.
- **Client rules don't replace node policies.** Node policies stay authoritative. Client rules only choose direct, proxy or reject, and which group.

### 4.5 sing-box (R3)

- **Build:**
  - pinned upstream tag and commit (Phase 0: v1.14.4, `c005f353…`), pinned Go toolchain (go1.26.10, as upstream's release workflow), `CGO_ENABLED=0`, `-trimpath`;
  - upstream Makefile flags: `-ldflags "-X 'github.com/sagernet/sing-box/constant.Version=<ver>' $(cat release/LDFLAGS) -s -w -buildid="`, tags `release/DEFAULT_BUILD_TAGS_OTHERS` + `with_v2ray_api`;
  - **our script** refuses a dirty checkout (`git status --porcelain` non-empty) and checks `vcs.modified=false` in `go version -m`; upstream's own build doesn't (A.3);
  - output: one static binary per architecture (amd64, arm64): no `PT_INTERP`, no `DT_NEEDED` (A.3), so it doesn't depend on glibc or musl;
  - it is not byte-identical to upstream's release assets, which use the CGO "naive" variant (naive outbound only; qui doesn't use it);
  - packed in the upstream archive layout as `sing-box-<ver>-qui.<n>-linux-<arch>.tar.gz`, plus a provenance file;
  - shipped **inside the qui release** and covered by `SHA256SUMS`.
- **Installers:**
  - `--core sing-box` defaults to the qui build from the same release, verified through `SHA256SUMS`;
  - `--core-source official` keeps today's path (`--core-sha256`, musl selection).
- **Core updates.** `core_source.go` also accepts `https://github.com/jingniao/qui/releases/download/<tag>/sing-box-<ver>-qui.<n>-linux-(amd64|arm64).tar.gz`. The panel only offers this to Agents that advertise the new capability, since older Agents would reject the URL.
- **Agent:**
  - When `Tags:` include `with_v2ray_api`, render `experimental.v2ray_api` on a random 127.0.0.1 port with `stats.enabled`, `stats.users` = **every** user credential name on the node (unlisted users get no counters; counters appear lazily on first traffic) and `stats.inbounds` = the user inbounds.
  - Read per-user counters through a sing-box reader with the same cumulative-counter and cursor semantics as `core/xray/stats.go` (`reset=false`), into the existing traffic batch, spool and quarantine path. Wire details (A.3):
    - the server path is `/v2ray.core.app.stats.command.StatsService/QueryStats` (sing-box overrides the service name), so the reader calls `grpc.ClientConn.Invoke` with that method and reuses the existing `xraystatspb` messages, which are wire-compatible; no new proto and no `go.mod` change;
    - sing-box ignores the legacy `pattern` field and returns every counter, so the reader issues **one** query and keeps `user>>>…>>>traffic>>>{uplink,downlink}` client-side; it must never issue the Xray reader's second query, which would produce duplicate names;
    - both cores count the same bytes (identical counters for the same transfer, A.6d), so quotas are consistent across cores.
  - The Clash API stays for node totals and for the device gate (7.3).
  - Official binaries keep exactly today's D5 behavior.

## 7. Concurrent device limit (R7)

### 7.1 Definition

A **device** is a distinct client **source address key** with at least one active user session on an entry node within the last `active window` (default 60 s):
- IPv4: the full address;
- IPv6: the `/64` prefix, which absorbs privacy-address rotation.

Keys are unioned across all of the user's entry nodes. Relay and internal credentials are excluded.

### 7.2 Observation (Agent)

| Core | Source | Precision |
| --- | --- | --- |
| Xray | `GetStatsOnlineIpList` per user credential, polled every 5 s (the API already used for online counts). Upstream semantics (A.4b): reference-counted per IP (no port), the IP disappears as soon as its last connection closes, `lastSeen` is Unix seconds, loopback is never listed, no upstream expiry. The panel's active window (60 s) therefore starts from the last snapshot that listed the key. | Exact IPs of open TCP sessions |
| sing-box | The existing log parser already ties a connection ID to the user. A new ID-keyed join in `collector/singbox.go` stores the source from the same ID's `inbound connection from <ip>:<port>` line (today it is silently dropped; A.3h) and attaches it when the `[user] inbound connection to …` line arrives; `from`-only entries expire on the existing 2-minute sweep, and a malformed source is rejected like a malformed destination. The key stays active while the Clash API `/connections` still lists that `sourceIP`/`sourcePort` (both present, A.3g). | Exact for connections that are open now |
| WireGuard (either core) | none | Not counted, not gated (C5) |

The address keys travel in the existing connection snapshot (15 s heartbeat). Agents that can't observe a user's addresses report "unknown" for that user, as today.

### 7.3 Admission (panel, in memory)

- **Per-user state:** an admission map `key → {firstSeen, lastSeen, nodes, state}`, where state is allowed or gated. It lives next to `connections.Store` and is never persisted.
- **Allowed set:** with `device_limit = N > 0`, the first N active keys by `firstSeen` are allowed, and any additional key is gated.
  - **Sticky:** an allowed key stays allowed while it is active.
  - **Release:** after the active window (60 s) ends, a slot frees when an allowed key has been inactive for the `release window` (default 120 s); maximum retention from its last observation is 180 s. The oldest gated key is then promoted.
- **Gate commands.** When a user's gated set changes, the panel sends `DeviceGateCommand{user credential names, gated address keys, ttl = 3 min}` to every Agent that announced support and holds that user's credentials. It refreshes the command before the TTL runs out.
  - Gates expire on the node if the panel goes away, so this **fails open**, consistent with "nodes keep running when the panel is offline".
- **Events:**
  - the first gate per user per hour raises a `user_access` alert;
  - an Owner limit change, or `devices-online/reset`, recomputes immediately.

### 7.4 Enforcement (Agent, no restart, no revision)

- **Xray:**
  - The Agent keeps the rendered `routing` JSON (rules, balancers). To apply gates it writes a JSON file `{"routing":{"rules":[deny rules…, rendered rules…],"balancers":[rendered…]}}` and runs the **installed official binary**: `xray api adrules -s 127.0.0.1:<api port> -append=false <file>`. Upstream's own JSON loader turns it into the protobuf that `AddRule` needs (`AddRule` takes protobuf only; A.4c, A.6a), so the Agent doesn't depend on `xray-core` and qui's `go.mod` is unchanged.
    - Deny rules: `{"ruleTag":"qui-gate-<n>","user":[credential emails],"source":[gated IPs/CIDRs],"outboundTag":<rendered block outbound>}`. The renderer reserves the `qui-gate-` tag prefix and must never emit it.
    - `routing.domainStrategy` isn't changed by a reload (A.6a-DS); the rendered value stays in force, which is what we want.
  - **Non-atomic reload (A.4c, A.6a).** A rejected payload leaves Xray with no rules, so traffic would fall through to the default outbound and bypass node policies. The Agent therefore:
    - builds the payload only from the rendered routing (already accepted by this core at start) plus gate rules with unique tags, so the server-side checks (missing or duplicate balancer, duplicate tag) can't fail by construction;
    - on any non-zero exit immediately re-sends the gate-free rendered routing, then verifies with `xray api lsrules` that the expected rule tags are present;
    - if that also fails, asks the supervisor to restart the core from the current revision (the normal restore path) and raises a node event. Gates are then re-applied on the next refresh.
  - It re-applies gates after every config apply and core restart, and when gates expire (gate-free payload).
  - New TCP connections from gated addresses are refused at once; established connections continue until they close (A.4c).
  - **Xray SOCKS5 UDP has no user** (upstream sets the user only on the TCP path; A.6b), so a (user, source) gate can't stop SOCKS5 UDP on Xray. The plan doesn't add a source-only gate (it would block other users behind the same address); this is limitation 8 in 7.5. UDP on the other protocols is checked per protocol by the real-core tests in A10.3.
  - `RoutingService` is added to the existing loopback API inbound's services. That API has no authentication; any local process could already change users through `HandlerService`, so this adds no new class of local access. It is documented as a local trust boundary and never exposed off-host.
- **sing-box:**
  - The Agent closes Clash API connections (`DELETE /connections/{id}`) whose source address belongs to a gated key, matched to the gated user through the log parser's connection→user map.
  - It polls every 2 s while any gate is active.
  - This is reactive: a gated device gets connections that open and are closed within about 2 s, which in practice stops it from working.
- **Fallback:** if a capability is missing (older Agent, official sing-box without the needed Clash API fields, or a probe failure), the node doesn't gate. The panel shows the user's limit as "partially enforced", with the nodes listed. This is never silent.

### 7.5 Limitations (stated in the admin UI, portal help and docs)

1. **Addresses, not devices.**
   - Several devices behind one NAT or CGNAT address count as **one**, so the limit is under-enforced.
   - One device can count as **two or more**: IPv4 and IPv6 at once, a Wi-Fi ↔ mobile handover, or different nodes reached over different address families. Handover double-counting lasts until the old address goes inactive (≤ active window + release window).
   - There is no way around this without per-device identity, which R6 rules out.
2. **Delay.** A new device beyond the limit works for up to about one report interval plus delivery (≈ 5–20 s) before it is gated.
3. **No retroactive cut on Xray.** Connections that were established before the gate continue until they close; there is no upstream per-connection kill. sing-box cuts them within about 2 s.
4. **First come, first served.** The device that gets gated is the newest address, not necessarily the one the user wants. Users see "device limit reached"; the Owner can raise the limit or reset the admission order.
5. **Fails open** while the panel is unreachable, after the 3-minute TTL.
6. **WireGuard** is neither counted nor limited.
7. **Privacy.** Client addresses stay in panel memory only. They are masked to both the Owner and the user (/24 IPv4, /48 IPv6), and are never stored, logged or backed up.
8. **SOCKS5 UDP on Xray nodes isn't limited.** Xray doesn't attach the user to SOCKS5 UDP packets, so a device over the limit can still send SOCKS5 UDP through an Xray node. TCP is limited on every protocol. UDP over VLESS, Trojan, Shadowsocks, Hysteria2 and TUIC is checked per protocol in A10.3; any protocol whose UDP turns out to carry no user is added to this limitation rather than worked around.

### 12.3 Technical limitations (investigated, not worked around)

- **L10 U4/U6 measurement and identity scope.** Agent probes measure TCP
  establishment, with loss defined as failed connects and median over successful
  attempts; they do not measure bandwidth, ICMP loss, jitter or reverse-path
  packet loss. The panel-host self-hosted check tests TCP and, when configured,
  a verified TLS handshake to the first resolved address, with bounded DNS and
  connection/handshake deadlines. System roots plus the inbound's configured
  certificate/CA are trusted; certificate verification is never bypassed.
  QUIC/UDP-only listeners cannot be qualified by that TCP check; its failure
  does not change node availability. Forward listeners carry no user identity:
  per-user quota and device limits cannot apply, they are excluded from all
  subscriptions and user-domain access attribution, and automatic user-access
  revisions preserve their published state. Native forward config validation
  and TCP/UDP echo tests are implemented behind XRAY_BINARY/SINGBOX_BINARY in
  CI; their execution and a managed-node field check remain CI/Owner evidence,
  not local passes. No substitute forwarder or core patch was added.

- **L9 U3 monthly traffic retention.** Monthly node totals sum retained
  `account_traffic_samples` within exact local month boundaries, using panel
  timezone and half-open UTC timestamp bounds. Existing retention removes
  these samples after `HourlyDays`; older daily aggregates have UTC buckets
  and cannot reconstruct exact local boundaries (including half-hour zones).
  The UI labels the result as retained records, and the API reports
  `scope=retained_account_samples`. It does not mix cumulative heartbeats,
  UTC-day estimates or domain observations into the total. A complete historical
  month after sample pruning needs a separately planned retention/aggregation
  change. AU3.2's equality to retained traffic samples is tested; completeness
  after pruning is open. No retention policy was silently widened.

- **L8 Phase 10 real-core protocol scope.** A10.3 lists Hysteria2/TUIC in
  its Xray UDP sentence, but the official Xray protocol matrix established in
  Phase 0 has neither inbound. No core patch or alternate forwarder is added.
  Xray's env-gated gate suite covers VLESS, Trojan, Shadowsocks UDP and the
  expected SOCKS5 UDP exception. sing-box's env-gated source/join/close suite
  covers HTTP, SOCKS5, Shadowsocks, VLESS, Trojan, Hysteria2 and TUIC TCP streams
  (including streams transported over QUIC). Hysteria2/TUIC UDP datagram gate
  behavior remains open for a separate CI/Owner experiment; closing a Clash
  connection is reactive and is not a promise that its first datagram was
  refused. All real-core executions are awaiting CI/Owner run. No local core
  execution was used as evidence.
- **Phase 10 privacy clarification.** The Part H task's explicit privacy rule
  overrides section 7.5's earlier full-address Owner view: both admin and portal
  responses mask IPv4 to /24 and IPv6 to /48. Source keys remain volatile.


- **L1 Per-user speed limits** (the 上行/下行限速 fields). Neither official Xray nor official sing-box has per-user rate limiting, and our sing-box build adds only upstream tags. Linux `tc` only sees per-user traffic when the core marks a per-user outbound socket. That covers the server→Internet direction only. The client-facing direction is the shared inbound socket, so download (the direction that matters) can't be limited per user. **Owner decision 2026-10-27: per-user speed limits are removed.** The fields go from the UI, and existing `up=`/`down=` entries are stripped from remarks.
- **L2 Server tuning** (基础调优, restore). It needs a new privileged fixed operation (sysctl profiles such as BBR + fq, with snapshot and restore) run by a helper unit like the host-network helper. That widens the Agent's privilege boundary (AGENTS §23). Not built until the Owner approves. The tab shows the current values read-only (non-privileged `/proc/sys` reads, U3).
- **L3** "Server tunnel" between a managed server and an *imported* node's host is not possible (no Agent there). The canvas offers only proxy chaining for imported nodes, as the summary already states.

- **L4 RC1 prerelease installation.** Phase 7's RC1 asks for an unreleased
  `1.1.0-rc.<sha>` installed through `qui-update --bundle`. The current
  updater rejects every non-`X.Y.Z` version before considering the bundle
  (`deploy/linux/update.sh:1081`); deployment §5 documents the same restriction.
  On a host with both components it also updates the Agent before the panel,
  which conflicts with RC1's requirement to keep Agents on 1.0.9. No installer
  change or alternative installation was attempted in Phase 7. RC1 requires an
  Owner-approved prerelease/component-selection solution before the prepared
  checklist can be executed.

- **L5 U5 parser and client-chain scope.** URI/Base64 and Clash imports accept
  typed HTTP, SOCKS5, Shadowsocks (AEAD ciphers), VLESS, Trojan, Hysteria2 and
  TUIC entries that fit the neutral model. VMess, Reality, plugins, unsupported
  fields and insecure TLS entries are omitted with a generic warning; no opaque
  config is forwarded. Client publication accepts one continuous path of import
  references or published self-hosted inbounds, without branches or cycles.
  Only mihomo carries the chain; URI/Base64, legacy Clash and the current sing-box
  fragment omit dependent hops with preview warnings. Import identities follow
  content, so a changed credential/endpoint needs its canvas reference selected
  again; refreshing/reordering unchanged entries keeps references stable.
  Existing browser-only imports are left intact in storage but are not loaded
  into U5 automatically; they have no trustworthy user grants. Re-import through
  the existing import dialog and grant users in subscription management.
  The earlier B6 exception for server-relay conversion conflicts with Part E's
  explicit no-Agent/no-revision constraint; imported server-relay conversion
  remains unavailable under this phase's authorized scope.
- **L6 U5 real-core acceptance.** AU5.2 is an env-gated test in `format/clash`,
  covered by the existing digest-verified CI `cores` job. It is **awaiting
  Owner/CI run**; mihomo is not executed on this workstation. Current source
  definitions/caches/grants win over backup copies during in-process restore
  to preserve current deletions and revocations. An old backup is not a way to
  roll back external grants.

- **L7 Phase 8 local build verification.** The pinned go1.26.10 toolchain is
  available offline on this Windows host, and Git Bash/GNU tar work, but `readelf`
  is unavailable. The build script deliberately requires ELF inspection and
  refuses missing tools before cloning. No substitute, downloaded core execution,
  or local reproducibility claim was made. The CI `cores` job builds both Linux
  architectures twice, compares archives and provenance, checks static linkage,
  runs `version` and real-core tests, then verifies an unpublished release dry-run.
  A8.1 and the actual build/dry-run part of A8.2 await that CI/Owner run. The new
  core-update capability is absent until Phase 9; both panel gates stay closed.
