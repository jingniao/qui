Acceptance (AU2.2):
- **Managed-server edge** ensures an internal relay inbound on the target
  (`internalRelay=true`, `subscriptionVisible=false`, edge protocol and port) and an
  outbound on the source targeting it — verified by
  `TestCanvasPublishSingleHopTranslatesIntoRelayObjects`.
- **Two or more edges** become a `proxy_chains` row (A→B→C only), and the entry
  inbound's `defaultOutbound` becomes `chain:<id>` — verified by
  `TestCanvasPublishTwoHopsCreatesProxyChain`.
- **Publishing through the existing batches** in exit → relay → entry order: the node
  order is asserted in both tests, and the Deployment module creates and starts the
  batch through `CreateBatch`/`StartBatch` (the same calls the chain and relay editors
  use), covered by `TestCanvasPublisherUsesRevisionOrBatch`.
- **Scheme-tagged objects**: every generated object is named
  `[<scheme>] <A> → <B> (<protocol>:<port>) 中转入口 | 中转出站`, so a second publication
  updates instead of duplicating (`TestCanvasPublishIsIdempotent`).
- **Removing a drawing deletes nothing until the next publication**; that publication
  removes only the scheme's own objects (`TestCanvasPublishPrunesRemovedEdge`).
- **Refusals**: fourth hop, port conflict on the same node, unsupported protocol and
  everything else the module cannot express stop the publication before any object is
  created (the refusal tests assert zero generated objects and zero deploy calls).

Deviations:
1. **Scheme names must be unique** (409 `duplicate_scheme_name`). Publishing derives
   every generated object's name from the scheme name, so two drawings with the same
   name would prune each other's objects. The plan did not say this; it is needed for
   the "re-publishing updates rather than duplicates" guarantee.
2. **"TLS" maps to Trojan** over TLS (`SaveInbound` forces `security=tls` and manages
   the certificate). The plan allows "VLESS/Trojan"; Trojan needs a single credential
   and no extra client id, so it is the simpler of the two.
3. **Object names embed the protocol and port.** A changed port or protocol then
   produces a new object and prunes the old one, instead of hitting the immutable
   node/protocol/relay-target rule.
4. **A fan-out or an over-long path is refused**, not approximated: the proxy chain
   validator accepts two or three nodes in a line only.
5. **Busy nodes keep the existing rule**: publishing to a node that still has an
   unapplied revision returns the deployment module's "node is reserved by an active
   deployment or rollback" error, which the canvas shows as the failure message.
6. **Per-node results render inside the existing properties panel** (a small block
   under 发布状态) instead of a new layout, per R9.
7. Imported nodes and client schemes are refused with their phase (`U5`), port
   forwarding with `U6`, exactly as the plan says.

   `invalid_subscription`, and the body text stays generic.
9. **A node that has not reported capabilities no longer panics**: the old loop
   dereferenced `node.Capabilities` directly, so such a node returned 500 for the
   whole subscription; it now simply contributes no endpoint.
