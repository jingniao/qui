## Irreversibility to know before starting

- **Panel:** 1.2.0 applies migrations 0112–0125. Going back to 1.0.9 is only
  possible with `--database <pre-update-1.0.9-*.db>`, which **discards
  everything written after the upgrade** (revisions, traffic, audit).
- **Agent:** a successful upgrade rewrites the install record to v2. The new
  updater **refuses** to downgrade a v2 record to the 1.0.9 installer. Only a
  *failed* upgrade restores 1.0.9 automatically. Upgrade one Agent at a time
  and only after the drills in H2 pass.
- **0113 merges devices:** every user keeps one hidden access identity; other
  device credentials are revoked and their subscription links stop working.
- Each Agent upgrade restarts the proxy core on that host: **existing user
  connections on that node drop briefly**.

## H1 — panel RC1 on us2-node  **STOP: restarts proxy-panel**

Impact: the web UI and API are down for a few seconds; Agents keep running
their current revision and reconnect by themselves.

```sh
mkdir -p /root/qui-rc && cd /root/qui-rc
rc_version=1.2.0-rc.1; arch=amd64
base=https://github.com/jingniao/qui/releases/download/v$rc_version
curl --no-insecure -fsSLO "$base/proxy-control-$rc_version-linux-$arch.tar.gz"
curl --no-insecure -fsSLO "$base/SHA256SUMS"
rc_dir="proxy-control-${rc_version}-linux-${arch}"; bundle="${rc_dir}.tar.gz"
awk -v file="$bundle" '$2 == file { print }' SHA256SUMS | sha256sum --check --strict || exit 1
tar -xzf "$bundle" || exit 1
bash "$rc_dir/deploy/linux/update.sh" --component panel --version "$rc_version" --bundle "$bundle" --sums SHA256SUMS
```

Pass criteria:
- prints `[proxy-panel] 已更新到 1.2.0-rc.1，服务运行正常（10 秒内无重启）。`; `proxy-panel --version` is `1.2.0-rc.1`;
- `/var/lib/proxy-panel/backups/pre-update-1.0.9-*.db` exists;
- all three nodes reconnect (1.0.9 Agents) and show online; dashboard counts are right;
- a no-op publish and a rollback to the previous revision succeed on uk-node with the old Agent;
- user list shows device limits as 部分执行 for 1.0.9 nodes; subscriptions still download.

Abort path (data written after the upgrade is lost):
`qui-update --component panel --version 1.0.9 --database /var/lib/proxy-panel/backups/pre-update-1.0.9-<time>.db`.
