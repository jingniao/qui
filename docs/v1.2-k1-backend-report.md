## 迁移与语义

- 新增 `0122_node_group_entries.sql` 及校验和；0001–0121、go.mod、go.sum 未修改。
- `node_group_inbounds(group_id,inbound_id)` 与 `node_group_imports(group_id,source_id,proxy_key)` 使用级联外键。导入空 key 为整源，单项 key 为 `name|protocol`，同名同协议条目共享权限；缓存刷新不删除成员记录。
- 原服务器成员展开为迁移时订阅可见、非内部中转的入站；无符合条件入站的服务器不再占据组成员。原来源授权转换为“导入 · 来源名”分组并保留用户授权；名称超长时截短，同名时加唯一后缀。旧 `user_source_grants` 仅保留兼容，不参与访问。
- `node_group_members` 是入站所在服务器的去重派生索引。分组仓储保存与入站移动/删除的事务触发器维护，服务端视图与节点策略继续使用；新增入站须显式入组。
- 访问要求有效的 subscription/mixed 分组及用户授权，服务器启用、未维护、允许订阅、未删除；入站订阅可见、非内部中转，且非空 allowedUserIds 包含本人。订阅还核对已发布凭据，渲染按具体入站附加凭据。
- 客户端链继续仅使用已过滤的端点集合；缺任何一跳便整链省略。画布内容哈希引用保持原语义，刷新改变代理内容时不会静默重指向。
- 门户维持服务器列表响应形状，仅显示至少一个入站可达的服务器。导入代理通过订阅输出，不伪造为自托管服务器。
- 自动额度/删除用户仍覆盖已发布状态持有凭据的服务器；草稿渲染失败的回退路径也检查当前入站授权，只移除访问，不采用草稿路由设置。
- 进程内恢复保留当前分组定义、成员和用户授权；不存在于恢复后业务数据中的入站引用被过滤。旧归档先执行迁移。元数据端口范围按现有元数据规则保留当前值。
- 端口范围须同时为空或满足 `1 <= start <= end <= 65535`。迁移提取备注末尾有效 `[ports:A-B]`，无效后缀保留。画布隐式中转端口优先从范围分配，检查所有入站（含禁用）与计划监听的 TCP/UDP 占用，重复发布复用所属监听；耗尽报错。显式端口不受范围限制，无范围沿用旧默认值。

## API 合同

没有新增路由。分组接口沿用 Owner、写入 CSRF 与现有审计；未知字段仍拒绝。未实现可选的批量替换用户授权路由，继续使用原用户授权接口。

`POST /api/v1/node-groups`、`PUT /api/v1/node-groups/{id}`：

```json
{
  "name": "日本入口",
  "purpose": "subscription",
  "enabled": true,
  "subscriptionVisible": true,
  "remark": "",
  "inboundIds": ["inbound-id"],
  "imports": [{"sourceId": "source-id", "proxyKey": "Tokyo|vless"}]
}
```

成员上限 500 入站、200 导入，验证重复及存在性。兼容输入 `nodeIds: string[]`（最多 100）：仅当 inboundIds 未提供或为 null 时展开其服务器当前符合条件入站；显式 `inboundIds: []` 优先于 nodeIds。新客户端应发送 inboundIds/imports，nodeIds 只作为输出的服务器索引使用。

GET 列表仍为 `{items,total,page,pageSize}`；列表项与保存响应为：

```json
{
  "id": "group-id",
  "name": "日本入口",
  "purpose": "subscription",
  "enabled": true,
  "subscriptionVisible": true,
  "nodeIds": ["server-id"],
  "inboundIds": ["inbound-id"],
  "imports": [{"sourceId": "source-id", "proxyKey": "Tokyo|vless"}],
  "grantedUserIds": ["user-id"],
  "remark": "",
  "createdAt": "RFC3339 timestamp"
}
```

`GET /api/v1/imported-proxies`：

```json
{"items":[{"id":"content-hash-id","sourceId":"source-id","proxyKey":"Tokyo|vless","name":"Tokyo","protocol":"vless","server":"example.com","port":443}]}
```

`GET /api/v1/subscription-sources` 保持 `{items:[{id,name,intervalSeconds,lastFetchAt,lastStatus,lastError,userIds}]}`。userIds 输出从有效分组推导的用户集合，不表示账号当前活跃或来源缓存可用；来源保存仍接受 userIds，但忽略其授权意图。

`PUT /api/v1/nodes/{id}/meta`（原字段保留）：

```json
{"region":"JP","remark":"","renewDate":"","renewCycle":"","renewPrice":"","renewCurrency":"","renewNoticeDays":7,"portRangeStart":20000,"portRangeEnd":20100,"importOnly":false}
```

GET 与 PUT 成功响应均为 `{meta:{region,remark,renewDate,renewCycle,renewPrice,renewCurrency,renewNoticeDays,portRangeStart,portRangeEnd},present:boolean}`。两端口字段的 JSON 类型均为 integer 或 null；非法输入 400 `invalid_request`。importOnly 仍为可选写入控制字段，不出现在 meta 响应内。

## K1 fix (2026-10-29): preserve server policy scope

This section supersedes the original K1 description of a purely inbound-derived server index. Migration 0122 is unreleased and was revised directly with its checksum. This fix does not change migrations 0001-0121, go.mod, go.sum, web, Agent, proto or deployment scripts. No commit, push, live database or server operations were performed.

### Design and migration

- Added `node_group_servers(group_id,node_id)`, with a composite primary key and cascading foreign keys to node_groups and nodes. `node_group_members` is the deduplicated union of explicit servers and servers of member inbounds, preserving its use for policy scope, server filtering and bulk operations.
- All original relay/egress servers become explicit members; these groups do not expand subscription inbounds. Subscription/mixed servers expand eligible subscription-visible, non-internal-relay inbounds; original servers not represented by those inbounds become explicit members. Every original group's post-migration server set is EXACTLY its pre-migration set.
- Explicit servers grant NO user access, subscription, portal visibility or proxy credentials. Access still requires authorized inbound/import entries and all K1 eligibility/published-credential checks.
- Repository writes and SQL triggers maintain the union on explicit member insert/delete/update, inbound moves and FK cascades. Removing an inbound retains explicit membership; removing explicit membership retains a server still represented by another inbound.
- Logical server deletion clears explicit membership alongside the old node_group_members cleanup; physical deletion uses FK CASCADE. Backups include the new table, and inventory adds `totals.nodeGroupServers`. Validation checks table/migration presence, references, deleted nodes, the 100-explicit-server cap, and both directions of union equality. In-process recovery preserves current explicit membership, filtering deleted nodes, consistently with current group/entry recovery. Older archives migrate first.

### API and existing bulk action

GET group lists and POST/PUT responses add `serverIds: string[]` (explicit membership); `nodeIds` returns the union. POST/PUT accept optional `serverIds`: at most 100 unique existing, non-deleted servers. Omission/null preserves existing explicit membership (empty on create); [] clears it.

- subscription/mixed: nodeIds expands current eligible inbounds only when inboundIds is absent/null. Explicit inboundIds, including [], takes priority. When serverIds is omitted on a legacy nodeIds request, existing explicit membership is intersected with selected nodeIds; newly selected servers do not automatically become explicit members.
- relay/egress: nodeIds sets explicit servers without implicitly expanding inbounds. Explicit serverIds takes priority if supplied. Subscription visibility remains false.
- Legacy nodeIds requests retain omitted imports, since old bulk clients cannot represent them. Explicit imports: [] clears them; other requests retain K1's entry replacement semantics.

Read-only inspection of `web/src/modules/nodes/components/ServerBulkActions.vue` and `web/src/modules/proxy/lineGroups.ts` confirmed its PUT sends name/purpose/enabled/subscriptionVisible/remark/nodeIds, omitting inboundIds/imports/serverIds. Exact behavior:

1. relay/egress join/leave replaces explicit membership with the complete selected server list, including servers with no inbounds or only internal relay inbounds. This grants no user access.
2. subscription/mixed join re-expands all currently eligible inbounds on every selected server. Leave removes that server's inbound entries and any preserved explicit membership. Remaining explicit members and existing imports survive. As in K1, this legacy full-record PUT can widen a partially selected server to all its current eligible inbounds. Adding a new server without eligible inbounds has no effect; policy-only membership requires explicit serverIds.
3. Saving a group does not automatically publish node policies. Subscriptions reflect the change at the next refresh, subject to authorization and eligibility. No web files were edited.
