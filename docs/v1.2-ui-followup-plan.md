## 1. The product model the new UI implies

The Owner's edits describe a model that differs from the backend in five places. The table states the target model; §3 plans the backend for each row.

| Area | New UI model (target) | Backend today |
|---|---|---|
| Node groups | A **node group holds individual nodes**: self-hosted inbounds and imported proxies. Users are granted groups **on the group page**; the user pages have no grant controls. | Groups hold **servers**. A user gets every subscription-visible inbound on the granted servers. Imported proxies reach users only through per-user source grants (`user_source_grants`). |
| Imported sources | Airport and manually imported nodes are distributed **through node groups**, not per-user. | Per-user grants on each source. |
| Servers | A server has **finance** (price, monthly cost, residual value), **hardware/system** info (CPU model, arch, kernel, memory/swap/disk totals), **monitoring history** (CPU, memory, disk, network, connections, processes; 1H–7D), a **port range** used for new nodes, relays and tunnels, and a **tuning** tab. | Finance: yes (node_meta). Hardware info, totals, history and port range: no. Tuning: read-only heartbeat fields only. |
| Cores | **Several cores per server**, with 添加内核 / 删除内核 / 升级. | One core per node. An update replaces it, and there's no removal. (MC1–MC4 are already planned in v1.2.) |
| Relay canvas | **Tunnels are reusable objects shared across schemes.** The library has five categories: servers, self-hosted, airport, manual, tunnels. | Tunnels are connections inside one scheme. Objects are generated per scheme, so the same tunnel in two schemes conflicts or duplicates. |
| Tasks | One **任务记录** page for Agent and core update tasks. 版本与更新 does single upgrades and "全部升级" (upgrade all). | APIs exist. Signed Agent release registration and recover are no longer reachable in the UI. |
| Admin accounts | Listed and managed on **用户管理** together with end users. | APIs exist; works. |
| Certificates | Hidden from the UI (Owner, 2026-10-29). Renewed **every 30 days with the same key**, only while connected. | 90-day certs; the Agent renews when ≤14 days remain. |

## 2. Defects found in the modified UI

### 2.1 Must fix: broken or data-damaging
1. **Navigation guard removed** (`router.ts`).
   - Missing: login redirect, `/setup` enforcement, Viewer route limits, portal guard.
   - Nothing loads the session on a page reload, so `isOwner`/`isViewer` are false: Owner-only menu items disappear, a Viewer sees every section, and SSE never connects.
   - The document title and chunk-reload handlers were removed with it.
   - The new `csrf_failed` auto-retry hides part of this; it also re-sends a mutation under whatever session the cookie now holds. Remove the retry once the guard is back.
2. **Saving a subscription source wipes its user grants**: every create/edit sends `userIds: []`, and the backend replaces the grant set.
3. **Saving server metadata fails with 400 once a port range is set**: `saveNodeMeta` spreads `portRangeStart/End` into the PUT, and the API rejects unknown fields. The node PUT before it has already succeeded, so the save is half-applied.
4. **New users get an empty subscription.** There's no UI left to grant node groups (`grantGroup`/`revokeGroup` have no callers), and new users are created with `nodeGroupIds: []`.
5. **Editing an imported node creates a new source** (`saveManualNodeModal` always calls create). Deleting one imported node deletes its whole source.

### 2.2 Must fix: shows things that are not true
6. **Monitoring charts are invented.**
   - Sine-wave history with injected spikes.
   - Fixed values: memory total 431 MB, disk 1021 MB, 111 processes, connections 69, uptime 360000 s, traffic 48 KiB/s, CPU 0.7 %, memory 46.8 %, disk 69.8 %, an 88/12 TCP/UDP split.
   - The 1H–7D ranges only relabel this data.
7. **Hardware panels** read fields that don't exist (CPU model, arch, kernel, GPU, totals), show a made-up CPU label, and repeat the percentage under "total".
8. **Cores page.**
   - The installed-core list lives in localStorage; once written, it overrides what the node reports.
   - "添加内核" for the other core always gets a 409 (one core per node).
   - "删除内核" removes nothing on the server, yet says it succeeded.
   - Preset SHA-256 values are fake (one is the hash of an empty file). The backend accepts them; the Agent then fails with `checksum_mismatch`.
   - Agent release matching ignores architecture.
   - "全部升级" only covers the first 20 servers.
9. **Node groups.**
   - Per-inbound and imported membership lives in localStorage.
   - The backend receives only the derived server list, so removing one inbound changes nothing, and imported members do nothing.
   - 用户详情 "可用节点" lists every subscription-enabled server regardless of grants, and the footer says a fixed "账号正常" (account OK).
10. **Tuning.** "确认下发并生效" (confirm: apply now) sends nothing; it only writes localStorage. The "BBR 就绪" (BBR ready) check only looks at the OS name, even though the heartbeat reports the real `tcp_congestion_control`/`default_qdisc`.
11. **Shared tunnels** live in localStorage.
    - The pool is rebuilt from every scheme on every change, and "delete" doesn't stick.
    - Reusing a tunnel copies it; the second scheme then gets a port conflict or duplicate objects at publish.
12. **Canvas.**
    - The publish dialog says "校验通过，配置无环路冲突" (check passed, no loop conflicts) without running a check.
    - Node aliases are never saved.
    - The connection rubber-band uses the wrong element for coordinates.
    - Mouse listeners leak.
    - Code that can never run: the tunnel-list modal, `TunnelList.vue`.
    - `getNodeRelayRoutes` has hard-coded demo matching (`manual-jp`, 日本).
    - "检查" (check) always fails for client schemes.
    - A placeholder scheme can appear after the last scheme is deleted.
    - A new scheme can get a duplicate name.
13. **Smaller issues.**
    - Server card "已运行" (uptime) is hard-coded "—" although `host_uptime_seconds` exists.
    - The card ignores `core_healthy`.
    - The overview region call has its arguments swapped.
    - The renewal warning ignores `renewNoticeDays`.
    - "订阅接入 IP / 域名" (subscription IP/domain) accepts only an IP.
    - "安装命令" (install command) revokes the token even for a live server.

### 2.3 Lower priority
14. `TaskRecordPage` turns every load failure into "暂无任务记录" (no task records), reads only the first 100 of each type, and clears without confirming.
15. Owner-only buttons are not hidden for Viewers on the node pages (新建节点, 编辑, 删除, 添加中转) or in user creation.
16. The 用户中心 (user center) password form allows 6 characters; the backend and other forms use 12–128.
17. Dead code: `AppHeader.vue`, `AdminPage.vue`, `AgentUpdatesPanel.vue`, `NodeCertificatePanel.vue` (hidden on purpose), `NodeHealthPanel.vue`, `TCPProbesPanel.vue`, `NodeCollectorPanel.vue`, `NodeTrafficSourcesPanel.vue`, `ServerDetailGroups.vue`, `TunnelList.vue`.
18. The log has no closing summary; E31 is title-only.

### P1: node groups by node, and port range (backend, then frontend)
- **Migration 0122.**
  - Group members become nodes: `node_group_inbounds(group_id, inbound_id)` and `node_group_imports(group_id, source_id | imported proxy key)`.
  - Data migration: each server member becomes all of that server's eligible inbounds.
  - Each existing `user_source_grants` set becomes a generated group "导入 · <source>" granted to the same users, so no one loses access.
  - Add `node_meta.port_range_start/end`, migrating the `[ports:]` remark suffix out.
- **Subscription and portal:** user → groups → inbounds ∪ imported proxies. Server switches (enabled, maintenance, allowSubscription) still filter.
- **Credential deployment** (`AccessForGroups`, quota auto-revisions, deletion) moves to inbound granularity: a server gets a user's credentials only for the inbounds that user can reach.
- **Port range:** validated on the API. Canvas-generated relay inbounds pick from the range.
- **Backups:** backup, restore and inventory cover the new tables. Tests. AGENTS.md §10.1/§26 updated.
- **Frontend:** wire the 节点分组 page to the real membership; remove the localStorage maps and the temporary user-grant fallback in the import dialog.

### P2: Agent release bundle: host info, metrics history, 30-day certificate renewal
- **Agent:**
  - Report host info once in capabilities: CPU model, cores, arch, kernel, memory/swap/disk totals.
  - Add to the heartbeat: load, process count, TCP/UDP connection counts, swap used.
  - Renew the certificate once it is 30 days old, same key, only while connected (B7, decided (a)).
- **Panel:**
  - `node_metric_samples` with one sample per minute, kept 7 days and excluded from backups (same pattern as latency, 0123).
  - `GET /nodes/{id}/metrics?hours=` with the same bucketing as latency.
- **Frontend:** real hardware panels and real monitoring charts. Older Agents show "—".
- **Release:** needs a new Agent release; the panel ships first, as usual.

### P3: multi-core and core management (the v1.2 MC1–MC4 phases, then GOST)
- Multiple cores per node.
- Per-core capabilities (list instead of one `coreName`).
- A fixed "remove core" Agent operation, refused while any inbound uses that core.
- 添加/删除内核 wired to the real backend.
- Then G0–G3 (GOST) as already planned.

### P4: shared tunnels (only if the Owner wants real sharing)
- Tunnels become first-class objects (`canvas_tunnels`) referenced by schemes.
- Publish generates each tunnel's server objects once, named by tunnel, not by scheme.
- Deleting a scheme keeps tunnels still in use elsewhere.
- Frontend library reads tunnels from the API.

### P5: wrap-up
Docs (AGENTS.md, ui-structure, acceptance matrix, operations), full gate, browser walkthrough on the demo data. An RC or release only with explicit approval.
