# v1.2 UI structure proposal — pages first, backend later (draft)

Status: **proposal for Owner review**, 2026-10-28. Pages only; no backend
changes. Everything here uses existing APIs. The backend items in
docs/v1.2-plan.md (per-scheme access S1, multi-core MC, GOST G) wait until the
pages are settled.

## 1. Three words, one meaning each

The current UI mixes these. Every page, label and toast will follow this table.

| Word | Means | Example |
| --- | --- | --- |
| **服务器** | A machine running the Agent (table `nodes`) | Tokyo-01, 1.2.3.4 |
| **节点** | Something a user can connect to: an inbound on a server, which shows up in subscriptions | Tokyo-01 · VLESS 443 |
| **线路组** (today 节点组) | A named set of **servers**. Granting a 线路组 to a user lets that user use every user-facing 节点 on those servers | 日本线路 = Tokyo-01 + Osaka-01 |

Why rename 节点组 to 线路组: a group contains servers, not nodes, and its
purpose is access. "线路" is what users and Owners already call a set of
servers. The backend keeps the name `node_groups`; this is a label change only.

## 3. 线路组 page (节点配置 › 线路组)

### 3.1 Two kinds of groups

The backend has four purposes: subscription, relay, egress and mixed. The page
shows two kinds and keeps the rest behind 高级:

- **用户线路组** (purpose subscription): grants users. This is the normal case.
- **内部分组** (relay/egress, hidden from subscriptions): used only by 中转搭建
  and policies. It never grants users.

### 3.2 Layout A — list + detail (recommended)

```

│ [+ 新建线路组]   [搜索]                          视图: (列表) / 矩阵    │

│ ● 日本线路   3 台 · 5 人 │ 用户线路组 · 已启用 · 备注：主力线路         │
│ ● 香港线路   2 台 · 4 人 │                                             │

│                          │  Tokyo-01   在线  VLESS·Trojan  2 个节点 [移出]│

│                          │ 授权用户 (5)                   [+ 授权用户]  │
│                          │  alice  bob  carol  dave  erin   (点击移除)  │
│                          │                                             │
```

- **Left:** groups by kind, with server and user counts. Disabled groups are
  greyed.
- **Right:** one group's servers and its granted users, so the effect of a
  group is visible in one place.
- **添加服务器:** a picker with search, region, status and checkboxes. A server
  may be in several groups; its other groups show as chips.
- **授权用户:** the same picker for users. It writes the existing user grants.
- **效果预览:** read-only. It is computed from servers × user-facing inbounds
  (existing APIs), so the Owner sees what users actually get.
- **Internal groups:** show servers only, plus a 被引用 list (relay schemes and
  policies that use the group). There is no user section.

### 3.3 Layout B — matrix (optional second view)

At 1–10 users and a handful of servers, a matrix answers "who gets what"
fastest:

```
                 日本线路   香港线路   美国备用   中转专线(内部)
Tokyo-01            ☑          ☐          ☐           ☑
Tokyo-02            ☑          ☐          ☐           ☐
HK-01               ☐          ☑          ☐           ☑
LA-01               ☐          ☐          ☑           ☐
──────────────── 授权用户 ─────────────────────────────────
alice               ☑          ☑          ☐           —
bob                 ☑          ☐          ☐           —
```

- The top half shows server membership; the bottom half shows user grants.
  Internal groups have no user column.
- Toggling a cell marks it as changed. **保存** applies every change in one
  confirmation that lists them.

Recommendation: build A, with B as a toggle. They share one data model and one
save path.

### 3.4 Where else membership is edited

Every place uses the same chips plus picker:

- **Server list:** bulk action 加入/移出线路组 on selected servers.
- **Server details › 概况:** 所属线路组 chips, with an edit button. Saves all
  changes in one go.
- **User details:** 授权线路组 chips with the picker (already there; restyled).

## 4. Decluttering rules for every page

1. **One job per page:** lists show status, detail pages do management. A list
   never hosts management dialogs that belong to a detail page.
2. **No placeholders:** no "—" walls, fake 测试点 boxes, "待办" cards or demo
   values. A value that doesn't exist is hidden, with one line saying why.
3. **One status vocabulary:** `StatusBadge` everywhere, with every server state
   from AGENTS §11.4 (including core errors).
4. **Progressive disclosure:** forms show only the fields for the chosen
   protocol or kind. Advanced options sit behind 高级, closed by default.
5. **Design system:** tokens and components only, with no raw hex colours or
   arbitrary sizes. A self-test enforces this.
6. **Small files:** pages over ~400 lines are split into components.

## 6. 新建节点 drawer (steps)

```
① 服务器      选择服务器（只列出在线/已登记；显示其核心与支持的协议）
② 协议与端口  协议（不支持的置灰并说明原因）· 端口（实时检查占用）
③ 传输与安全  仅在协议需要时出现：传输 ws/grpc · TLS 证书（必填校验）
④ 协议专属    Hysteria2/TUIC 速率与拥塞 · WireGuard 地址/MTU · SS 加密 · 转发目标
⑤ 高级（折叠） 监听地址 · 默认出站 · 内部中转 · 订阅可见 · 允许用户
⑥ 确认        摘要 + 配置差异预览 → [保存草稿] [保存并发布]
```

The port-conflict check (`GET /nodes/{id}/ports?check=`) is the one small
backend addition here. Until it lands, the drawer checks against the node's
inbound list on the client.
