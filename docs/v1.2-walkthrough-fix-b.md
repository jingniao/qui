## 1. 每个自建节点都显示 "TCP · UDP"

**根因**
`ProxyNodeListPage.selfHostedNodes` 用 `getTcpUdpSupport(ib.protocol)` 猜测端口能力：除 `hysteria2`/`tuic`/`wireguard`/`http` 外一律返回 `{tcp:true,udp:true}`，所以 VLESS/VMess/Trojan 全部显示 "TCP · UDP"。同一份数据在服务器详情页用的是 `listenNetworks(inbound)`（`web/src/modules/proxy/components/node-editor/nodeEditorModel.ts`），因此两页结论不一致（详情页 VLESS 显示 TCP，Shadowsocks/SOCKS5 显示 TCP/UDP）。另外 `loadImports()` 对导入节点直接写 `supportTcp:false, supportUdp:false`，列表里那一行是空白。

**修复与决策**
- 自建项改用 `listenNetworks(ib)`：`supportTcp = networks.includes('tcp')`、`supportUdp = networks.includes('udp')`，与服务器详情页完全同源。
- 页面内的 `getTcpUdpSupport()` 已删除（`listenNetworks` 是唯一口径）。
- 协议猜测只保留给导入节点（面板没有它们的 inbound 记录）：新函数 `proxyNodes.guessProtocolNetworks()`，由 `loadImports()` 使用。默认值收紧为"只有 TCP"，因为 vless/vmess/trojan 都是 TCP 传输，只有 SS/SOCKS5 与 QUIC 类协议明确带 UDP；这是刻意不沿用旧的"默认同时支持 TCP+UDP"。
- 展示改为 `networkLabel(node)`，输出 `TCP` / `UDP` / `TCP · UDP` / `—`（旧模板在只有 UDP 时会渲染出前导 "· UDP"）。

## 2. 画布"我的自建节点"永远为空

**根因**
`RelayCanvasPage.selfHostedNodes` 从 `proxyNodeStore.manualNodes` 过滤 `sourceType === 'self_hosted'`，但 `manualNodes` 只由 `loadImports()` 写入，且写入的值恒为 `'subscription'` —— 没有任何代码产生 `self_hosted` 项，因此该分组恒为空，而"机场导入节点"里塞满了本来属于自建/单独导入的条目。

**修复与决策**
- 新纯函数 `canvasLibrary.selfHostedLibraryItems(servers, inbounds, search)`：遍历已启用且未逻辑删除的服务器，逐条取其 inbound；命名、地址、在线判定与 `ProxyNodeListPage.selfHostedNodes` 完全一致（去掉与服务器名重复的前缀、`·`、`(内部中转)`、`(已停用)`、`publicIp || hostname || 127.0.0.1`）。停用入站仍列出但不可拖（`draggable=false` + 提示），删除/停用的服务器不产生条目。搜索框同时过滤该分组。
- 条目 id 使用 `selfHostedResourceId(inbound)` = `self-<nodeId>-<inboundId>`，这正是 `api.canvasInstanceRef()` 会识别并转成 `inbound:<inboundId>` 的值。因此拖入后保存的草稿引用是**入站引用**，与"添加中转"流程（`createDraftSchemeForTargetNode`，同样产生绑定入站的实例）一致，不需要新的布局格式。
- 拖入语义（服务器方案）：拖入的实例是"该服务器的入口入站"，`role='entry'`；同一入站每个方案只加一次（重复拖入只选中已有实例并提示），因为入站是唯一的面板对象，不像导入节点那样可重复放置。为此 `onCanvasDrop` 识别新的 payload 字段 `entryBound`，并把角色规则改为 `entryBound || nodes.length === 0 ? 'entry' : 'relay'`；若 `inbounds` 里找不到该入站（资源尚未载入），拖入被拒绝，避免把 `inbound:` 误存成 `import:`。
- 已验证后端接受该引用（未改动后端）：`canvas.go:222 validateRefs` 只校验引用存在；`canvas_publish.go:343-368` 把布局里的 `inbound:` 实例当作"该节点被路由的入口入站"；`canvas.go:134 validate()` 接受 `inbound:` + 三种 role。但 `canvasInstanceNode()` 只把 `server:` 引用映射为节点，所以**任何一端是入站实例的连线在 plan/publish 时都会被拒绝**（"连接只能在两个受管服务器之间发布"）。
- 因此新增护栏：服务器方案下，从/向入站实例拖连线会被拒绝并提示"自建入站已绑定为所在服务器的入口，请在画布上使用「我的服务器」中的服务器节点连线"。**客户端方案不加此护栏**：`canvas_client.go:19 ValidateClientLayout` 要求实例引用是 `import:` 或 `inbound:`，客户端链本身就是一串入站/导入框，护栏只在 `executionLocation === 'server'` 时生效。
- 导入节点分组（机场/单独导入）改由重命名的 `importedNodes` computed 过滤，行为与之前一致；左侧库条目总数统计现在真实包含自建节点。

## 3. 空状态没有遮住资源库与属性面板

**根因**
- 覆盖层用的是 `bg-ios-background`，而 Tailwind 主题里只有 `ios-bg` / `ios-card`（`web/tailwind.config.js`），该类不存在 → 覆盖层透明；它仍是 `z-40` 的全屏层，所以看起来"面板还在、但点不动"，同时也把自建库挡成了不可用状态。
- 属性面板在 `currentScheme` 是占位对象（`emptyScheme`，`id === ''`）时照旧渲染"方案名称"（空输入）与"删除此方案"按钮，等于给不存在的方案提供删除入口。

**修复与决策**
- 覆盖层改为不透明 `bg-[#F5F5F7]`，仍是 `absolute inset-0 z-40`，并补上图标、说明文字与"新建方案"按钮；无方案时它覆盖整个工作区（含左侧资源库）。决策：不保留可用的资源库 —— 无方案时拖放只会写入内存中的 `emptyScheme` 占位对象（不会被保存），保持可拖反而是假象。
- 属性面板增加 `v-else-if="!currentScheme.id"` 占位块（"暂无中转方案：请先点击「新建方案」…"），"删除此方案"额外包在 `v-if="currentScheme.id"` 内，双重保险。

## 4. 导入来源的 kind：单独导入被算成机场订阅

**根因**
- 后端 `subscription_sources` 没有区分来源类型的列：机场订阅（HTTPS 拉取）与"导入节点"粘贴内容（`importAPI.create({content})`）都写同一张表，唯一的差别是 `url_encrypted` 里存的是什么 —— 内容导入写的是 `Vault.Seal([]byte(""))`（`Refresh` 正是靠解出来是空串来跳过拉取）。
- 前端 `loadImports()` 把所有导入节点一律标成 `sourceType: 'subscription'`，所以"机场订阅管理 (n)"把单独导入的节点也算了进去（走查里显示 `(1)`），而 `单独导入` 过滤器与画布的"单独导入节点"分组永远为空。

**后端改动（`internal/panel/subscription/importer/store.go`）**
- `Source` 新增只读字段 `Kind string \`json:"kind"\``（与 `lastFetchAt` 同一个 JSON 视图）。
- `List()` 追加读取 `url_encrypted`，用 `sourceKind(sealed)` 派生：解密后为空 → `"content"`；非空或无法解密 → `"url"`。
- **不加迁移**：现有列已能可靠区分（`last_fetch_at`/`last_status` 对两类都会写，所以不能作为判据；`url_encrypted` 的明文是唯一信号）。无法解密时按 `"url"` 处理 —— 只有链接型来源才真的持有链接。
- 新增回归测试 `TestSourceKindDistinguishesSubscriptionFromContent`：新建 URL 来源与内容来源 → kind 正确；改名/改间隔（不触碰 `url_encrypted`）后 kind 不变；JSON 视图同时含 `"kind":"content"`、`"kind":"url"` 与 `"lastFetchAt"`。

**前端改动**
- `ImportSource` / `SubscriptionItem` 增加 `kind?: 'url' | 'content'`；无字段（旧缓存或旧面板）按 `url` 处理。
- `loadImports()`：`proxySourceType(kind)` 把内容来源的代理节点标为 `sourceType: 'manual'`，URL 来源标为 `'subscription'`，并给每个来源写入 `kind`。于是画布"机场导入节点"只剩机场来源，"单独导入节点"不再为空，节点列表的"单独导入"过滤也生效。
- `airportSources()` + 页面内 `airportSubscriptions`：顶部"机场订阅管理 (n)"只统计 `kind === 'url'`。
- 单独导入来源仍需可管理：来源管理对话框改为"导入来源管理"，列出全部来源（每张卡片带 `机场订阅` / `单独导入` 标记、`内容导入` 状态徽标，内容来源隐藏"更新"按钮与 URL 字段并给出说明），编辑/删除仍走原来的 `startEditSub` / `saveEditSub` / `deleteSubscription`／`importAPI.update` / `importAPI.remove`，所以内容来源可改名、改间隔、删除。

**决策：`proxyNodeStore.subscriptions` 仍保存全部来源（带 `kind`），只在页面层过滤**
`web/src/modules/proxy/pages/LineGroupPage.vue` 用 `proxyNodeStore.subscriptions` 生成节点分组的"整源"成员，而该文件不在本次可编辑范围内。若把内容来源从该数组移出，单独导入的来源会从节点的线路分组里消失（`node_group_imports` 依然支持它们）。因此保持 store 形状不变，用 `kind` 在页面层划分展示与计数；机场订阅的列表/计数已按 `kind === 'url'` 过滤。

## 自检脚本

`web/scripts/canvas-library-selftest.mjs`（沿用其它 `*-selftest.mjs` 的做法：`typescript.transpileModule` + `data:` URL 导入纯 TS 助手，并对 Vue 单文件读源码断言）：

1. `listenNetworks()` 对 vless/trojan/shadowsocks/socks5/hysteria2/wireguard/forward 的返回值；`ProxyNodeListPage` 的自建块使用 `listenNetworks(ib)`、不含 `getTcpUdpSupport`、不含协议分支；猜测只出现在 `proxyNodes.guessProtocolNetworks()` 并被 `loadImports()` 使用。
2. `canvasLibrary.selfHostedLibraryItems()` 的真实运行结果（命名、地址、状态、停用/删除服务器过滤、搜索）；并用真实的 `api.canvasInstanceRef()` 断言每个条目保存为 `inbound:<inboundId>`（server 仍为 `server:`，导入节点仍为 `import:`）；断言画布页使用该助手、`entryBound` 拖入语义、入站实例护栏及其"仅服务器方案"条件。
3. 空状态：不再出现 `bg-ios-background`，覆盖层为不透明 `absolute inset-0 z-40 bg-[#F5F5F7]`，属性面板有 `v-else-if="!currentScheme.id"` 占位，删除按钮受 `v-if="currentScheme.id"` 约束。
4. kind 映射：`proxySourceType('content') === 'manual'`、`proxySourceType('url') === 'subscription'`、`importSourceKind()` 的兜底、`airportSources()` 只留 URL 来源；再用伪造的面板响应真跑 `loadImports()`，断言 `sourceType` 划分、导入节点的传输猜测结果，以及页面用 `airportSubscriptions` 计数、内容来源仍可删除。

## 已知限制与后续

- `kind` 是派生值：没有迁移、没有新列，因此无法区分"内容导入后又改成 URL 拉取"的中间历史（`Save` 传 URL 会当场变成 `url`），这是与服务端现有语义一致的唯一口径。
- 画布拖入自建入站只产生"入口入站"实例：如需中转必须同时拖入"我的服务器"里的服务器节点来连线；入站实例参与连线会被 plan/publish 拒绝，前端已在服务器方案中提前拦截。客户端方案保持原有"入站即一跳"的用法。
- 未在浏览器中重放走查流程（本地仅自检 + 类型检查 + 构建）；未做真机/发布验收，未提交。
