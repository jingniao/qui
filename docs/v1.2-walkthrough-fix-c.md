## 1. 问题与根因

### 1.1 工具栏按钮互相压住

`<header class="h-14 px-4 … flex items-center justify-between gap-3 shrink-0 z-30">` 是「固定 56 px + 单行 + 两个分组都 `shrink-0`」的组合：

- 左侧分组（资源库开关 + 方案胶囊 + 执行位置分段）与右侧分组（校验链路、保存草稿、检查、发布到服务器、分隔条、属性面板开关）在小屏上的最小内容宽度之和超过可用宽度；
- 父级是 `flex-nowrap`，两个分组都不能收缩、也不会换行，于是右侧动作组直接从左侧方案胶囊下方溢出（走查里看到的「选择…」压住图标），并被页面根容器的 `overflow-hidden` 裁掉一部分；
- 动作按钮的文字标签本来就是 `hidden sm:inline`，但「校验链路」「保存草稿」没有 `title`/`aria-label`，小屏上只剩无名图标。

### 1.2 资源库与属性面板互相覆盖、压住画布

左右两侧面板原先都是**参与 flex 布局的列**：左侧 `w-64`（256 px，xl 起 `w-72`）、右侧 `w-72`（288 px，xl 起 `w-80`），两者都带 `shrink-0`。256 + 288 = 544 px 已经大于 509 px 视口宽度，画布 `flex-1 min-w-0` 被压到 0 宽，两个面板在视觉上叠在一起并盖住整个工作区。

### 1.3 附带发现：画布底部提示压住缩放控件

画布左下角的「💡 提示：…」文案约 354 px 宽且没有响应式约束，底部固定 `bottom-4 left-4`；右下角缩放胶囊 `bottom-4 right-4` 约 160 px。509 px 视口下两者必然重叠（提示被画布裁切后仍横穿缩放控件）。

## 2. 实现

### 2.1 断点与面板状态（script）

```ts
const COMPACT_QUERY = '(max-width: 1023.98px)';   // 与 shell 的 lg:(1024px) 对齐
const compactMedia = … window.matchMedia(COMPACT_QUERY) …;
const compactViewport = ref(compactMedia ? compactMedia.matches : false);
const leftPanelOpen  = ref(!compactViewport.value);
const rightPanelOpen = ref(!compactViewport.value);
```

- **初始值即正确模式**：`matchMedia` 在 `setup` 阶段同步求值，窄屏首帧就是「两个抽屉关闭」，不会先闪出两个面板。
- **默认值随断点**：< lg 默认关闭（画布占满工作区），≥ lg 默认打开（Owner 的桌面工作室完全不变）。
- **跨断点 resize**：`applyCompactViewport()` 在进入抽屉模式时关闭两者，回到桌面时恢复两列；监听在 `onMounted` 用 `compactMedia?.addEventListener('change', …)` 注册，`onUnmounted` 注销。
- **互斥**：`toggleLeftPanel()` / `toggleRightPanel()` / `openLeftPanel()` / `openRightPanel()` 在 < lg 时打开一个即关闭另一个，避免两个抽屉在 320–509 px 上叠成一片；`closeDrawers()` 由背板调用。
- **`revealInspector()`**：桌面保留原有「选中节点 / 拖入已存在入站时自动展开属性面板」的行为（`rightPanelOpen.value = true`）；< lg 不自动弹出，否则点一下节点就在刚点过的拓扑上盖一层 320 px 抽屉，改由画布右上角的浮动「节点属性」按钮进入（该按钮本来就存在，只有面板关闭时显示）。

### 2.2 工具栏：< lg 换行，≥ lg 不变

```text
改前（单行固定高度，右侧动作组被挤到方案胶囊下方）
  h-14 px-4 … flex items-center justify-between gap-3 shrink-0

改后
  px-3 sm:px-4 py-2 min-h-[3.5rem] lg:h-14 lg:py-0
  … flex flex-wrap lg:flex-nowrap items-center justify-between gap-x-3 gap-y-2 shrink-0
```

- `flex-wrap` 只在 < lg 生效（`lg:flex-nowrap`），两个分组最小宽度放不进一行时自动落到第二行；`min-h-[3.5rem]` 保证单行时仍是 56 px，`lg:h-14 lg:py-0` 让 ≥ lg 的几何与改前逐像素一致（`px-3 sm:px-4` 在 lg 上等于原来的 `px-4`）。
- 左侧分组加 `flex-wrap … min-w-0`（内部也能换行，绝不溢出）；右侧动作组加 `ml-auto`，换到第二行时仍贴右。
- 「校验链路」「保存草稿」补 `title` + `aria-label`，并加 `!min-w-0 !px-2 sm:!min-w-[4.5rem] sm:!px-5`：`main.css` 的 `.ios-btn-secondary` 有 `min-width:4.5rem / padding:0 1.25rem`，图标态按钮原本至少 72 px；< sm 收窄到约 32 px（4 个动作共省下约 80 px），≥ sm 用 `!important` 覆盖回 4.5rem / 20 px，桌面完全一致。
- 「检查」按钮保留原有的 `hidden md:inline`：它调用的是 `checkScheme()`，与「校验链路」（`validateScheme()` → `checkScheme()`）是同一个动作，小屏上仍可通过「校验链路」触达，另外 4 个工具栏动作在 ≥ 320 px 上全部可见。

### 2.3 资源库 / 属性面板：< lg 覆盖式抽屉

```text
改前（参与的 flex 列）
  aside: transition-all … shrink-0 overflow-hidden bg-white border-r … flex flex-col z-20 shadow-xs
        :class="leftPanelOpen ? 'w-64 xl:w-72' : 'w-0 border-r-0'"

改后（< lg 绝对定位抽屉 + ≥ lg 原先的 flex 列）
  aside: … absolute inset-y-0 left-0 z-30 w-[min(18rem,85vw)]
           lg:relative lg:inset-auto lg:z-20 lg:shrink-0
        :class="leftPanelOpen ? 'translate-x-0 lg:w-64 xl:w-72'
                              : '-translate-x-full pointer-events-none lg:pointer-events-auto lg:translate-x-0 lg:w-0 lg:border-r-0'"
```

- < lg：`absolute inset-y-0` + `w-[min(18rem,85vw)]`（属性面板是 `right-0` + `w-[min(20rem,85vw)]`），关闭时 `translate-x-full/-translate-x-full` 滑出并被工作区的 `overflow-hidden` 裁掉 —— 绝对定位元素不参与 flex 布局，画布始终是唯一的流内子元素，宽度 100%（这正是「不再把画布压到 0」的关键）。
- ≥ lg：`lg:relative lg:inset-auto lg:z-20 lg:shrink-0` 恢复成原先的列，`lg:w-64 / xl:w-72`（左）与 `lg:w-72 / xl:w-80`（右）宽度、`transition-all` 收起动画、`w-0 border-r-0 / border-l-0` 全部保持原样。
- 面板内部固定宽度的容器（左 `w-64 xl:w-72` 2 处、右 `w-72 xl:w-80` 2 处）改为 `w-full lg:w-64 xl:w-72` / `w-full lg:w-72 xl:w-80`：抽屉里内容铺满 288/320 px，桌面仍是固定宽度（收起动画期间内容不重排）。
- **背板**：工作区第一个子元素新增 `v-if="leftPanelOpen || rightPanelOpen" class="lg:hidden absolute inset-0 z-[25] bg-black/25" @click="closeDrawers"`。点背板即关闭抽屉、把画布交回；`lg:hidden` 保证桌面上完全不参与命中测试。
- **z-index 层次（自上而下）**：空状态覆盖层 `z-40` > 抽屉 `z-30` > 背板 `z-[25]` > 画布内浮动控件/缩放胶囊 `z-20`。抽屉永远在空状态之下（无方案时的覆盖层行为未变），背板又能盖住画布控件。
- 抽屉宽度：左 `min(18rem,85vw)`、右 `min(20rem,85vw)`，509 px 上分别是 288 / 320 px，320 px 视口上是 272 px，始终留出可见的画布边缘提示抽屉是浮层。

### 2.4 画布底部提示

`absolute bottom-4 left-4 … flex items-center gap-2` 改为 `hidden lg:flex …`：< lg 不再与右下角缩放胶囊抢同一条底边，≥ lg 一字不差地保留。

### 2.5 无障碍

- 两个面板开关补 `:aria-expanded`，`title` 仍是「收起/展开资源库」「收起/展开属性面板」。
- 小屏只剩图标的两颗按钮（校验链路、保存草稿）有 `title` + `aria-label`。
- 背板 `aria-hidden="true"`（纯鼠标/触摸关闭手段，抽屉自身有「收起」按钮）。

### 2.6 明确未改

画布数据与拖拽/连线手势、`useTunnelPlan` / 发布计划与发布代码、`v-if="!currentScheme.id"` 空状态覆盖层及其文案、`MainLayout.vue`（`pt-16` 与固定的 ☰ 按钮）、全局 `ios-btn-*` 样式、任何后端与迁移。

## 第二轮（1120 px）

**日期：** 2026-10-29
**范围：** 同一页面（`/proxy/relay` 中转画布工作室）在 1120 px 视口下：shell 侧栏展开占 272 px，工作室实际可用约 850 px，两个面板仍在停靠状态
**状态：** 本地实现并验证（源码自检 + `vue-tsc` + `vite build`）；未提交、未发布

### 1. 现象与根因

第一轮把紧凑断点放在 lg（1024 px），只覆盖了 509 px 那一类窄视口。1120 px 落在「桌面布局」一侧，于是三处重叠同时出现：

| 位置 | 现象 | 根因 |
| --- | --- | --- |
| 顶部工具栏 | 方案切换器（`演示 · 新加坡中转 · 演示 · VLESS 接…` / `草稿` / `+`）压住「校验链路」 | `lg:flex-nowrap` 让两个分组都不能收缩，方案名 `md:max-w-[260px]` 又吃掉整行剩余宽度；左分组内部还在换行，栏高却被 `lg:h-14` 固定成 56 px，第二行溢出到下面的面板上 |
| 顶部工具栏 | 「客户端执行 / 服务器执行」分段控件排到第二行，压在「拓扑资源库 … 拖拽上画布」标题上 | 分段控件本身是流内元素，但被固定的 56 px 栏高挤出工具栏的可视区，看起来像浮在资源库面板头部 |
| 画布底部 | 「💡 提示：从绿色右锚点…」压住缩放胶囊（`+ 100% − 居中`） | 停靠布局下 1120 px 的画布只剩约 400 px（850 − 288 − 320），提示约 354 px 加胶囊约 166 px 必然重叠 |

根因不是某个按钮，而是「桌面布局」的阈值选错了：工作室是「左 288 + 右 320 + 画布」的三栏，加上 shell 的 272 px 侧栏，至少需要约 1280 px 视口才有可用画布。

### 2. 实现

#### 2.1 断点从 lg 移到 xl

```ts
const COMPACT_QUERY = '(max-width: 1279.98px)';   // 与 Tailwind xl:(1280px) 对齐
```

- 页面里所有 `lg:` 类改为 `xl:`（自检断言 `canvas.includes('lg:') === false`，防止回退）。
- < xl：资源库与属性面板都是覆盖式抽屉（默认关闭、互斥、点背板关闭），画布占满工作室；工具栏随内容增高换行。
- ≥ xl：仍是原来的停靠两栏（左 `xl:w-72`、右 `xl:w-80`），几何与之前 xl 时完全一致。

#### 2.2 工具栏：< xl 换行，≥ xl 单行并截断方案名

| 元素 | 改前 | 改后 |
| --- | --- | --- |

- 1120 px：工具栏变两行——第 1 行资源库开关 + 方案胶囊（名字最多 260 px）+ 分段控件，第 2 行是靠右的动作组；`min-h` 允许增高，不再有元素被挤出或压住面板。
- 1280 px：单行。左侧分组 `xl:flex-1 min-w-0`，其余项都是 `shrink-0`，所以唯一的收缩项是方案名：它带 `truncate`（`overflow:hidden` 使 `min-width:auto` 归零）和 `xl:max-w-[7rem]`，空间不足时显示省略号，完整名字在 tooltip 里。
- 1280 px 的宽度账（估算：CJK 按 1em、`text-xs` 12 px、`ios-btn-*` 内边距 20 px）：内容区 1280 − 272（侧栏）− 32（左右内边距）= 976 px；左侧分组最小内容约 433 px（开关 90 + 分隔 1 + 胶囊 142 + 分段 170 + 间距 30），动作组约 477 px（校验 106 + 保存 106 + 发布 130 + 分隔 1 + 属性开关 102 + 间距 32），合计 922 px，剩约 54 px 给方案名，因此不会溢出到动作按钮上。

#### 2.3 底部提示：只在画布够宽时出现

`hidden lg:flex` → `hidden sm:flex xl:hidden 2xl:flex` + `max-w-[calc(100%-12rem)]`：

- < xl（面板是抽屉）：画布等于整个工作室宽度，≥ 640 px 时提示与约 166 px 的缩放胶囊不会相撞；
- xl–2xl（两栏停靠、画布约 400 px）：提示隐藏，缩放胶囊独占右下角；
- ≥ 2xl（画布约 656 px）：提示回来，`max-w` 保证末行不进入胶囊区域。

#### 2.4 顺带修掉的隐藏问题

「检查」按钮原本写成 `class="ios-btn-secondary … hidden md:inline"`。构建产物里 `.hidden{display:none}` 在样式表第 9068 字节处，而 `.ios-btn-secondary{display:inline-flex}` 在 59129 字节处：同特异性下后者胜出，`hidden` 对它从来没生效过（标签文字靠 `hidden sm:inline` 的 `<span>` 才真的隐藏）。这一轮需要它让出约 74 px，所以把可见性交给无竞争样式的 `<span class="hidden 2xl:inline">` 外层，自检里同时断言旧的 `ios-btn-secondary !py-1 text-xs hidden` 写法不再存在。
