## 尚未完成及原因

1. **真实客户端 HTTP/握手、P1/P2/P4 流量、导入 SS2022/Reality/xhttp 端到端消费、新旧公钥认证。** 计划只使用本轮临时用户、测试端点，在 Owner 既有 Linux 测试机 `192.168.5.36` 运行 Mihomo。自动审批两次拒绝“把生产生成的订阅配置与凭据传到另一台测试机”，第二次即使核实该用户仅授权临时分组、无既有用户凭据也仍要求 Owner 明确确认数据与目的地。已发送具体确认请求，尚无答复；没有执行配置导出或传输，也没有改走其他通道。受控回环目标曾启动，只验证它自身可用，不能算代理流量通过；已停止。
2. **P3 公网接收中转与三跳 GOST。** Alpine 仅 `10.111.111.41` 私网地址、无公网 IPv6 或入站覆盖，不能承担原方案的公网接收跳；且它未上报 GOST 安装能力。需要可达中转主机（GOST 路径还要求支持 GOST 的 linux/amd64），不能把现有三台的控制连接在线视为此路径可用。已询问 Owner 是否提供额外主机，尚无答复。
3. **完整 A1 和正式发布。** 上述数据面路径未完成，首次应用失败首因未定；完整 v1.4 浏览器、混合流量 soak、二进制版本降级演练也未执行。本轮验证了配置回滚、失败批次自动回滚和同版本加密备份恢复，没有执行 1.4→1.3 的程序/数据库降级。

本轮遵循 Owner 精简测试要求，没有重跑全仓库 race 或 GitHub gate；早前 Linux 实核证据见[协议验证](v1.4-protocol-verification.md)。本轮原始 JSON、升级日志、加密备份副本与脚本在本机忽略目录 `.tools/a1/`，远端构建日志在 Linux 测试机 `/root/qui-a1/`。这些目录可能含临时或历史配置材料，不作为公开附件。
