# M4 sing-box Reality adapter: local evidence and limits

Date: 2026-11-05. Base: M1 correction commit `4cece33`. Root approved the adapter
and focused evidence for a local phase commit on `feat/v1.4-selfhost-m4`;
the Linux gate is pending.
This is an Agent adapter result, not completed M2 public subscription mapping,
M3 editor support, S5 acceptance or production deployment.

The adapter renders VLESS Reality over TCP with no flow or
`xtls-rprx-vision`. It requires exactly one concrete server name and preserves the
entire ordered ShortID list. Multiple names, conflicting legacy server name,
Reality over gRPC, and xhttp are rejected explicitly. The shared
`ValidateCoreServerSettings` restriction is called by the save/snapshot/deploy
contract gate and by the renderer, without restricting Xray's separate model.

## Capability authorization

Detection reads the core banner for existing protocol/build facts, then creates
temporary random X25519 keys and passes each candidate through the production
typed renderer and the installed executable's `check -c` command independently.
Only a successful native result adds the corresponding exact inbound combination
to contract version 1. If all candidates fail, contract version remains zero.
The probe binds no listener and uses no remote target. Temporary native files
use the existing private configuration writer and are removed immediately.

`Adapter.Render` requires the resulting probed report before accepting Reality.
Pure rendering tests exercise mapping independently, while native-probe tests
prove that failure of Vision or both combinations removes those authorizations.
A version string alone never declares the contract. Nothing declares xhttp or
Reality outbounds.

## Native and connection evidence

Command, with the cached executable configured in `SINGBOX_BINARY`:

```powershell
go test ./internal/agent/core/singbox ./pkg/contracts/desiredstate -run 'Test(Reality|RealReality|SingboxReality)' -v -count=1
go test ./internal/agent/core/singbox -run '^TestRealSingboxXHTTPRemainsUnavailable$' -v -count=1
```

| Combination | Native server/client checks | Authenticated HTTP | Negative/history checks |
| --- | --- | --- | --- |
| Reality + TCP, no flow | Pass | Pass, exact random nonce response | Both configured ShortIDs connect; wrong VLESS UUID gives no origin hit; failed apply restores old keys; key rotation and explicit rollback restore original revision |
| Reality + TCP + Vision | Pass | Pass, exact random nonce response | Same independent checks |
| xhttp | Native rejection | No connection attempted | Agent typed rejection and no capability declaration |

The final full Reality probe took **7.740 s**; its real-core subcases were
**3.73 s** (no flow) and **3.89 s** (Vision). Each subcase recorded exactly four
origin hits: two valid ShortIDs, original-key access following failed apply,
and original-key access following rotation/rollback. The wrong UUID adds zero.
The standalone native xhttp negative passed in **0.200 s**.

The handshake target is a temporary loopback TLS 1.3 server with HTTP/2 and
X25519. The HTTP origin is a separate loopback listener serving only a random
nonce path. Clients connect to loopback and use a public-key/SNI/ShortID/uTLS
fixture, without the server private key or insecure TLS switches. Random keys,
credentials and complete generated configuration are never printed or checked
into the repository. All processes and temporary files belong to test cleanup.

This official binary lacks `with_v2ray_api`: the test confirms account telemetry
is unavailable and `TrafficCounters` returns `ErrTelemetryUnavailable`.
It does not report zero user traffic. The test includes a conditional measurement
assertion for a stats-enabled build, but that branch was **not exercised here**;
Reality user-byte accounting on qui builds is still unverified by this report.

Unit coverage also checks exact typed server mapping, no ordinary TLS certificate
branch, no client public-key field in native server configuration, no mutation of
input/historical keys, field/combination rejection, and native-probe failures.
M1's API masking, encrypted archive and revision-diff protections remain in place.

Additional local regressions, without a real-core environment variable, passed:
entire desiredstate **0.486 s**, sing-box **0.445 s**, node **13.720 s**, proxy
**29.386 s**, and deployment **18.524 s** packages. The proxy/deployment suites
include existing private-key masking, revision-diff and capability gates.
These tests do not substitute for a Linux gate or real-core tests skipped when
their environment variables are absent.

## Remaining acceptance

- Linux and arm64 executions, stats-enabled build measurements and device-gate
  coverage for these new combinations are not established here.
- The shared client model/codecs, published and relayed subscription mapping,
  key generation UI and layered editor diagnostics remain with M2/M3/S3/S4.
- The protocol table's global pending status is retained while those product
  paths remain incomplete. The Agent's exact capability report is the authority
  for this adapter's available server settings.
- No production node, real external subscription, remote gate, release, push or
  deployment was touched.
