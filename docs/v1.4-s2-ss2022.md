## Implemented scope

The importer accepts typed SS2022 AES-256, AES-128 and ChaCha20 credentials through
the existing URI, Base64-document and Clash parsers. It reuses the neutral
`Method` and `Credential.Password` fields and encrypted cache; no schema migration
or opaque configuration map is needed. The cipher is normalized to lowercase;
PSKs and their order are preserved exactly.

`proxy.ValidateShadowsocks` validates standard padded Base64 and exact decoded
key lengths: AES-128 uses 16 bytes, AES-256 and ChaCha20 use 32. Every identity
segment is checked. The initial measured subset is a single key or exactly
`serverPSK:userPSK` for AES; ChaCha20 identity and more than two segments have
explicit rejection codes. The endpoint-level `Proxy.Shadowsocks` check also
rejects unrepresented TLS, transport, flow and unrelated credential options, so
exporters cannot silently discard required settings.

Plain/percent-encoded userinfo and padded/unpadded standard/Base64URL **userinfo
wrappers** are accepted on input. This compatibility does not relax the PSK's
own standard padded Base64 requirement. A plain standard-Base64 password may
contain `+`, `/`, `=` and the identity separator `:`. Encodings normalize to the
same SS2022 neutral credential. Nonempty SS2022 URI query options and paths other
than the optional SIP002 `/` are rejected rather than ignored.

SS2022 URI output is always the SIP002 plain form. Method, password and tag use
RFC3986 percent escaping; `+`, `/`, `=`, the inner identity `:` and spaces become
`%2B`, `%2F`, `%3D`, `%3A` and `%20`. The literal method/password separator remains
`:`, and Base64 subscription output wraps this same URI document. Non-SS2022
export forms retain their existing encoding.

The format helper implements only the per-client evidence from
[S0 §8](v1.4-s0-evidence.md#8-capability-conclusions-s1s4-may-rely-on-per-client):

| Cipher / credential | URI / Base64 | Mihomo | sing-box | Legacy Clash |
| --- | --- | --- | --- | --- |
| AES-256 single key | emit | emit | emit | omit |
| AES-256 two-key identity | emit | emit | emit | omit |
| AES-128 single key | emit | emit | emit | omit |
| AES-128 two-key identity | emit | omit: unverified | emit | omit |
| ChaCha20 single key | emit | emit | omit: unverified | omit |
| ChaCha20 identity / longer chains | reject import | — | — | — |

An unverified format combination is omitted individually with an Owner warning;
usable endpoints remain. Existing Clash member/dependency filtering and
`emptyPolicy=reject` handling remain in effect. Invalid key material or internal
SS2022 settings cause an error, separately from a normal capability omission.

Backup verification rejects unknown payload fields and trailing JSON values,
then uses the same importer/SS2022 semantic validation for new SS2022 payloads.
Existing pre-0133 archive compatibility is covered by the retained import tests.
The new safe diagnostic codes are part of the existing bounded result verifier.

Self-hosted SS2022 is not enabled: desiredstate, server settings, credential
generation, Agent rendering and self-hosted protocol allowlists are unchanged.
Imported endpoints retain the existing authorization, metering and device-gate
boundaries.

## Synthetic fixtures and local checks

`internal/panel/subscription/importer/testdata/ss2022.uri` contains the three
synthetic AES-256 entries defined by [the S0 manifest](v1.4-s0-fixtures.md#1-ss2022-aes-256-3-entries):
two distinct single-key endpoints and one two-key identity. All keys are public
deterministic fixture bytes; no real provider material is used.

Focused Go suites passed on Windows/amd64 using the repository's Go toolchain:

```text
go test -count=1 ./internal/panel/subscription/importer \
  ./internal/panel/subscription/proxy ./internal/panel/subscription/format/...
go test -count=1 -run TestImportBackup ./internal/panel/system/backup
```

Coverage includes all three fixtures through URI/Base64 round trips and encrypted
persistence, authorization isolation, Clash input, invalid key encoding/length
in every segment, identity-depth limits, partial import success, format-specific
omissions, chain dependency cleanup, preserved REJECT empty groups, archive
acceptance and archive corruption rejection. `git diff --check` passes.

The broader Windows backup suite was attempted. Its existing restore-stage and
canvas tests fail with `Access is denied` during filesystem/hardlink operations.
The focused import backup tests pass; no unrelated backup code was changed to
work around Windows behavior.

## Actual connection evidence and remaining gate work

The new environment-gated `TestRealSS2022ImportedAES256Connections` is discovered
by the existing `scripts/real-core-packages.sh` mechanism. It uses only loopback
and ephemeral test ports. It renders the real exporter output and performs native
checks before launching clients. Each cell requires an HTTP response containing
a unique test nonce **and** an authenticated Shadowsocks server log naming that
origin. A wrong-key control must fail without an origin hit. Readiness TCP probes
do not satisfy either success condition.
