# S4: typed xhttp imports and measured format filtering

This phase builds on S3 commit `08e0a67`. It adds URI/Base64 and Clash xhttp
imports through the shared public `Transport.XHTTP` model. Host and TLS SNI are
independent; an empty path is retained; mode must be explicitly one of `auto`,
`packet-up`, `stream-up`, or `stream-one`. VLESS flow is rejected for gRPC/xhttp.
URI export preserves host/path/mode. Unknown advanced `extra` settings are
rejected with bounded, fixed diagnostics; no raw extension map is persisted.

Mihomo output permits only Reality + xhttp `auto` with exactly `alpn: [h2]`,
consistent with the S0 measured boundary. Other xhttp modes, TLS-only xhttp,
sing-box and legacy Clash omit the endpoint with warnings. Filtering retains
ordinary endpoints, client-chain dependency cleanup and explicit REJECT policy.

## Verification and limits

- Eleven synthetic fixtures cover four auto, three packet-up, two stream-up and
  two stream-one entries, each with a distinct identity/name/port. Tests verify
  codec fidelity, independent host/SNI, empty paths, IPv6/escaped paths, rejection
  of unmodeled extensions and misplaced fields, and format filtering.
- Actual backup Create/Examine verifies that encrypted xhttp payloads retain
  transport host separately from SNI, explicit empty path, and mode.
- Windows subscription unit suites and focused Reality/xhttp/import-backup tests
  passed. Full backup tests retain the S3 Windows restore-stage permission limit.
- `TestRealRealityGeneratedExporterConnections` consumes actual generated output.
  Cached Windows Xray 26.3.27 + sing-box 1.14.3 passed Reality TCP Vision native
  checks and authenticated HTTP. Wrong-user control reached no origin; the valid
  request matched both the unique origin response and Xray authenticated-user
  access evidence (one origin hit).
- The same test includes generated Mihomo TCP Vision and xhttp-auto cells;
  Windows has no configured Mihomo binary/home, so these cells were skipped.
  They remain pending a pinned real-core run. The xhttp cell checks an independent
  transport Host against the server, rather than relying on its default.
- No claim is made of a URI-consuming client's import of GR02 or xhttp links.
  URI results establish codec fidelity, not that additional runtime evidence.
- No Linux gate, browser walkthrough, real-source fetch, production action, or
  complete S5 acceptance was performed.
