## 1. 保存节点组时自动下发凭据

状态：已实现（待审查）

### 1.1 现状与问题

用户凭据进入节点有两条路径：

1. 手动发布节点：按草稿渲染，带上当时经节点组授权的全部用户凭据。
2. 自动额度版本（`internal/platform/server/quota.go`，说明书 §22.1）：用户新建／修改、授权或撤销节点组（`POST/DELETE /api/v1/users/{id}/node-groups/{groupId}`，节点组页「授权账号」也走它）、凭据重置时，`user.Handler.AccessChanged` → `quotaDeployer.accessChanged` 排队，60 秒合并后只对用户访问面不一致的节点生成 Revision。

保存节点组（`POST /api/v1/node-groups`、`PUT /api/v1/node-groups/{id}`，`internal/panel/node/handler_groups.go` 的 `saveGroup`）和删除节点组（`deleteGroup`）只写库与审计，**不触发自动版本**。节点组页的分组编辑弹窗（`LineGroupEditor.vue`）与入站编辑器的「所属节点组」（`NodeEditorDrawer.vue`）都调用这两个接口。

后果：用户已授权某组后，再把一个**已发布**的入站加入该组，节点上没有该用户凭据；订阅生成要求“已发布凭据”（§10.3 第 10 步），所以该端点不会出现在订阅里，直到 Owner 手动发布该节点。这与 §10.1“组内新增可用接入后，用户刷新订阅即可获得，无须重新授权”的预期不一致。反方向同理：把入站移出组、禁用组、改用途或订阅可见、删除组之后，已发布凭据要等下一次手动发布或其他自动版本才被移除（订阅侧会立即不再输出，但节点仍接受该凭据）。

### 1.2 目标

保存或删除节点组后，受影响用户的凭据按自动额度版本的同一机制增减，无须手动发布；订阅与节点实际接受的凭据在一个合并窗口内一致。

### 1.3 方案

- `node.Handler` 增加回调 `GroupAccessChanged func(ctx context.Context, groupID string, userIDs []string)`，由 `internal/platform/server/server.go` 装配到 `quotaDeployer`（新增按用户批量调用 `accessChanged` 的薄方法，reason 用 `node group updated`／`node group deleted`）。不让 node 模块直接依赖 server 或 user 模块（说明书 §24）。
- 受影响用户 = 该组 `user_node_group_grants` 中的用户。保存时在提交后读取（保存不改授权）；删除时必须在删除**前**读取授权列表，删除成功后再回调。
- 只在保存／删除成功且审计写入后回调；失败不回调。回调本身只排队，不阻塞响应，不改变接口返回体与状态码。
- 只调度，不新增判定：节点集合沿用 `schedule` 的“当前授权节点＋已发布状态仍持凭据的节点”，对账照旧只对不一致节点生成 Revision，内容未变的保存不发版。基线、草稿例外（只带出用户／入站绑定）、启用意图取自已发布基线、连续 3 次失败告警等规则全部不变。
- 未发布的入站不在已发布基线里，加入组也不会被自动版本带上线，仍须手动发布该入站，这一点不变。

### 1.4 不在本项

- 节点本身的维护、禁用、`allow_subscription` 变化，以及入站 `subscriptionVisible`／`allowedUserIds` 的草稿修改，同样影响 `UserInboundGroups`，但它们属于节点或入站的发布流程，本项不改。
- 不改 60 秒合并窗口、不改订阅过滤规则、不新增迁移。

### 1.5 测试与验收

- 单元／集成（`internal/platform/server`）：
  - 用户已授权组 A，已发布入站 X 加入 A → 一个窗口内 X 所在节点生成 `auto:` Revision 且带该用户凭据；订阅出现 X。
  - X 移出 A、A 停用、A 改为 relay、A 删除 → 对应节点自动 Revision 移除凭据；订阅不再输出。
  - 只改名称／备注的保存 → 对账一致，不生成 Revision。
  - 组无授权用户 → 不调度。
  - 未发布入站加入组 → 不生成带该入站的 Revision。
  - 保存失败（400／404）→ 不调度。
- 前端无改动；`docs/install-guide.md` §6 与说明书 §10.1 补一句“保存节点组后凭据自动下发，约一个合并窗口生效”，删除“需要再手动发布”的说法。
- 门禁：改动 Go，走完整门禁（`scripts/check.sh` ＋ GitHub `check`）。

## 2. 节点连接地址：自动探测并支持域名

状态：已实现（B1 后端＋B2 前端，待审查）

### 2.1 现状与问题（2026-11-09 实机诊断）

在一台全新安装的主机（面板 1.4.6 ＋ Agent 1.4.5 同机）上：入站已发布成功（修订 7），也已加入 `subscription` 用途的节点组，用户已授权，但订阅为空；节点详情里的地址显示为主机名 `v2202410238878291989`。数据库中该节点的 `nodes.public_ip` 为空。

根因：

- Agent 从不填写 `Heartbeat.public_ip`（`internal/agent/capability/metrics.go` 只填指标，`internal/agent` 里没有任何代码设置 `PublicIp`），`Hello` 也没有这个字段。面板虽然会接收并保存这个值（`internal/panel/node/control.go`、`node/repository.go:285`），但实际收不到。`public_ip` 只能由 Owner 在节点设置的「订阅接入 IP」里手工填写，而且只接受 IP（`node/settings.go:54`）。
- 订阅在 `public_ip` 为空时**静默丢弃**该节点的全部端点（`internal/panel/subscription/source/published/published.go:122`），不报错也不给提示。
- 页面在地址为空时回退显示主机名，甚至 `127.0.0.1`（`ProxyNodeListPage.vue:1322`、`NodeEditorDrawer.vue:56`），看起来像“有地址但不对”，掩盖了真正的原因。
- 安装指南和注册流程都没有提到要填这个字段。

### 2.2 方案

1. **Agent 上报候选地址**：新增可选的 proto 字段（只做加法），Agent 上报默认路由网卡上的全局单播 IPv4/IPv6，排除私网、链路本地、docker/bridge 等地址；面板同时记录 gRPC 连接的对端地址（是公网地址时才记）。
2. **面板自动填写**：只在 `public_ip` 为空、且 Owner 没有手工设置过时，按“上报的公网 IPv4 → 连接对端公网 IPv4 → 公网 IPv6”的顺序自动填写。手工值永远优先，需要一列来区分“自动”还是“手工”（新迁移 0135）。接口的语义是“提交非空 IP 即手工”，所以 B2 的节点设置表单只在 Owner 改过地址时才提交 `publicIp`（或直接省略该字段），否则把自动填好的值原样回传会被当成手工值。
3. **支持域名**：新增节点级的「客户端连接地址」，可填域名或 IP，订阅和分享链接优先用它，`public_ip` 继续用于中转和隧道。域名格式校验沿用 `install_endpoint` 的规则。第 4 节自动申请证书后，可以把证书域名一键设为连接地址。
4. **不再静默**：节点没有可用地址时，节点详情、入站编辑器和订阅预览显示「未设置连接地址，订阅不会包含该节点」，并链接到设置项；页面不再回退显示主机名或 `127.0.0.1`。订阅预览的警告列表也带上这一条。
5. 文档：安装指南第 4、6 节写明连接地址的来源和手工修改方法。

### 2.3 验收

- 全新安装、不做任何手工设置：节点上线后自动得到公网 IPv4，订阅能输出端点。
- 手工改过的地址不会被自动探测覆盖；清空后恢复自动。
- 设置域名后，订阅和分享链接使用域名；TLS 的 SNI 规则不变。
- 只有私网地址（例如 NAT 后的 LXC）时不自动填写，页面明确提示需要手工设置。

## 3. Hysteria2／TLS 入站的证书与域名：说清楚怎么填

状态：已实现（C1 后端与 Agent、C2 编辑器，待审查）

### 3.1 现状

Hysteria2 强制使用 TLS。编辑器要求「服务器名（可选）、证书 PEM（首次必填）、私钥 PEM（必填）、可信 CA（可选）」，但没有说明这几项之间的关系；只支持粘贴证书内容，不支持节点上的文件路径，也没有自动申请证书或一键自签（自签目前只用于内部中转入站，`internal/panel/proxy/tls.go`）。客户端校验证书时要求：客户端连接的域名（或 SNI）必须在证书的覆盖范围内，而且证书必须受客户端信任。

### 3.2 方案：编辑器改为“证书来源”四选一

| 来源 | 适用场景 | 需要填写 |
| --- | --- | --- |
| 自动申请（第 4 节） | 有自己的域名，DNS 托管在 Cloudflare | 只填域名 |
| 节点上的文件路径 | 节点上已经有证书（例如 certbot 或 acme.sh 签发的） | 证书路径、私钥路径 |
| 粘贴内容 | 现有方式 | 证书 PEM、私钥 PEM |
| 自签名 | 没有域名，只用 IP | 不用填；订阅只在 sing-box 和 mihomo 格式里输出（带证书或指纹），URI 格式会省略 |

- 每种来源都配一段说明：域名必须解析到这台节点（Hysteria2/TUIC 走 UDP，Cloudflare 的橙云代理不支持 UDP，必须用灰云，也就是“仅 DNS”）；服务器名留空时等于连接地址。
- 保存时检查证书是否覆盖了服务器名或连接地址，不覆盖就提示；同时显示证书的到期时间。

### 3.3 证书文件路径

- 面板只保存两个绝对路径。证书由 Agent 在应用配置时读取并校验（证书与私钥是否匹配、是否过期、是否覆盖域名），校验失败按原有规则拒绝应用、保留上一次成功的配置。
- 渲染时使用核心原生的文件路径字段（sing-box 的 `certificate_path`/`key_path`，Xray 的 `certificateFile`/`keyFile`），由核心自己读取，私钥不经过面板。
- 安全边界：只允许 `/etc/proxy-agent/certs/` 下的路径，拒绝 `..` 和符号链接越界，要求私钥文件权限不宽于 0640；Agent 进程必须能读到这些文件。安装器负责创建这个目录。
- Agent 在能力上报里声明是否支持文件路径（一个新的能力位），旧 Agent 不能保存这种入站。
- 证书文件被外部工具续期后：先实测 sing-box 和 Xray 能否自动重新加载；不能的话，由 Agent 检测到文件变化后只重启对应核心，不生成新的配置版本。
- 心跳上报证书摘要（主题、SAN、到期时间、指纹），节点详情据此显示到期时间，到期前 14 天发出告警。

## 4. 自动申请与续期证书（Cloudflare DNS-01）

状态：已实现（D1、D2 后端，D3 页面，待审查）

### 4.1 目标

Owner 在系统设置里保存一次 Cloudflare API Token，之后在入站里只填一个域名，面板就会自动申请证书、填入入站并在到期前自动续期；还可以选择自动把这个域名的 A/AAAA 记录指向节点的连接地址。

### 4.2 设计

- **在哪里申请**：在面板上统一申请。DNS-01 验证不需要节点开放 80 端口，Cloudflare Token 也只保存在面板一处，不分发到每台节点。
- **系统设置 →「证书与 DNS」**（只有 Owner 可见，写操作需要 CSRF 并记操作日志）：
  - Cloudflare API Token：用 vault 加密保存，读取时只返回“已设置”和末 4 位，不回显；保存前调用 Cloudflare 接口验证 Token 是否有效。建议使用只授予 `Zone:DNS:Edit` 权限的 Token，不要用 Global API Key。
  - ACME 账户邮箱。
  - CA：Let's Encrypt 正式环境，或测试用的 staging 环境。
- **证书库**：新迁移增加 `certificates` 表，字段包括域名列表、状态、到期时间、加密保存的证书和私钥、上次错误、下次续期时间、关联的入站等。入站通过 `certificateId` 引用证书，不复制 PEM。
- **申请流程**：创建 TXT 记录 → 等待 DNS 生效 → ACME 验证 → 签发证书 → 删除 TXT 记录。失败时返回固定的错误代码和中文说明，不回显上游返回的原文和 Token；状态通过 SSE 推送。
- **下发到节点**：
  - 第一阶段：证书作为加密材料写进 DesiredState，签发或续期后，像自动额度版本那样自动为引用这个证书的节点生成一个配置版本。代价是发布会重启该节点的全部核心，现有连接会短暂中断，所以续期发布放在 Owner 设定的低峰时段。
  - 第二阶段（可选）：新增一个固定的 Agent 操作“更新证书”，只替换运行目录里的证书文件、触发核心热加载，不生成新版本也不重启。这需要新增 proto 命令，并且要通过安全评审（属于说明书 §23 的白名单固定操作）。
- **续期**：到期前 30 天开始续期，失败按 1 小时 → 6 小时 → 24 小时退避；剩 7 天还没续上就发 `system.alert` 告警。面板离线期间不会续期，节点继续使用已有证书。
- **可选：自动 DNS 记录**：勾选后，用 Cloudflare 把域名的 A/AAAA 记录写成节点连接地址，代理状态设为关闭（灰云）；连接地址变化时同步更新。默认关闭，避免改掉 Owner 已有的记录。
- **备份**：证书库和 Token 都随加密备份保存和恢复；恢复后不自动重新申请，按到期时间正常续期。
- **依赖**：ACME 协议准备使用 `golang.org/x/crypto/acme`（Go 官方扩展库；这是新增依赖，需要 Owner 批准），Cloudflare 接口直接用 `net/http` 实现，不引入 lego 这类大型第三方库。

### 4.3 验收

- 在 staging 环境完成一次申请、一次强制续期和一次失败退避（例如 Token 无效）。
- 入站引用证书 → 订阅能输出端点 → 客户端不需要额外信任 CA 就能连上 Hysteria2 和 VLESS-TLS-xhttp。
- 续期后节点自动换上新证书，客户端无需改动。
- 备份恢复后证书和 Token 可用，Token 不出现在任何 API、日志或预览中。

## 5. 附带核查

- 实机上的修订 6（`auto: user amdin updated`）一直停在 `draft` 状态：它在修订 5 部署期间生成，之后被手动发布的修订 7 取代。需要确认自动额度版本遇到“部署占用”时会不会留下孤立的草稿修订，以及下一个合并窗口能不能正确重建（说明书 §22.1）。

  A2 结论（2026-11-09，不涉及代码改动）：这个孤立草稿只是显示层面上的残留。节点的“占用”只来自 `deployment_targets`／命令／批次，没有任何路径会去部署最新草稿；下一个合并窗口按当前已发布状态重新渲染，一致就不发版，不一致才新建修订并把它留在原地。现有测试 `internal/platform/server/quota_test.go`（约 697–743 行）已固定“占用时留草稿、恢复后不部署过期草稿”的行为，因此不修。
- 订阅格式：xhttp 在 URI/Base64 格式下可以输出；在 mihomo 格式下只输出 Reality＋auto 模式；sing-box 格式不输出 xhttp。订阅预览要把被省略的原因明确展示给 Owner（目前只有警告文字）。
