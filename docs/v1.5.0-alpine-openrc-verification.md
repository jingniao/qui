## 产品缺陷与其他观察

**缺陷：调优键可写性探测忽略 `/proc/sys` 下的只读子挂载。**

复现步骤：

1. 在隔离 mount/net 命名空间内，将 `/proc/sys/fs` 绑定到自身并 remount 为 ro，同时保留 `/proc/sys/net` 可写。
2. 启动此快照 Agent，读取节点 API 的 `capabilities.host.tuningKeys`。
3. 比较 `fs.file-max` 的上报与 `test -w /proc/sys/fs/file-max`、不写内容的 O_WRONLY 打开结果。
4. 实际挂载只读、打开返回 EROFS，上报却为 `present=true,writable=true`；容器重启后仍能复现。

只读源码核对：`internal/agent/capability/tuning_env.go` 中 `procSysReadOnly` 只匹配挂载点恰为 `/proc/sys` 的记录；`tuningKeyStates` 为所有存在键复用这个全局只读判断，未按具体路径处理更深的挂载点。因此本环境中的保护挂载未被识别。可能导致界面把实际不可写键当作可编辑参数。本轮未向该全局键发送调优请求，也未修改产品。证据：`B-key-comparison.json`、`B-visibility.txt`、`runtime-investigation.txt`、`node-after-reboot.json`。

另有未定因观察：`OpenRC-messages.log` 在 15:56:18、15:56:48、15:57:18、16:00:12 出现 `telemetry observations rejected during parsing attribution or submission` WARN，count 分别为 12、14、11、6。未影响本轮调优回执、发布与连通断言；未进一步定位，不能将本轮描述为零 WARN 验收，也不据此直接认定新的 OpenRC 产品缺陷。
