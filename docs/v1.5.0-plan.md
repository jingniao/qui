## 1. Agent 网页一键升级

> **状态：已实现（P2，待审查）。**

### 现状
「服务器 → Agent 管理」点升级只提示「中央尚未配置发布公钥」（`NodeVersionPanel.vue`）。面板里的 Agent 更新走 Ed25519 签名目录：面板配置 `release_keys` 固定公钥，Agent 配置 `updates.catalogue/ca/keys` 固定目录与公钥（`internal/platform/config/config.go` 的 `Updates`），签名靠离线工具 `cmd/release`。GitHub 发布流程从不生成签名清单，生产也没配公钥，所以这条路径实际不可用；生产 Agent 一直靠 SSH 运行 `qui-update`。

### 方案（一步到位）
- **CI 签名**：`check.yml` 的 `release` 任务用 GitHub Secret 里的 Ed25519 私钥，给每个架构的 Agent 二进制生成签名清单（复用 `cmd/release sign`），连同签名目录一起作为 Release 附件。私钥只在 Secret 里，不进仓库、文档和日志。
- **公钥与目录内置**：官方构建在编译时内置官方公钥和 GitHub Release 目录地址，作为 `release_keys`／`updates` 的默认值。配置文件里显式写的值仍然优先，自建签名的用户不受影响。不需要改任何现有 `config.yaml`。
  - 这改变了「目录与公钥只由运维固定」的现状，改为「由官方构建固定」。
  - **安全边界（Owner 2026-11-09 已同意）**：GitHub 下载链接一定会跳转，而 Agent 下载器拒绝任何跳转，所以签名目录由面板托管（面板从 GitHub 导入并用内置公钥校验）。Agent 未配置 `updates` 时，默认目录只接受「主机名等于自己控制连接的主机、端口来自本次连接的 Welcome、证书由面板 CA 签发」，公钥用内置官方公钥。这放宽了「控制消息不得引入 URL」的现有规则：只放开端口，主机与信任根不放开；控制消息仍不能修改目录主机、公钥与用途。配置里显式写了 `updates` 时完全按配置。
- **面板一键排队**：面板像「核心更新」那样从 GitHub 读取最近的已签名 Agent 版本（只列正式版，缓存与失败口径同 `core-releases`），Owner 选择后直接排队 `POST /api/v1/agent-updates`。Agent 端的签名校验、安装历史防重放、失败回滚确认镜像全部不变。
- **界面**：未内置公钥、也未配置公钥的面板（开发版）不显示升级按钮，只说明原因（遵守「不可用的操作直接隐藏」规则）。
- **过渡**：现有 Agent（≤1.4.7）的二进制里没有内置公钥，需要最后一次用 `qui-update --component agent` 升到 v1.5.0，之后才能网页升级。发布说明与运维手册要写明。

### 需要 Owner 做
我生成密钥对后，由 Owner 在 GitHub 仓库设置里把私钥加入 Actions Secrets（本机没有 `gh`）。公钥写进源码。

### 验收
- 一次 Release 产出各架构的签名清单，`cmd/release verify` 能用内置公钥校验通过。
- 在测试机上从 v1.5.0 网页升级到下一个签名版本（可用测试 tag），成功后版本切换；人为损坏下载文件时校验拒绝；健康检查失败时自动回滚。
- 开发版面板不显示升级按钮。

## 2. 节点连接地址与公网 IP

> **状态：已实现（P3，待审查）。**

### 现状
- 新建服务器的对话框没有连接地址字段。
- v1.4.7 的 Agent 只从默认路由网卡选**一个**公网地址填进 `Heartbeat.public_ip`（`netaddr.Select`），面板以 gRPC 对端公网地址兜底；服务器设置里还能手动填 IP（`public_ip_manual`）。
- 迁移 0135 把所有既有非空 `public_ip` 回填为手动，所以升级后的老节点不会自动探测。

### 方案
- **新建服务器**：注册对话框增加「客户端连接地址」（域名或 IP，校验同 `connectHost`），随创建请求写入。
- **上报全部地址**：Heartbeat 新增可重复字段，列出所有非回环网卡上的公网单播地址（同一个 `netaddr` 判定）及所属网卡，只做加法。面板另把 gRPC 对端公网地址作为一个候选。
- **存储**：新迁移给节点加地址候选列表（JSON：地址、来源 `interface:<名称>`／`peer`、族、最后出现时间）和「选定地址」。`public_ip` 继续作为中转、隧道、画布使用的地址，值等于选定地址；未选定时取第一个 IPv4，否则第一个 IPv6，否则对端地址。
- **界面**：服务器设置里去掉手动 IP 输入框，改为「探测到的地址」列表，每条显示来源与族，点选哪个用于中转和隧道。`connectHost` 保留，作为客户端地址的兜底（NAT、弹性 IP 等网卡上没有公网地址的主机）。
- **迁移老节点**：手动标记清除，改由选定地址决定；原手动值若出现在新的候选列表里就设为选定值，若没出现则**保留原值**并在节点详情提示「手动地址不在探测结果中，请确认」，不悄悄改动中转与订阅地址。
- 旧 Agent 没有新字段时沿用单一 `public_ip` 与对端地址。

### 验收
- 多网卡、多公网地址的主机全部列出；点选后中转与隧道使用选定地址。
- 只有私网地址的 NAT 主机列出对端地址，页面提示可填 `connectHost`。
- 升级后生产三台节点的 `public_ip` 不变（原值在候选里，或被保留并提示）。

## 3. 通知系统（第一期）

### 现状
没有任何外发渠道。面板内部已经发布 `system.alert`（证书续期失败、证书自动发布失败、自动额度版本发布失败、节点续费提醒、设备观测等），但前端只用它刷新用户页，Owner 实际看不到。

### 方案
- 新模块 `internal/panel/notification`，遵守模块化单体约束；新迁移包含通知规则、渠道、通知记录三类表。
- **事件来源**：

| 规则 | 默认 | 说明 |
| --- | --- | --- |
| 节点离线 | 开，3 分钟 | 心跳超时判定，恢复时发一条恢复通知 |
| CPU 持续占用 | 开，90% 持续 5 分钟 | 基于每分钟资源采样 |
| 内存持续占用 | 开，90% 持续 5 分钟 | 同上 |
| 磁盘占用 | 开，90% | 状态目录文件系统 |
| 公网 IP 变化 | 开 | 依赖第 2 项的地址候选，新增或消失都算 |
| 已有后台告警 | 开 | 把现有 `system.alert` 各类接入 |
| 整机月流量超额度 | 开 | 有额度设置时才触发 |

  每条规则都能开关、调整阈值和持续时间；同一节点同一规则有冷却时间（默认 30 分钟），恢复后重新计时。
- **渠道**：面板内通知中心（顶栏铃铛、未读数、列表、全部已读）、Telegram Bot（Bot Token＋Chat ID）、通用 Webhook（POST JSON，可接企业微信、钉钉、飞书、Bark 等）。渠道可「发送测试」。
- **安全**：Bot Token 与 Webhook 地址用 vault 加密保存，接口只回「已设置」与末 4 位；外发请求有超时与大小限制，失败只记固定错误码，不回显上游内容，不阻塞业务。随加密备份与恢复。
- **权限**：Owner 管理规则与渠道；Viewer 可看通知中心里节点状态类通知，不能看渠道设置。
- 通知记录保留 90 天。

### 验收
停 Agent 3 分钟后各渠道收到离线通知，恢复后收到恢复通知；用压测把 CPU 打满 5 分钟触发占用通知；调高阈值后不再触发；冷却期内不重复；Token 不出现在任何接口、日志与备份明文中。

## 6. 证书：按域名查找，没有就申请

### 现状
「节点上的证书文件」要 Agent 上报 v1.4.7 的 `tls_certificate_files_supported` 才出现；「自动申请」要证书库里已有签发的证书才出现。所以老 Agent 上只看到自签名和粘贴。

### 方案
- **Agent 只读证书清单**：新增固定只读操作（白名单，§23），列出 `/etc/proxy-agent/certs/` 下的证书摘要：路径、Subject、SAN、到期时间、指纹、是否有配对私钥。不读取或上报私钥内容，路径校验同文件来源（解析符号链接后必须仍在该目录）。新能力位门禁，旧 Agent 不提供该查询。
- **编辑器改为先填域名**，然后按顺序查找：
  1. 节点证书目录里覆盖该域名且未过期的证书 → 显示「使用：<文件>（到期 yyyy-mm-dd）」，选中后填入两个路径。
  2. 面板证书库里已签发的证书 → 显示并可选（`acme` 来源）。
  3. 都没有 → 显示「申请证书」按钮：在证书库创建该域名的申请，签发成功后自动选中（需要已配置 Cloudflare Token，未配置时按钮旁说明去哪里配置）。
- 申请到的证书走现有 `acme` 来源，由面板随配置下发，**不往节点写文件**。
- 自签与粘贴仍保留。

### 验收
节点目录放一张覆盖域名的证书 → 编辑器识别并可用；只有证书库有 → 识别；都没有 → 申请成功后自动选中并发布；旧 Agent 只显示证书库与申请路径。

## 7. Hysteria2 端口跳跃

### 现状
Hysteria2 只支持 sing-box 入站、单个端口。端口占用按单个数字端口记录（`port_claims`），转发范围上限 256。

### 方案（先实测，再实施）
- **先实测**：在本地 Linux 测试机上验证 sing-box 1.14 hy2 入站加 nftables 端口重定向的效果，以及 mihomo、sing-box 客户端的跳跃连接；实测结论不理想就先回报 Owner，不硬做。
- **服务端**：Agent 新增固定的 nft 操作，独立表（例如 `inet proxy_agent_hop`），把跳跃范围的 UDP 重定向到入站监听端口；沿用强制出站源地址那套最小权限 helper（只有 CAP_NET_ADMIN），开机重放，失败自动回滚；新能力位门禁。
- **入站字段**：跳跃端口范围（起止端口）与客户端跳跃间隔；端口冲突检查覆盖整段范围，端口声明改为支持按范围记录（大范围不逐端口插行）。
- **订阅输出**：mihomo 写 `ports`／`hop-interval`；sing-box 写 `server_ports`／`hop_interval`；URI 写 `mport`；legacy Clash 本来就不输出 hy2。
- **限制**：NAT 主机（例如 Alpine 只映射了 21411–21419）跳跃范围必须在服务商放行的端口内，编辑器写明。

### 验收
mihomo 与 sing-box 客户端在跳跃模式下连通且发生端口切换；删除入站后 nft 规则清理；重启 Agent 与主机后规则恢复；与其他入站端口冲突时拒绝保存。

## 9. 规则集引入外部文件（已实现（P4，待审查））

### 现状
规则集（`service_sets`）的条目只有 `domain`／`suffix`／`cidr` 三种（迁移 0009 的 CHECK），没有关键字，也不能引用外部文件。

### 方案
- 规则集新增「外部来源」：一个规则集除手写条目外，可以添加多个外部来源（HTTPS 链接，格式 yaml／text／mrs，行为 classical／domain／ipcidr）。
- **客户端（mihomo）**：订阅输出时为外部来源生成 `rule-provider`，由客户端自己下载；yaml、text、mrs 都支持。mrs 是 mihomo 专用二进制格式，只能这样原样转交。legacy Clash 按现有规则省略 provider 并警告。
- **节点策略（Xray／sing-box）**：面板复用外部订阅导入的安全抓取（只走 HTTPS、逐跳解析并固定公网 IP、2 MiB／15 秒、定时刷新、加密缓存、固定错误码），解析 `.list` 与 yaml 中的 DOMAIN、DOMAIN-SUFFIX、DOMAIN-KEYWORD、IP-CIDR／IP-CIDR6；其他类型（PROCESS-NAME、USER-AGENT 等）跳过并显示「已跳过 N 条」。mrs 不能用于节点策略。节点发布使用最近一次成功缓存，抓取失败不影响已发布配置。
- **新增关键字类型**：迁移给条目加 `keyword`，Xray 渲染为 `keyword:`，sing-box 渲染为 `domain_keyword`；手写条目也可用。
- 页面为每个外部来源标明「客户端可用／节点可用」，显示最近抓取时间、条目数与失败原因。
- 外部来源与缓存随加密备份；恢复不自动抓取。

### 验收
引入 `https://raw.githubusercontent.com/blackmatrix7/ios_rule_script/master/rule/Clash/OpenAI/OpenAI.list`：mihomo 订阅出现对应 rule-provider；节点策略按解析出的域名、后缀、关键字、CIDR 分流到指定出口；抓取失败显示固定原因且不影响已发布配置。

据此调整方案：
- **状态要区分来源**：两台 Debian 的 BBR/FQ 是系统自带配置开的，面板却显示「暂无调优请求」。状态卡要区分「面板设置」「系统已是该值（外部配置）」「默认值」。
- **看不到的键不再整体失败**：v1.2 验收时，Alpine 上一次请求里只要有容器中不存在的键，整次就干净失败。改为 Agent 上报每个键「存在／可写」，草稿、预设与推荐只包含可用的键，不可用的显示「此环境不可用」。
- **`LimitNOFILE` 降为按需**：systemd 主机上实际已是 524287，不需要改单元。只在 OpenRC 实测偏低时，给 OpenRC 服务加 `rc_ulimit`；页面照常显示实际值。
- **推荐值要保守**：三台内存只有 0.33–2 GB。QUIC 至少需要约 7 MB 的 UDP 接收缓冲，所以 `rmem_max`／`wmem_max` 的推荐值按内存分档（例如 1 GB 以下 8–16 MB，2 GB 起 32 MB），不一律给 64 MB。

补充判断（2026-11-09）：
- 规模决定收益。1～10 个用户、小内存 VPS、重传率 0.03%～0.12% 时，连接队列、`netdev_max_backlog`、本地端口范围、`fs.file-max` 基本碰不到上限。真正有用的是：BBR＋fq、`tcp_slow_start_after_idle=0`（长连接空闲后不重新慢启动）、`tcp_notsent_lowat`（配合 BBR 降低发送端排队）、缓冲上限，以及中转／隧道节点的 `tcp_mtu_probing=1`。
- Xray 与 sing-box 是 Go 程序，Go 会给每个连接单独设置 keepalive（默认 15 秒），覆盖 `tcp_keepalive_*`，所以不加这三项。
- `tcp_fastopen` 要核心在连接上主动开启才生效，我们不渲染 TFO，标为「仅在核心启用 TFO 时有效」，不进推荐。`tcp_ecn` 保持默认 2，不推荐改。
- 核心进程只有 `CAP_NET_BIND_SERVICE`（uk 实测），quic-go 不能用 `SO_RCVBUFFORCE` 绕过上限，UDP 接收缓冲只能靠 `rmem_max`；生产目前没有 Hysteria2/TUIC 入站。
- 现有页面的两个缺陷：预设会把草稿整份替换成两项，一键应用后其他已生效参数恢复初始值；拥塞控制下拉框写死了 `bbr2`、`bbr3`，三台都不可用。这两处提前放进 P1 修。
- 模块自动加载（本地测试机实测，内核 6.1）：`tcp_bbr.ko` 存在但未加载时 `bbr` 不在 `tcp_available_congestion_control` 里；以 root 写入 `tcp_congestion_control=bbr`、`default_qdisc=cake`／`fq` 后，内核自动加载 `tcp_bbr`、`sch_cake`、`sch_fq` 并生效；写入不存在的 `bbr3` 返回「没有那个文件或目录」。测试后已恢复原值并卸载模块。Agent 现在的校验只认已加载的算法，会拒绝这种可自动加载的情况。

### A. 调优状态看板
- 详情页顶部状态卡：拥塞控制与排队算法当前值；「N 项已生效／M 项漂移／K 项此环境不可用」；最后一次应用的时间与结果；重启后是否仍保持。
- 参数表增加「初始值」（helper 快照）、「来源」与「推荐值」三列，每行标出：面板设置／系统已是该值（外部配置）／默认值／漂移／此环境不可用。
- 来源：Agent 只读解析 `/etc/sysctl.d/*.conf` 等标准位置，标出设置该参数的文件（例如「`99-bbr-qdisc.conf` 设为 bbr」）。提供「纳入面板管理」，把外部已设的值复制成面板期望配置。
- 重启后被覆盖检测：开机标识变化后比较实测值与期望值，被覆盖的参数标出是哪个文件（例如排在 `99-proxy-tuning.conf` 之后的 `99-sysctl.conf`）。不改我们的文件名。
- 服务器列表卡片显示小标签（「BBR ✓」「有调优建议」「调优漂移」），可按它筛选。
- Agent 只做加法地上报：虚拟化类型（KVM／LXC 等）；每个白名单参数是否存在、是否可写；拥塞控制与排队算法分「已可用」「可加载」（模块文件存在于 `/lib/modules/$(uname -r)`）两类；Agent 与各核心进程实际生效的文件句柄上限；helper 回执带回快照里的初始值。旧 Agent 显示「未知」。

### B. 参数与模块
- 白名单新增（每个都有边界）：`net.ipv4.tcp_slow_start_after_idle`、`net.ipv4.tcp_notsent_lowat`、`net.core.rmem_default`／`wmem_default`、`net.ipv4.udp_rmem_min`／`udp_wmem_min`。面板、Agent 与 helper 三处白名单同步，备份校验接受新键。原有的连接队列、`fs.file-max`、`tcp_fastopen`、`tcp_ecn` 等保留，但收进「高级」默认折叠。
- 算法选项只列这台机器「已可用」或「可加载」的，内核里没有的不列（遵守「不可用的直接隐藏」规则）。选「可加载」的算法时，helper 照常写入，由内核自动加载模块，再以读回值确认；失败在回执里写明。不调用 `modprobe`、不加权限；重启后 sysctl 配置再次写入时模块同样自动加载。实施时须在 systemd 沙箱内的 helper 与 OpenRC 下各实测一次。
- 内核本身不含所需算法（例如内核太老没有 bbr）或容器环境（宿主未加载模块）时，只提示原因与运维文档里的手动步骤，**不在面板里安装或更换系统内核**（风险、第三方来源与 §23 安全边界）。
- 进程文件句柄：页面显示实际值。systemd 主机已是 524287，不改单元；只在 OpenRC 实测偏低时加 `rc_ulimit`，由 `qui-update` 快照并替换。
- 继续不做：任意 sysctl、显式 `modprobe`、`ethtool`／网卡队列等非 sysctl 操作。

### C. 每台机器自动推荐
- 面板为每台服务器自动计算一份推荐配置，规则放在独立的小模块里，每条规则写明条件、取值与中文理由，规则集带版本号。
- 推荐依据：内存、CPU 核数、内核版本、虚拟化类型、参数存在／可写、已可用／可加载的算法、当前值与来源、这台机器的入站协议（有 Hysteria2/TUIC 才推荐加大 UDP 缓冲）、在隧道／中转里的角色（中转与出口推荐 `tcp_mtu_probing=1`）、已有 TCP 探测的延迟，以及可选的「线路带宽」（节点信息新增，可空；填了按「带宽 × 延迟」估算缓冲，不填只按内存分档）。
- 缓冲上限按内存分档且有上限（例如 1 GB 以下 8–16 MB，2 GB 起 32 MB），并不低于 QUIC 需要的约 7 MB（有 QUIC 入站时）。推荐中从不出现此环境不可用的参数。
- 推荐卡：每条显示参数、当前值、推荐值、理由与级别（建议／可选）。可「采用全部建议」或逐条勾选，**合并进当前草稿**，不清掉其他已设置的参数；确认框列出将要改变以及将恢复初始值的参数。
- 「不采纳」：逐条记住不再提醒；推荐依据变化（例如新增 Hysteria2 入站）后重新提醒。需要存储（与「线路带宽」一起放进本版迁移）。
- 重新计算时机：能力上报变化、入站或隧道发布、重启后。
- 默认只推荐，由 Owner 确认后应用。可选开关「新服务器上线后自动应用推荐」，默认关闭，只对之后新登记的服务器生效。
- 按现有数据预估（实施时按规则重新算）：us2 保留 BBR/fq 并提示纳入面板管理、空闲后不慢启动、`tcp_notsent_lowat`、缓冲约 32 MB；uk 同上、缓冲约 16 MB；alpine 只推荐容器内可改项，TCP 缓冲约 8 MB，可用列表有 bbr 时才推荐 bbr。
- 场景预设保留为手动选项（通用代理、高带宽长距离、QUIC/Hysteria2、小内存 VPS），同样合并进草稿、略过不可用参数。每个参数一行中文说明：作用、风险、何时需要。

### E. 效果验证
- 心跳上报 TCP 重传计数（`/proc/net/snmp` 的 `RetransSegs`／`OutSegs`），资源曲线增加「TCP 重传率」，标出调优应用的时间点，配合已有 TCP 探测延迟图对比前后效果。缺测为 null，不补 0。

### 验收
- 三台生产主机（含 Alpine LXC/OpenRC）的状态卡正确显示：可写／不可用、已可用／可加载算法、来源文件、文件句柄上限与初始值；us2 与 uk 的 BBR/FQ 显示为「系统已是该值（外部配置）」。
- 三台的推荐各不相同且每条有理由；Alpine 的推荐不含 `net.core.*`；新增 Hysteria2 入站后该机出现 UDP 缓冲推荐。
- 采用推荐只合并进草稿，其他已设置参数不变；「不采纳」后不再提醒，条件变化后重新提醒。
- 在模块未加载的测试机上选 bbr／cake，经 helper 应用后生效且重启后保持；内核不含的算法不出现在选项里。
- 新参数应用、清除恢复初始值、重启后被覆盖检测均通过；QUIC 推荐应用后 quic-go 不再报 UDP 缓冲告警。
- 页面显示的文件句柄上限与 `/proc/<pid>/limits` 一致。
