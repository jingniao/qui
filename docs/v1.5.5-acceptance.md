- 三节点隧道：t1 入口 → 同机独立中间 Agent → t3 出口。TCP 请求 3/3 返回出口地址 `155.117.82.80`；经隧道的 UDP 与 TCP DNS 查询都返回有效 `example.com` A 记录。暂停中间 Agent 后，新三节点路径超时，既有两节点路径仍可用；恢复并重启中间 Agent 后，三次 TCP 请求及两种 DNS 查询恢复成功。细节与脱敏结果见工作区临时证据 `.tools/v155-accept/three-result.json`。
- 服务器标签 API：空格裁剪、忽略大小写重复、持久化与列表返回正确；省略 tags 保留现值，显式空数组清除，含逗号的非法值返回 400 且未改数据。

## 出站源 IP 实流与失败

在本轮独立中间 Agent 上，以 Xray 26.3.27 创建两个 Direct 出站，分别绑定主机 IPv4 `155.117.82.80` 与 IPv6 `2a0e:97c0:3f0:1::588`；两个仅监听回环的 Xray forward 入站各指向一个出站。分别访问 IPv4／IPv6 查询站点，各 3/3 请求返回对应配置地址。该结果覆盖显式双栈绑定；没有两个同地址族公网地址，因此未测试多地址强制出站豁免，也未做 sing-box 实流。

随后把专用 IPv4 出站改为主机不存在的 `192.0.2.99`，发布修订 71 返回 `success`，实际经该入站访问返回空响应（curl 52），没有自动回滚。按计划第 17 项“本机不存在的源 IP 应用失败并自动回滚”的验收标准，此场景失败。恢复正确 IP 后修订 72 成功、原路径恢复；删除本项入站／出站后的修订 73 成功，资源列表与本项开始前相同。

第一次启用双栈测试入站时，修订 62 出现 `Xray startup or health check failed` 并回滚到 57；新增资源清理成功（修订 66）。为补取启动错误，在本轮中间 Agent 上临时使用仅记录启动 stdout/stderr 的 Xray 启动包装器；随后相同双栈场景成功，未复现首次启动失败，原原因未确定。包装器配置已经撤回，原始失败未记作通过。首次诊断包装器还曾截走能力探测输出，修正为只记录真正启动后才继续；此问题仅在临时验收脚本内，不涉及产品代码。详细结果见 `.tools/v155-accept/source-ip-result.json`，原失败与诊断记录保留在同目录。
