## 发现并已修复

1. **隧道补装 GOST 在从未发布过配置的服务器上失败**：页面以修订 0 排队安装，面板返回 409 `core_update_conflict`（提示为「与进行中的操作冲突」，有误导）。现与「版本与更新」页共用 `web/src/modules/system/nodeBaseline.ts`：无已确认修订时先发布基础配置并等待确认，再排队安装。实机两节点按此顺序安装 GOST 约 10 秒完成；页面流程由 `tunnel-baseline-selftest.mjs` 覆盖，未在浏览器实测。
2. **发布失败的服务器显示「后续服务器失败，已回滚」，看不到真实原因**：现区分本服务器应用失败自动回滚（「配置应用失败，已自动回滚（apply_failed）」，只显示修订结果码）与被反向回滚。rc.2 复测两种提示均正确。
3. **完整撤除后 `canvas_tunnels` 行残留**：再次创建并仅删除画布后，残留空通道与新资源被并为一组，报「端点分叉／重复连接」，界面无法挂接或撤除。现撤除的最终事务删除方案专用的空通道行；历史空通道在遗留资源中单独列出，可直接「清除空通道」。rc.2 复测通过。
4. 小问题：remove-plan/remove 缺少 `updatedAt` 返回 400（原 409 `stale_scheme`）；撤除结果补齐节点名；隧道／规则生成的入站 routeSummary 显示「隧道转发」及出口节点（原显示为直连）。

详细代码与测试见 [canvas-field-fixes-verification.md](canvas-field-fixes-verification.md)。

## 未覆盖与待决

- 三节点隧道（入口→中间→出口）：只有一台公网可达主机，未测。
- 入口复用（reuse）模式：高级画布尚无编辑入口，未测。
- 页面操作（浏览器）未实测，本轮全部经 API 驱动，与页面调用的接口相同。
- 快速创建的通道：说明书写「通道为 TLS/TCP」，实际出口入站为 Shadowsocks 时通道为 Shadowsocks/TCP（AEAD 加密，无 TLS），规划器用出口协议覆盖了 Trojan/TLS。是改文档还是固定为 Trojan/TLS，待 Owner 决定。
- 快速创建后未做任何修改的入口，撤除时仍要求确认「未记录创建时完整配置」与分组移除（按设计：绑定只存已应用出站），每次撤除都会出现确认。
- 节点元数据 PUT 省略字段时 `renewNoticeDays` 被重置为 0（页面总是提交完整对象，影响仅限直接调用接口）。
