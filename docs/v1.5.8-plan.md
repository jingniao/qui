# v1.5.8 规划

状态：Owner 于 2026-11-15 确认全部范围；实现交给 Codex，Claude 审查。迁移号 **0150**（只给 A1 使用）。

## 背景

- 生产「测试中转-shlii-CC」等中转方案无法撤除：撤除要等所有节点确认，美国 CC 离线就卡住；撤除弹窗步骤繁多。
- 美国 CC 每 30 秒连上后 1 秒内被面板断开：Agent 本地积压了修订 87 的流量批次，面板把 87 记为 `rollback/apply_failed`，拒收这些批次并以 `FailedPrecondition traffic batch rejected` 断开控制流（`internal/panel/node/control.go:455-458`，修订判定 `internal/panel/deployment/repository.go:199`）。Agent 每批重试 3 次才隔离，积压数千批，节点永久离线，新修订也送不到。
- 节点列表：`loadData`（`web/src/modules/proxy/pages/ProxyNodeListPage.vue:1255`）把方案、导入、分组放在一个 `Promise.all`，任一失败方案就不载入，中转入口不折叠；`choices()`（`web/src/modules/proxy/api.ts:121`）在两页之间列表变化时直接抛错。

## Owner 规则（必须遵守）

1. **入口只属于一个方案**：方案入口（`canvas_entry_bindings` 的入站）不能被其他方案当作出口／中转节点，也不能作为隧道规则 linked 目标。保存时拒绝，删除时因此不会遇到引用。
2. **取消「复用现有入口」（reuse）**：入口一律由方案新建（create）。迁移 0150 删除现有 reuse 绑定行（入站保留为普通入站，不改其配置）。没有绑定记录的历史入口（`canvas_remove_plan.go:114` 的 `legacy:` 视为 reuse）一律按 create 处理：撤除时删除。
3. **停用并移除 = 一次确认后直接执行**：不再有影响预览、恢复目标选择或人工改动勾选；确认即等于 `acknowledgeChanges`。
4. **撤除不等离线／失败节点（N3 方案 A）**：确认后面板立即删除方案及其专用对象（入口入站、内部监听、中转出站、通道、隧道规则等）并从页面消失；对每个受影响节点按「已发布状态减去被删对象」生成修订：在线即下发；离线节点重连后自动下发；应用失败或回滚的节点标记「待清理」并自动重试，直到成功。节点在此之前照旧运行旧配置。
5. **删除出口时连带删除**：
   - 删除出口**入站**：连带删除以它为出口的全部方案、linked 到它的隧道规则；隧道失去全部规则后一并删除。
   - 删除出口**服务器**：连带删除该服务器上的全部入站，以及涉及该服务器（任一实例或隧道跳）的全部方案、隧道、规则。其他与中转无关的引用（手工出站、出口组、代理链、策略）仍按现有 `node_delete_blocked` 阻止并列出。
   - 删除前一次确认，**列出明细**（每个将删除的方案、规则、隧道、入站的名称）。
6. **去掉「仅删除画布」和「遗留资源」**（含重新挂接）。升级后启动时一次性清理生产残留：脱离方案（detached）的入口、没有方案引用的画布通道及其对象，按规则 4 删除并下发。
7. **节点列表卡片**：去掉「直连／中转／隧道转发」类型标签，只保留导入来源标签（单独导入、订阅来源名）；协议名称从标题行移到第二行。
8. **CC 恢复**：面板接受本节点**已下发过**的任何修订（`deployment_targets` 存在该节点该修订行，不论终态）的流量、访问记录与设备观测并照常归属；仍拒绝未知或不属于本节点的修订。

## 接口合同（A 与 B 共同遵守）

- `POST /api/v1/canvas-schemes/{id}/remove`：体 `{updatedAt}`（其他字段忽略）；200 `{schemeId,removed:true,pendingNodes:[{nodeId,name,reason}]}`；`pendingNodes` 为离线或应用失败、已标待清理的节点。409 `stale_scheme`、404 `not_found`。`remove-plan`、`remove-status` 删除。
- `GET /api/v1/inbounds/{id}/deletion-preview`、`GET /api/v1/nodes/{id}/deletion-preview`：200 `{schemes:[{id,name}],tunnels:[{id,name}],rules:[{id,name}],inbounds:[{id,name,nodeName}],blockers:[{kind,id,name}]}`；`blockers` 非空时删除返回 409（`node_delete_blocked`／`inbound_delete_blocked`）。
- `DELETE /api/v1/inbounds/{id}`、`DELETE /api/v1/nodes/{id}`：执行连带删除，200/204 并附 `pendingNodes`（同上）。
- `GET /api/v1/nodes` 与节点详情增加 `relayCleanupPending:boolean`、`relayCleanupCode`（最近失败码，可空）。
- 移除的接口：`DELETE /canvas-schemes/{id}`（仅删画布）、`/relay-schemes/legacy-resources`、`/reattach`、`remove-plan`、`remove-status`；`entryBinding.mode` 只接受 `create`。
