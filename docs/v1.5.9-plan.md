## 1. 隧道规则单独授权（迁移 0151）

需求：一台落地机，多条隧道转发线路（入口只原样转发，不在入口终止协议），直连与每条线路分别给不同的人。只要求订阅里不显示，不要求阻止用户自行直连落地机。

- 新表 `node_group_relays(group_id, rule_id)`：关联目标入站的隧道规则成为节点分组的独立成员，两端外键级联删除。
- 订阅：直连端点只看目标入站是否在用户的授权分组里；规则端点只看规则是否在授权分组里，两者互不连带。规则端点的分组标签为含该规则的授权分组。
- 凭据：规则只转发字节，用户在目标入站认证。只拿到规则的用户也会在目标入站获得凭据（`AccessForGroups` 并入规则目标入站，`SubscriptionGroups` 并入规则目标所在服务器的分组）。额度自动版本与在线设备统计按 `nodeIds` ∪ `relayNodeIds` 计算。
- 接口：节点分组 POST/PUT 增加 `relayIds`（省略或 null 保留，`[]` 清空，最多 500 条，只接受关联目标的规则）；响应增加 `relayIds` 与只读 `relayNodeIds`。
- 升级：0151 把已在组内的目标入站的全部关联规则写入同一组，升级后订阅不变。新建规则不自动入组，须在分组里加入（隧道页与「添加中转」均有提示）。
- 页面：「编辑分组 → 组内节点」的候选与成员列表增加「隧道转发」类型；未发布、未勾选订阅可见、等待移除的规则在成员行给出提示，后两者不能新加入。
- 备份：清单计数 `nodeGroupRelays`，校验分组与规则存在、规则为关联目标、每组不超过 500；恢复以当前库成员为准，只保留恢复数据里仍存在的规则。
- 已知限制：规则删除或改目标后，只拿到规则的用户在原目标入站上的凭据要等该节点下一次发布或自动对账才移除；只拿到规则的用户知道落地地址时仍可直连。

## 2. 订阅里隧道规则端点的名称与入口地址

- 名称改用规则当前名称（「添加中转」默认「目标节点 经 隧道」），规则名为空时才回退旧格式「目标 · 协议 · 经 入口」。
- 入口地址改用入口节点当前的客户端连接地址（`connectHost`，否则 `publicIp`；两者皆空时沿用发布快照里的地址）。
- 名称与入口地址不属于节点运行配置，改动不需重新发布；端口、网络、启用、可见与目标地址仍以成功发布的快照为准。
- 影响：按名称关键词筛选的客户端策略组可能因规则改名而不再包含该端点；客户端会把改名后的端点视为新节点。

## 3. Clash（mihomo）订阅放宽 xhttp 的 ALPN 限制

- 原先 VLESS xhttp 节点的 ALPN 只要不是空或恰为 `[h2]`，就从 Clash 订阅里删除并提示「xhttp 的 ALPN 只支持留空或 h2」。
- 按 mihomo 源码（`transport/xhttp/client.go`）：ALPN 恰为 `[http/1.1]` 时走 HTTP/1.1，恰为 `[h3]` 时走 HTTP/3，其余（空、`[h2]`、`[h2,http/1.1]`）走 h2。面板客户端模型只接受 h2 与 http/1.1，所以这些组合现在都原样输出到 Clash 订阅。
- xhttp 仍只接受 TLS 或 Reality（导入时已校验）；sing-box 与旧版 Clash 仍不输出 xhttp。
- 起因：生产导入的 xhttp 节点在 Clash Verge Rev（默认 UA `clash-verge/v…`，按 mihomo 格式下发）订阅里被过滤。

## 4. 中转方案与快速流程新入口可选安全方式

- 画布「用户入口」与「添加中转」代理模式的新 VLESS 入口可选 Reality（能力支持时默认）、TLS（自签名证书）或不加密；Reality 不可用时默认 TLS。纯转发流程不变。
- 安全与传输组合按入口核心实际报告的能力筛选，隐藏不可用选项；TCP、TCP Vision、xhttp 共用节点编辑器能力判断。规划及保存复用同一设置契约检查；xhttp 仅与 TLS／Reality 搭配，Vision 仅支持 TCP + TLS／Reality。
- Reality 必填握手目标 host:port 与一个无通配符的 DNS 服务器名称；出口为 VLESS Reality 时预填其公开参数，否则留空。创建时生成 X25519 密钥对及 16 位小写十六进制 Short ID；私钥不进布局或规划响应。xhttp 使用 auto 模式、空 Host 与随机路径。TLS 复用十年自签名证书，要求节点已有公网 IP 或客户端连接地址。
- 新字段只用于 VLESS：布局 `security/transport/flow/realityTarget/realityServerName`，快速接口对应 `entrySecurity/entryTransport/entryFlow/entryRealityTarget/entryRealityServerName`。省略安全与传输的旧布局仍按不加密 TCP 发布，requestId 重试仍复用原入口。
- Trojan／Hysteria2／TUIC 保持自签名 TLS，Shadowsocks 保持原加密方法。VLESS 不加密、HTTP 与 SOCKS5 入口在表单及规划中提示「容易被识别和干扰，不建议在国内直连使用」。
- 已发布入口在方案中只读展示实际安全设置；须在「节点列表」编辑该入站后发布，重新发布方案仅调整路由，不修改安全材料。0148 基线已摘要实际 Settings 与证书来源，无需更改格式或迁移，旧基线继续有效。
