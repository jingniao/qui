# v1.6.0 规划

Owner 于 2026-11-16 提出，开发中。

## 1. 服务器方案以导入节点为出口（画布 U5）

需求：入口是自己的服务器，出口是导入的代理节点（例如生产的「美国 家宽 v6」，导入的 VLESS），在「服务器执行」的中转方案里直接连过去并发布。Owner 在“小修（隐藏）”与“真正支持”之间选择了后者。

### 1.1 现状（2026-11-16 核实）

- 服务器方案的连接目标只接受受管服务器、自建入站和服务器上的出站资源（`outbound:<id>`，作为上一跳服务器的最终出站，`canvas_publish.go` 的 `finals`）。目标是导入节点时规划直接拒绝：「连接只能在两个受管服务器之间发布（客户端方案与导入节点在 U5 支持）」（`canvas_publish.go:257`）。导入节点只能用于客户端方案。
- 在导入节点上点「添加中转」会创建一个把该节点放进去的**服务器**草稿（`web/src/modules/proxy/proxyNodes.ts` 的 `createDraftSchemeForEntryNode`），这个草稿永远发布不了；画布资源库也不隐藏导入节点。生产已有一个这样的草稿「美国 家宽 v6 中转方案 (草稿)」，从未发布。
- 服务器出站目前只能表达经典组合：SOCKS5、HTTP、Shadowsocks、Trojan（TLS，tcp/ws/grpc）、VLESS（无加密或 TLS，tcp/ws/grpc，Vision）、WireGuard，以及仅 sing-box 的 Hysteria2／TUIC。`desiredstate.ProtocolSettings` 没有 ALPN、客户端指纹（uTLS）、WebSocket Host、证书 SHA-256 固定、客户端侧 Reality（公钥／Short ID／SpiderX）与出站 xhttp；`Reality`／`XHTTP` 两个类型化字段是自建入站的服务端私有半边，渲染入口对出站携带它们一律拒绝。Xray／sing-box 适配器上报的设置契约组合全部是 `direction=inbound`。

### 1.2 行为

- 服务器方案里，导入节点**只能做最后一跳出口**：连接 `上一跳服务器 → 导入节点`。发布时面板在上一跳服务器上生成一个**方案专属出站**，参数取自导入节点的已保存内容，并把它当作该服务器的最终出站（复用 `finals` 路径，与手工出站资源同一条链路／路由生成逻辑）。
- 生成的出站按 ID 归属到该连接的画布隧道（`canvas_tunnel_objects`，`object_kind='outbound'`，表已支持），不按名称认领；普通出站编辑器对它返回 `managed_by_tunnel` 同类保护；撤除方案、删除服务器连带删除时随方案对象一起删除并走现有待清理下发。
- 规划预览列出该出站的 create／update／remove，摘要只含协议、安全、传输与地址端口，**不含凭据**；差异与预览沿用现有出站的隐藏规则。
- 导入节点刷新（订阅连接 `Kind=url` 定时刷新、单独导入改名）后内容与已生成出站不一致时：已运行的配置不变；方案状态的「草稿」项提示「导入节点已更新，重新发布后生效」，下次发布预览为该出站 update。改名不影响已生成出站。导入节点被刷新掉（订阅里不再有该节点）时规划失败并给出固定中文原因，已运行配置保留到 Owner 处理。
- 删除导入节点：沿用 0147 起的删除预览，被画布草稿或发布快照引用时阻止（`import_in_use_by_canvas`），服务器方案同样适用。
- 凭据：导入节点的凭据随生成出站密封保存在 `outbounds.encrypted_settings` 并下发到上一跳服务器，这是该功能的必然结果；API／计划／日志不回显。
- TCP/UDP：连接的 `supportTcp/supportUdp` 默认按导入协议推断（沿用 `guessProtocolNetworks`），与生成出站能力相交校验。

### 1.3 可转换的导入节点（契约 + 渲染器）

可转换 = 导入节点的（协议、安全、传输、flow）能映射为出站，且上一跳服务器上将渲染该出站的核心上报了对应的 `direction=outbound` 设置契约组合。不可转换的导入节点在服务器方案资源库里**隐藏**（Owner 规则：隐藏不可用选项），不灰显。

| 范围 | 需要的工作 |
| --- | --- |
| SOCKS5、HTTP、Shadowsocks（含 2022 方法，按核心支持）、Trojan TLS、VLESS 无加密／TLS（tcp/ws/grpc，Vision） | 已有出站，只补转换；TLS 补 ALPN、uTLS 客户端指纹、ws Host、证书固定（`TLS.Fingerprint` → Xray `pinnedPeerCertificateChainSha256`／sing-box 对应字段，核心不支持则该节点不可转换） |
| VLESS Reality（TCP 无 flow／Vision、gRPC） | `desiredstate` 新增出站专用类型化字段（公钥、Short ID、SpiderX、uTLS 指纹，SNI 用 `server_name`），与入站的服务端私有 `reality` 互斥、角色不能混用；Xray 与 sing-box（仅 TCP）出站渲染器；原生 `check` 探测成功才上报 `direction=outbound` 组合 |
| VLESS xhttp（TLS／Reality，auto/packet-up/stream-up/stream-one） | 出站 xhttp 渲染（仅 Xray）；复用 `XHTTPSettings` 的 host/path/mode 校验但按出站角色放行 |
| Hysteria2、TUIC | sing-box 已有出站，补转换（跳跃端口 `mport` 只用于客户端，出站不支持则该节点不可转换）；上一跳入口须为 sing-box 核心 |
| `insecure`（跳过证书校验）的导入节点 | 默认不可转换（服务器侧静默跳过校验风险高）；是否放开由 Owner 另行决定 |

能力位：沿用 `CoreCapability.server_settings_combinations`（字段 11）与单核标量（字段 24），新增的只是 `direction=outbound` 的组合，不新增 proto 字段；旧 Agent 不上报，面板在保存、`SnapshotIntent` 与发布前三处一致拒绝（与入站同一个 `RequireInboundServerSettings` 风格的判断），页面提示升级上一跳服务器的 Agent。新字段使旧 Agent 的 `desiredstate.Decode` 拒绝未知字段，因此门禁必须在面板侧完成，不能依赖 Agent 报错。

### 1.4 页面

- 服务器方案画布资源库：导入节点只在可做出口时显示，只能作为连接终点；拖入后节点属性显示「导入节点 · 出口」、协议与安全摘要和「发布时在 <上一跳服务器> 生成出站」。
- 节点列表在导入节点上点「添加中转」：新建服务器方案，导入节点放在**出口**位置，聚焦入口选择（不再生成放在入口位置的不可发布草稿）；该导入节点不可转换时按钮隐藏，只保留客户端方案路径。
- 已存在的这类草稿（含生产那份）在 1.6.0 打开后按新规则可直接补入口并发布，不需要迁移。

### 1.5 分阶段

1. **契约**：`desiredstate` 出站客户端字段（ALPN、uTLS 指纹、ws Host、证书固定、出站 Reality、出站 xhttp）与校验、出站组合的门禁判断、协议矩阵；表驱动测试覆盖入站／出站角色互斥。
2. **Agent 渲染**：Xray 与 sing-box 出站渲染与原生探测上报；真实核测试：本地 Xray Reality（TCP/Vision、gRPC）与 xhttp 服务端、sing-box Reality TCP，经生成出站往返；错误公钥／Short ID 被拒。
3. **面板转换与规划**：`proxy.Proxy` → 出站输入的纯函数（逐字段表驱动测试，不可转换给出固定原因码）；画布规划接受 `import:` 终点、生成／更新／删除归属出站、未变化识别、状态提示刷新差异；删除预览与撤除路径覆盖；备份校验覆盖新出站字段。
4. **页面**：资源库过滤、属性面板、「添加中转」改为出口位置；自测。
5. **验收与文档**：AGENTS.md（第 12、13、14、26 节、协议矩阵）、发布说明；在测试面板 t3 用导入节点做一次端到端连通验证（不在生产上做）。

### 1.7 实施状态

已实现（2026-11-16）。与上文的差异：

- 不可转换（服务器方案中隐藏，快速流程只给纯转发）：Shadowsocks 2022（共享校验只有四种 AEAD 方法，旧 Agent 无能力位可门禁）、证书指纹固定（`TLS.Fingerprint`）、跳过证书校验、Hysteria2 混淆、WireGuard、httpupgrade 等未建模传输。Hysteria2 跳跃端口不转换，只连主端口。
- 出站客户端字段为 `alpn`（仅 VLESS／Trojan，h2／http/1.1）、`client_fingerprint`、`ws_host`、`reality_client`，出站 xhttp 复用 `xhttp`；共享指纹与公钥校验在中立包 `pkg/contracts/clienttls`。sing-box 不输出 SpiderX。
- Agent 上报：Xray 13 个、sing-box 10 个 `direction=outbound` 组合（Linux 真实核实测）；面板门禁码 `outbound_client_unsupported`，保存出站、快照与发布前三处检查该节点全部启用的 Xray／sing-box 核心，禁用出站同样检查（旧 Agent 解码即拒绝）。
- 生成出站按连接所属画布隧道认领（不按名称），普通出站编辑器修改或删除它返回 409 `managed_by_tunnel`；导入内容变化时方案状态「草稿」显示原因、预览为 update，未变化不重写。`GET /api/v1/canvas-import-exits` 返回每个导入节点的原因与可做其上一跳的服务器。
- 导入节点的「添加中转」改为打开快速流程（第 2 节），不再生成画布草稿；可转换且路线末端服务器支持时提供代理中转，否则只有纯转发。

### 1.6 不在本项

- 导入节点做入口或中间跳（导入节点不受管，无法在其上生成监听）。
- 自动跟随订阅刷新重新发布（刷新只提示，发布仍由 Owner 触发）。
- 客户端方案行为不变。

## 2. 导入节点的快速中转（迁移 0152）

需求：在导入节点上点「添加中转」，打开与自建入站相同的快速流程，可选「纯转发」与「代理中转」。Owner 于 2026-11-16 决定加入 1.6.0。

### 2.1 纯转发（先做，不依赖第 1 项）

入口只原样转发字节到导入节点的地址端口，不解开协议，因此所有导入类型（VLESS Reality／xhttp、Trojan、Shadowsocks、Hysteria2、TUIC 等）都适用，不需要升级 Agent。

- 现状：隧道规则目标只有 `linked`（关联自建入站，进订阅）与 `manual`（固定地址，不进订阅）。手填导入节点地址的 manual 规则能转发，但用户订阅里没有它。
- **新目标类型 `import`**：`tunnel_rules.target_mode` 的 CHECK 只允许 `linked`／`manual`，SQLite 须重建该表，迁移 **0152** 增加 `import` 与导入节点引用列（导入节点删除时的行为见下）。目标地址端口从导入节点的已保存内容派生，读取时计算，与 `linked` 一样不写死。
- **刷新失效（同 D8）**：导入节点刷新后地址或端口变化，已发布规则在同一事务标为 `needs_publish`，已发布快照与运行配置不动；导入节点从订阅里消失时规则保留并显示「目标已删除」，规划拒绝，Owner 修改或删除规则。删除导入节点的预览列出引用它的规则，与画布引用一样须先处理（不静默连带删除）。
- **订阅端点**：按成功发布快照，输出导入节点的原始公开参数，只把地址端口换成入口客户端连接地址与规则端口；TLS／Reality／xhttp 保留原 SNI，原隐含 SNI 显式写为原服务器名，与 linked 规则端点同一套处理。名称取规则名。Hysteria2 跳跃端口清空，只走主端口。快照不含凭据，凭据在生成订阅时从导入节点读取；导入节点凭据刷新后订阅随之更新（规则只转发字节）。
- **分组授权**：`import` 规则可加入节点分组（`node_group_relays`，校验放宽为 linked 或 import），与 1.5.9 的规则成员同样单独授权；不要求导入节点本身在用户分组里。凭据下发不涉及（导入节点不在面板管理的服务器上）。
- **备份**：校验 `import` 目标引用存在、0152 前归档合法；恢复不重新抓取。
- **快速流程**：`/relay-schemes/quick` 的纯转发模式与页面接受导入节点为出口，创建 `import` 规则、加入所选分组并发布；隧道页的规则编辑器同样可选导入节点为目标。
- 已知限制：UDP／QUIC 经隧道时由 TLS 封装，延迟略高；导入节点使用 CDN 域名时客户端改连入口，不再经过 CDN；导入节点的跳跃端口不可用。
- 状态：已实现（迁移 0152、规则目标 import、订阅端点、分组、备份、快速流程纯转发、规则编辑器、删除保护与分组成员）。

### 2.2 代理中转（依赖第 1 项）

入口解开协议后以客户端身份连接导入节点，即第 1 项生成的方案专属出站。第 1 项完成后：快速创建接口的出口输入从「出口入站 ID」扩展为「出口入站或导入节点」，预览与执行复用第 1 项的规划；页面在导入节点可转换（第 1.3 节）时显示「代理中转」，否则只显示「纯转发」。支持范围与 Agent 升级要求同第 1 项。

状态：已实现。快速创建接口增加 `exitImportId`（与 `exitInboundId` 二选一），最后一跳连接按导入节点的 TCP／UDP 能力设置；「加入出口所在分组」对导入出口取包含该导入节点的分组（经中间服务器同样适用）。

### 2.3 顺序

先做 2.1（与第 1 项的契约、Agent 渲染并行，文件互不相交），第 1 项面板规划完成后再做 2.2。最后合并页面：导入节点的「添加中转」打开快速流程，按可转换性显示两种模式（第 1.4 节「新建服务器方案、导入节点放在出口位置」保留为「在画布中编辑」的入口）。

## 3. 系统 Reality 预设

需求：在系统里预设一个或几个 Reality 参数，创建节点和创建中转时一键填入。Owner 于 2026-11-16 提出。

- 现状：节点编辑器只有写死在前端的 5 个「常用目标」（`serverSettingsModel.ts` 的 `REALITY_HANDSHAKE_PRESETS`），选中只填握手目标，SNI 要另点「从握手目标填入」；中转方案与快速流程的入口安全设置（`EntrySecurityEditor.vue`）没有预设，只从出口入站的 Reality 带入。
- **预设内容**：名称、握手目标 `host:port`、服务器名称（1–16 个 DNS 主机名，默认取握手目标主机）、可选的默认传输与 flow（TCP Vision／TCP／xhttp）。**不含密钥与 Short ID**：每个入站仍各自生成 X25519 密钥对与 Short ID，避免多台节点共用私钥。校验复用 `desiredstate` 的 Reality 规则（具体主机名，不接受 IP、通配符、带端口）。
- **存储**：`system_settings` 键 `reality_presets`（`{items:[{id,name,handshakeTarget,serverNames,transport,flow}],defaultId,revision,updatedAt,updatedBy}`），无迁移，最多 20 个；随整库快照备份与恢复。
- **接口**：`GET /api/v1/system/reality-presets`（Owner）；`PUT` 同路径（Owner＋CSRF，`expectedRevision`，未知字段拒绝，409 `settings_conflict`，内容未变不推进版本，记「修改 Reality 预设」）。
- **系统设置**：新增「Reality 预设」卡片，增删改、设一个默认；未设置任何预设时节点编辑器继续显示内置 5 个常用目标作为备选。
- **节点编辑器**：Reality 区块的「常用目标」改为「Reality 预设」下拉，选中一次填入握手目标与服务器名称（及预设里的传输／flow，仅在所选核心能力支持时）；新建 VLESS Reality 入站且有默认预设时自动带入，已有入站不自动改写。
- **中转方案与快速流程**：入口安全设置增加同一个预设下拉；选 Reality 时的默认值优先级为「绑定已有值 ＞ 默认预设 ＞ 出口入站的 Reality 参数」。后端合同不变（仍是 `realityTarget`／`realityServerName`），预设只在页面填值，不随绑定保存预设 ID。
- 不在本项：预设共享密钥对；按节点地域自动挑选握手目标；对握手目标做可达性探测（Agent 原生校验仍是最终门禁）。

第 3 项只涉及系统设置、节点编辑器与入口安全设置页面，与第 1、2 项文件基本不相交，可最先完成。

状态：已实现并审查。
