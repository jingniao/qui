总览 1.7.1 最小 7.994 秒、最大 23.458 秒。10:19 UTC 只读检查确认流量整理、访问记录清理和增量缩容均于 10:08:17 已完成；本轮接口测速始于 10:13:17，期间没有上述任务执行记录，不能把波动归因于正在清理数据库。

接口采样结束后，使用本版实际 Go 仓库代码、独立只读连接、面板账号执行固定窗口诊断：月汇总整秒 5.112 秒、带纳秒边界 6.020 秒（结果摘要相同）；今日统计 0.361 秒、节点日/月流量 5.408 秒、趋势 0.398 秒、最近访问 0.034 秒、最近阻断 0.013 秒。月汇总仍是已确认的大头；该诊断未覆盖真实 HTTP 中的鉴权、节点详情读取和请求之间的等待，不能把剩余差额都归到某一层。生产诊断开关未启用。

新版本第一轮菜单试测发现异步页面代码尚未加载时，脚本提前判定静默，出现没有请求的约 0.3 秒结果；该轮全部作废。正式复测增加目标 URL 和页面标题记录，确认路由落地后才判定加载结束。旧版基线未保存路由落地证明，逐页对比只作参考；接口与弹窗指标另行独立采样。

用户及总览的主要慢请求落在用户在线状态和节点数据读取路径；本地占用主写连接的回归测试证实，独立只读池可以避免这些显示接口排队等写连接。生产此前没有阶段计时，尚不能给出数据库排队占比。

新建节点使用轻量用户选择数据，并行加载相互独立的数据；节点列表合并批量状态请求，详情仅加载当前页签。新旧版本仍需在相同生产数据与浏览器上复测，不能用减少请求数估算提速倍数。

## v1.7.0 部署后发现的问题

用户摘要接口抽样约 0.38 秒、服务器选择接口约 1.01 秒；但总览接口明显回退，超过前端 15 秒超时后，“待处理问题”“节点流量”“近期阻断”和实时概况不显示，用户用量卡片仍有内容。生产浏览器已复现，未删除业务数据。

根因定位到新流量存储查询：对月内每条明细反复拼接时间字符串。同一只读快照中，原查询 11.101 秒、候选整秒索引查询 3.598 秒，12 条汇总结果摘要相同。候选 Go 实际查询以生产面板账号单独只读执行：月汇总 5.446 秒、今日 0.327 秒、小时趋势 0.338 秒。v1.7.1 只精确处理有纳秒的边界秒，不牺牲时间边界准确性。

服务器列表另有两个回退：后台期间停止刷新后，浏览器用旧心跳和新时钟判成全体离线；批量整机流量接口因显示仓库漏接时区读取函数返回 500。v1.7.1 分别增加“状态待更新”和后台代次隔离、补齐只读时区依赖，保留真实离线判定。两项针对性回归均观察到修复前失败、修复后通过。

## 环境变更与测量边界

生产已建立并验证加密一致文件快照，面板 v1.7.0 及迁移 0154 部署成功。按 Owner 要求启用 SQLite 增量自动缩容并完成一次 VACUUM，主库 711491584 → 513343488 字节；/tmp 在线从 482 MiB 扩到 1 GiB，保存持久挂载配置，未重启验证。详情见[发布说明](release-notes-1.7.0.md)。

阶段计时保持默认关闭，面板 YAML 摘要未变，无法把生产 HTTP 总耗时精确拆为连接等待与 SQL 耗时。最终对比包含代码更新、数据库整理和正常生产流量变化的共同影响。

测速期间另有并行管理操作：审计记录显示 `jingniao` 于 10:18:30 UTC 删除一条入站，触发自动 `relay cleanup` 修订 153 和 10:20:01 的 `post-deploy reconcile` 修订 154；德国节点当前修订因此从升级后的 146 变为 154，核心健康。10:23:06 取消待登记节点“1”，服务器记录从 13 变为 12。复测脚本仅浏览页签及打开/取消弹窗，没有发出这些删除或发布操作。最终详情覆盖当时实际存在的 12 台、72 个页签；已取消记录不再补建。并行操作进一步限制了性能前后对比的因果解释。

Agent 升级：德国、美国 CC、美国 shlii.io 成功到 1.7.0。日本 zouter、台湾 wap、新加坡 uzuma、洛杉矶 rn、香港阿里国际*2、香港 zouter、英国 eugamehost、shlii.io 美国 1元下载失败，旧版本在线、核心健康、修订不变，Owner 明确要求这八台暂时跳过。香港阿里云*1 原本离线，另有一条待登记记录，均未升级。

## 后台恢复、覆盖与遗留

- 隧道管理的“规则”子页另测一次：2.654 秒，最长请求为服务器列表 2.442 秒，接口均成功。
- 16 个主菜单各三轮、德国六个页签各三轮、当时全部 12 台服务器的 72 个页签、9 个系统设置页签、4 个用户详情及 10 次弹窗均已记录。列表到详情的概况首屏与独立统计加载分开解释，不能把缓存或在途请求复用算成 SQL 提速。
- 批量整机流量接口在实际服务器页面请求中均返回 200，原有 500 未复现。后台恢复回归已观察到代码修复前误判 offline、修复后 unknown，再由新响应恢复真实状态。
- 浏览器实际隐藏超过一分钟后，12 张卡片保持“状态待更新”，原来的离线告警没有被扩散成全体离线。工具未能把原标签页切回前台，已请求 Owner 手动切回；**真实恢复耗时和恢复后的状态仍待验收**，目前只证明后台阶段及代码回归通过。
- 用户门户真实会话、编辑后保存、删除、配置发布及新建备份不属于这轮只读页面复测，未运行；既有备份恢复能力由发布门禁覆盖。原生 arm64、服务器重启后的 /tmp 挂载、本轮代理客户端数据面抽样未运行。

仍需处理的优先项：总览拆开轻量内容与重流量统计，避免一个慢查询拖住所有卡片；月流量研究按小时预汇总并保留精确时间边界；服务器详情避免反复读取全部服务器月流量；代理节点页按实际配置变化更新入站状态，减少持续重复的昂贵请求。前述均是下一批建议，尚未实施；v1.7.2 是否发布部署已交由 Owner 决定，不能把现有 v1.7.1 授权顺延。
